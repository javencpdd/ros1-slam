# R670／批323：补上 make_plan 服务，路径可被标准接口消费

更新时间：2026-10-26

## 1. 为什么选这条

R669 已证「Gazebo + 仿真时钟 + 规划输出」，但裸 topic 的 `nav_msgs/Path` 在 move_base 下没有订阅者（文档核对已确认）。若不补标准接口，这条链只能自娱。故本片在节点上增加 `nav_msgs/GetPlan` 服务（默认 `/make_plan`），并验证成功与拒绝两条路。

## 2. 结果

| 项 | 读数 |
| --- | --- |
| 服务返回点数 | 18 |
| 与 topic 路径一致性 | 末点坐标相同 |
| 非法目标（图外 99,99,9） | 返回空路径，状态置 `E_PLAN_GOAL_INVALID`（goal 不在任何支撑面足迹内），不伪造路径 |
| 运行环境 | 同一台阶世界、gzserver、`use_sim_time`，network none |

证据：[sim_R670](sim_R670)（世界、场景、图、脚本、检查器、输出）。节点的 `pose_xyz` 只从消息取坐标，不用 0 冒充 z。

## 3. 边界与下一刀

- 服务形态是 `GetPlan`（move_base 的 `make_plan` 同名服务类型），**未在 move_base 进程内实测**；下一步才把它接进 move_base 的 `make_plan` 调用方做端到端，或改用 nav_core 插件。
- 场景仍是自建最小台阶世界；m1/stairs 正式场景与多场景矩阵仍待后续片。
- 未改旧判据、未 push。
