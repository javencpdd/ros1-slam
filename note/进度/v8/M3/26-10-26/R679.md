# R679／批329：move_base 进程内调用到本规划器（路径 18 点）

更新时间：2026-10-26

## 1. 读数

| 项 | 值 |
| --- | --- |
| master | 起得来（XMLRPC getPid 通过） |
| `/move_base/make_plan` | 服务在位 |
| 返回路径 | **18 个 pose**（响应里 19 个 seq 字段＝1 header + 18 poses） |
| 配置 | `base_global_planner: v8_support_global_planner/SupportGlobalPlanner` |
| 调用链 | move_base → 插件 makePlan → `/make_plan` 服务 → v8 规划器 |

即：move_base **进程内**确实调用到了本规划器，且拿到非空路径，不是空成功。

## 2. 这一刀连踩四个环境坑（都属测试脚本，不是插件）

1. `roscore` 报「无法联系自己」——容器 `--network none` 下主机名不可解析，缺 `ROS_IP=127.0.0.1`；
2. 规划节点起来就退——测试脚本没设 `keep_alive_s`，默认 10 s 已过；
3. 插件报 `service /make_plan not available`——`/work/map.json` 没挂进容器，节点读图失败直接崩；
4. 镜像名笔误（`ros1-slam/noetic-sim`）导致一次空跑。

## 3. 边界

- 本片只证「进程内调用 + 非空路径」；未测图外目标的拒绝分支在 move_base 侧的表现（插件代码里空路径即返回 false，逻辑已写死，但未取读数）。
- 局部规划器用的是默认 `TrajectoryPlannerROS`（仅初始化告警），未做执行闭环；执行链属 #136。
- 未改第三方、未动主镜像、未 push。
