# R694／批344：URDF 里 kinematic 确实存在，但怀疑 URDF→SDF 转换丢了插件参数

更新时间：2026-10-26

## 1. 已验证

xacro 展开后的 URDF 第 158 行原本是 `<driveMode>dynamic</driveMode>`，执行
`sed -i "s|<driveMode>dynamic</driveMode>|<driveMode>kinematic</driveMode>|"` 后，同位置变为
`<driveMode>kinematic</driveMode>`（逐行打印确认）。所以 R693 的替换**是生效的**，不是 sed 没命中。

## 2. 但仍无位移，且与 dynamic 完全相同（x=1.29, z=0.11）

插件里确实有 kinematic 分支：

```
if (drive_mode_ == "kinematic") { ... SetWorldPose(np, true); }
else { SetLinearVel/SetAngularVel ... }
```

按这段代码，kinematic 会把位姿直接推出去，不受台阶碰撞限制，结果必然与 dynamic 不同。既然读数一模一样，最可能的解释是：**插件根本没读到 `kinematic`，`drive_mode_` 落回缺省 `dynamic`**。

而 `spawn_model -urdf` 会做 URDF→SDF 转换，非标准的 `<driveMode>` 子元素有被丢弃的风险——这与「两种模式读数完全一致」吻合。

## 3. 下一刀（一步可判）

```
gz sdf -p /tmp/robot.urdf | grep -A3 driveMode
```

若 SDF 里没有 `<driveMode>`，即证实转换丢弃，则改法为：直接把插件块写进 SDF world（或 `-sdf` 直接 spawn），绕开 URDF 转换。
