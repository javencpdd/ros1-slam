# R701／批351：官方仓库实查——步态件是 MuJoCo/PyBullet，不是 Gazebo/ROS1

更新时间：2026-10-26

## 1. 实查方式与结果

GitHub API 读取 `DeepRoboticsLab` 组织 28 个公开仓库（raw.githubusercontent 被重置，改走 API）。相关件：

| 仓库 | 许可 | 内容 |
| --- | --- | --- |
| Lite3_rl_deploy | BSD-3 | `policy/`、`state_machine/`、`Lite3_description/`、`interface/robot/simulation` |
| deep_robotics_model | BSD-3 | 官方 URDF |
| deep-robotics-simulation | BSD-3 | `worlds/`、`simulator.py` |
| Lite3_ROS | MIT | 官方 ROS 接口 |
| Lite3_Navigation / Lite3_SLAM | **未标许可** | 不引入 |

**后端确认**（README_EN 原文）：Sim-to-Sim 用 **PyBullet 或 MuJoCo**：
`python pybullet_simulation.py` / `python mujoco_simulation.py`，再跑 `./rl_deploy`；依赖 `pybullet / mujoco / numpy<2 / python3.10`，构建 `-DBUILD_PLATFORM=x86 -DBUILD_SIM=ON`。**没有 ROS、没有 Gazebo 节点**。

## 2. 对两条阻塞的影响

- **#144 跨层载体**：拿到了「有策略的四足」，但它是**独立仿真器**里的；不能直接插进我们的 ROS1/Gazebo 运行面。
- **#139 高程源**：28 个仓库里仍无 elevation/height-map 包；自建观测链仍是唯一路。

## 4. 取件通道实测（同批补记）

- `git clone https://github.com/...` → **TLS 被重置**（gnutls handshake 失败）；
- `raw.githubusercontent.com` → 同样被重置；
- `api.github.com` → **可用**（仓库列表、contents 读取均成功）；`support.deeprobotics.cn` 返回 200。
- 结论：走 **GitHub API**（`git/trees?recursive=1` 取树 + `contents`/`blobs` 取文件）可行；tarball 直连 `codeload` 未测。第三方子模块（`third_party/`）可能同样需按 API 逐个取。
