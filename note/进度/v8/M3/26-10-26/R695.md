# R695／批345：两种方式注入 kinematic 后读数仍为 1.29 m（跨层结论不变）

更新时间：2026-10-26

## 1. 已证实与已否证

| 步骤 | 结果 |
| --- | --- |
| URDF 内替换 `driveMode` | 生效（第 158 行确为 kinematic） |
| `gz sdf -p` 后的 SDF | **`driveMode` 计数 = 0** → URDF→SDF 转换确实丢弃该插件参数 |
| 改写 SDF：按 `</plugin>` 首次出现注入 | INJECT = 1，但可能注入了别的插件块 |
| 改写 SDF：正则定位 `lite3_planar_drive` 插件块后注入 | INJECT = True（3 个插件） |
| 两种注入后实测 | 均为 `x=1.29, z=0.11`，与 dynamic **完全相同** |

## 2. 结论（可下的与不可下的）

- 可下：**平面差速载体（不论哪种驱动模式注入方式）在本三级楼梯场景里都没有越过 0.18 m 台阶**；跨层执行不能靠当前载体完成，需三维载体（V8-X1）。
- 不可下：不能断言「kinematic 分支无效」——三次读数完全相同（1.29），更像是**参数仍未真正进入插件**（例如插件读的是另一层级/另一份模型实例），需要插件侧打日志读出 `drive_mode_` 才能定论。

## 3. 为什么停在这一步

继续盲试注入位置属于重复劳动；下一步需要的是插件侧可观测性（打印 `drive_mode_` 与来源 SDF 路径），或改用原生 SDF world 直接写死插件参数。这两条都超出「判据链验证」范围，归到载体适配（V8-X1/V8-11）更合适。
