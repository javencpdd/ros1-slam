# R706／批355：模型是 motor（力矩）执行器；爆炸与垃圾值同源——观测里本身有坏值

更新时间：2026-10-27

## 1. 两个确定事实

1. `Lite3.xml` 用 `<motor/>`（力矩执行器），16 项 `class="motor"`；`mujoco_simulation.py` 侧按
   `tau = kp*(pos_cmd−q) + kd*(vel_cmd−qd) + tau_ff` 计算后写回——**我的 `qfrc_applied= kp*(target−q) − kd*qd` 语义上等价**，不是「用错了执行器类型」。
2. 官方 C++ 链路里 `Joint Cmd Target Pos` 也出现 **1e17~1e18**，说明**策略在两条链路上都输出坏值**，问题不在我的写回方式，而在**输入观测**。

## 2. 由此收敛的判断

- 观测里存在非有限/极端值（最可能是初始状态与策略训练分布差异过大，或仿真送给策略的关节/姿态字段与 runner 期望不一致）。
- 具体线索：仿真初始关节位 `URDF_INIT = [0, −1.35453, 2.54948]×4`，而策略默认位是 `[0, −0.65, 1.3]×4`；观测里减的是后者，第一帧就会出现约 `[0, −0.70, 1.25]×4` 的大偏差——虽不必然是 NaN，但加上速度/姿态项足以让策略发出极端动作。

## 3. 下一步（可执行）

1. 在 Python 环里**先打印第一帧 45 维 obs**，确认是否有 nan/inf、量级是否合理（这是当前最该做的一步）；
2. 若数值合理但动作仍极端：把仿真初始位改成策略默认位（或在策略侧先把机械狗"站"到默认位再接管）；
3. 若 obs 含 nan：查四元数→旋转矩阵、`qvel[3:6]` 的坐标约定；
4. 通过后再谈基座是否上 0.36 m 平台。
