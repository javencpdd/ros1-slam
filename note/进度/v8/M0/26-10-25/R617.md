- 现有镜像内 CMakeCache 与 devel/setup.bash 均可读，已存哈希及选定 CMake 字段；这直接否定以宿主 ws/build、ws/devel 不存在推断没有构建资产的说法。镜像 build/devel 的存在仍不证明当前源码已编过。
- Compose 将源码绑定到宿主，把 build/devel 挂到 docker_ros1_ws_build、docker_ros1_ws_devel 命名卷；实际 inspect 也印证这两处。卷内内容本次未取，不能用镜像内产物替代命名卷读数，也不能假定卷随源码自动更新。
- 镜像 runtime 中没有 /usr/local/bin/catkin_build.sh；该脚本只在 builder 阶段复制，runtime 仅复制工作区。这不是新增缺包；当前容器内重编入口应核实 docker 绑定目录里的脚本。
- JSON 内 source.head 与三棵树 hash 只锚定本次宿主检出的源码；没有镜像构建时的源码 commit 证明，不把这两层强行绑定。上游 commit/tag 仍须逐后端补来源。
