# R759／批408：另三个 pending 键补 scope/evidence 与正值守卫（R751 P3-1）

更新时间：2026-10-27

## 1. 改动

R751 复核指出：`budgets.stop_time_s`、`budgets.stop_distance_m`、`tolerances.max_localization_error_m` 与旧 success_rate 同族 fail-open——只填裸数字就能离开 pending。本批在 `_pending_report` 加通用守卫：

- 三键只要出现 `value`，必须为正数（`_is_number` 且 >0）；负值/0/NaN/Inf → 记 `.value` pending；
- 同时必须有非空字符串 `scope` 与 `evidence`，缺任一项 → 记键本身 pending；
- 未填值的键仍由原 `PENDING_REQUIRED` 记 pending（行为不变）。

测试 52→**56**：stop_time 裸值仍 pending、stop_time 带 scope/evidence 只剩其余 3 项、max_localization 裸值仍 pending、stop_distance 负值被拒。

## 2. 边界

- 三键的 scope token 尚未由判据面定义，本批只要求“非空字符串”，不写死具体 token；真正冻结时仍须按带域协议把精确 scope/sample_n 加入 `SCOPED_REQUIRED`（R742/R748 的精神）。
- 本批未改 FROZEN、未改 digest；`pending=4`、`48→56` 项测试全绿、`freeze_allowed=false`。
- P8：仍属“判据生效的前提”，沿用 05 F 段 R752 条的不触发判定与笔权声明。
