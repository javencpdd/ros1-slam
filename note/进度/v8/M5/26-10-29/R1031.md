# R1031 · 地图包可迁移：状态＋地图＋哈希清单，导入重封

- 时间：2026-10-31 21:25—21:40 CST（qoder）；性质＝MapDelta 跨机持久化
- 依据：README「开发中」仍列「MapDelta 多 map_id/跨机持久化」；状态快照
  本身是 JSON，但缺一个带完整性清单、可整包搬迁并重定位 data_uri 的载体。

## 一、实现

- `map_bundle.py`：
  - `export_bundle`：把 state 目录快照与引用地图文件复制进 bundle，写
    `bundle.json`（schema、各 map 的 map_id/version/digest、逐文件 sha256/字节数）。
  - `verify_bundle`：拒绝缺清单/schema 不符/绝对路径或 `..` 穿越/哈希不符。
  - `import_bundle`：验哈希后用 `MapService.load` 复核每份快照；将指向旧地图
    根的绝对 `data_uri` 重写到新目录，并同步重算内容摘要、history 末项与
    `source.sha256`，使服务自校验仍成立。
  - CLI `export/import`，失败 rc=5 带理由码。

## 二、读数

- `test_map_bundle` **4/4**：导出/搬迁导入（含 data_uri 重写）、篡改文件
  `E_BUNDLE_HASH`、路径穿越 `E_BUNDLE_PATH`、缺清单 `E_BUNDLE_MANIFEST`、
  CLI rc 0/5。
- 真实 ROS 冒烟（`multi_map_node`）：A 目录 map_a v2→**v3** 后导出 bundle
  （2 state + 2 maps）；导入新根并重启，恢复 map_a **v3**、map_b **v2**、
  mezz **z=0.8**，query v3；停止退净。
- V8 全树 **66 套件 0 失败**（新增 `test_map_bundle`）。

## 三、边界

- `data_uri` 是内容摘要的一部分；搬迁重写后必须重算摘要并重封，否则
  `MapService.load` 会拒。本批按「重定位即重封」处理，未改变冻结的摘要算法。
- 只迁移 state 与显式给出的地图文件；未打包轨迹/日志/其他外部资产。
- 跨机仅以本地目录搬迁验证，未做真实双机传输与权限差异；A1—A7 仍
  `NOT_VALIDATED`。
