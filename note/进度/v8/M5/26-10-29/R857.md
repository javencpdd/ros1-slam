## 为什么起点不能靠 RViz 的 2D Pose Estimate

本栈的 `map→odom` 是恒等静态桥（真值），`lite3_planar_drive` 的 odom 取 `WorldPose()` 闭环；
`/initialpose` 没有消费者，不会移动机器人。所以起点必须改 Gazebo 模型位姿；
改完 odom 随即跟随，模型位姿就是 map 系起点。

## 读数（headless m1，无 move_base）

| 步骤 | 模型位姿（world） | `/sim/odom_gt` |
|---|---|---|
| spawn 后 status | x 0.0 / y 0.0 / z 0.15 / yaw 0° | x 0.0 / y 0.0 / yaw 0° |
| `--start 2.0 -1.0 --yaw 30 --settle 1` | x 2.0 / y -1.0 / z 0.11 / yaw 30° | x 2.0 / y -1.0 / yaw 30° |
| 设置后 status | x 2.0 / y -1.0 / z 0.11 / yaw 30° | 同上 |
| `--goal 3.0 0.5 --yaw 45` | `/move_base_simple/goal`：frame=map、x=3.0、y=0.5、四元数 z=0.382683 / w=0.923880；`subscribers_seen=1` | — |

- 起点设置后 1 s 落稳，z 由 0.15 落到 0.11（模型自重落稳，符合既有复位口径）。
- 目标消息由 `rostopic echo -n1` 收到；本批未起 `move_base`，因此**不声称已行驶到点**。

## 用法

```bash
python3 ws/src/95_simulation/lite3_gazebo_sim/scripts/sim_pose.py --start 2.0 -1.0 --yaw 30
python3 ws/src/95_simulation/lite3_gazebo_sim/scripts/sim_pose.py --goal 3.0 0.5 --yaw 45
python3 ws/src/95_simulation/lite3_gazebo_sim/scripts/sim_pose.py --status
```

- 终点也可直接用 RViz 的 **2D Nav Goal**（同样发 `/move_base_simple/goal`），前提是 `flat2d_stack` 的 `move_base` 在跑。
- `--start` 会尽力取消 `move_base` 当前目标（`/move_base/cancel`），避免落到新起点后继续追旧目标。
- 只动仿真模型与目标消息，不直写底盘 `cmd_vel`；odom 话题默认 `/sim/odom_gt`，可用 `--odom-topic` 覆盖。

## 边界

- 无真机；本批未起 `move_base`，不声称导航闭环或到点精度。
- 目标点须落在已加载地图的自由区内（本批未验越界/不可达分支，交 `move_base` 自身拒绝）。
- `sim_pose.py` 只覆盖 m1 的 `lite3_planar` 模型名，其他载体需 `--model`。
