## 一、现场与根因

按 `a6_ndt_recovery_live_smoke.py --move 0.3,0` 跑局部劫持时，首次在启动门控处失败：

- A6 侧：`phase=TRACKING`、`lease=1`、`allowed=true`；
- gate 侧：`last_lease=0`、`active_lease=null`，命令行已收到 1019 条但门控始终不拿到 lease；
- 冒烟在 `timeout waiting for gate lease 1` 退出，未写 result JSON。

根因：`a6_recovery_node` 的 `/lease` 只在 lease 变化时发布一次，且未 latch；
gate 进程晚于 A6 激活订阅，就永久错过 lease 1。同一未加 latch 的脚本 09:25 重跑
通过，说明是启动时序竞态，不是每次必现。

## 二、修复

`a6_recovery_node.py`：

```python
lease_pub = rospy.Publisher(prefix + '/lease', UInt64, queue_size=20, latch=True)
```

晚订阅的 gate 会立即收到当前 lease；后续 lease 变化仍按原逻辑增量发布。

## 四、边界

- 劫持量 **0.3 m**，落在 NDT 有界搜索半径 0.4 m 内；不是任意位置 kidnapping，
  也不是全图重定位；
- 候选种子仍停在 prior（距真值 0.242—0.250 m），终态精度来自恢复点云后 NDT
  跟踪收敛；因此本轮只支持“短时局部失锁＋跟踪回正”，不支持“候选本身找到新位姿”；
- **0.6 m 探针（超出搜索半径）暴露系统级 fail-open**：候选与终态分别偏
  **0.5421 / 0.5225 m**，但 A6 仍 `TRACKING`、`allowed=true`，gate 报 `HEALTHY`、
  lease 2；只有冒烟器的后验真值门把它判成 `ok=false`。该缺口未修，见第六节；
- 每种条件单次运行；无四足、无真机；A6 仍 **PARTIAL**，不改变 formal 或 A1—A7 矩阵；
- 首次失败跑未落 JSON，现场摘录见 `unlatched_failure.txt`，不补造数据。

## 六、0.6 m 边界：搜索半径外 fail-open

同一链路把 `--move` 改为 `0.6,0`（超出 `_relocalize_radius_m=0.4`）：

| 项 | 读数 |
|---|---|
| 真值 / NDT 终态 | `2.1,0` / `1.578,-0.024` |
| 终态 XY 误差 | **0.522521 m** |
| 候选种子误差 | **0.542063 m**（仍为 prior） |
| A6 状态 | `TRACKING`、`allowed=true`、lease 2 |
| gate 状态 | `HEALTHY`、`last_lease=2` |
| 空扫描负控 | `FAILED`、lease 2→2、无新 reset、gate `[0,0]` |
| 冒烟判定 | **ok=false**（只因后验真值门；系统本身未 fail-closed） |

结论：有界搜索半径外的位移不能被 NDT 的局部候选识别，场景歧义又让旧位姿通过
score 门，导致 A6/gate 误恢复。负控仍成立（无观测时 FAILED），但“有观测但错位”
这一支是 open。修法需要独立运动先验或恢复后一致性检查，属新的安全决策，不在本批
自行改判据；A6 不得据此升格。

另起句（R1115）：0.6 m 的 fail-open 已在**带 BBS 绝对源共识门**的活体链上闭合
（BBS 共识与 NDT 候选差 >0.5 m 时 A6 FAILED、lease 保持 1）；NDT-only 链仍保持
本节边界，不回改本节原文。
