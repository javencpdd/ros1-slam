## 结论

1. **Foxglove 可以发终点**：Publish 面板 `geometry_msgs/PoseStamped` → `/move_base_simple/goal`（`docker/foxglove/README.md` §3.4 在册）。本镜像有 `rosbridge_server`（`/opt/ros/noetic/share/rosbridge_server`），无 `foxglove_bridge`（后者是 ROS2）。
2. **Foxglove 不能直接设起点**：修模型位姿要调 `/gazebo/set_model_state`，Foxglove 没有通用服务面板。新增 `sim_pose_bridge.py` 后，Publish 面板发 `PoseStamped` 到 `/sim/set_start`（或 `PoseWithCovarianceStamped` 到 `/initialpose`）即可；状态回 `/sim/set_start/status`。
3. **3D 场景可以热插拔模型，但不能热换世界文件**：`sim_scene.py` 用 `/gazebo/spawn_sdf_model`＋`/gazebo/delete_model` 在运行中的 m1 世界里换场景模型，不重启 gzserver；**静态地图不随场景更新**，正式导航判据必须重启对应世界。

## 读数（headless m1，无 move_base）

| 动作 | 结果 |
|---|---|
| `sim_scene --list` | 9 个场景：blank／ramp_envelope／sidewall_envelope／stairs_blocked_mid／stairs_easy／stairs_mid／stairs_steep／wall_h045／wall_h080 |
| `--scene stairs_easy` | spawn 成功；世界模型含 `stairs_easy`，机器人/地面不动 |
| `--scene wall_h045` | 先删 `stairs_easy`（DeleteModel success），再 spawn `wall_h045`；世界只剩 wall |
| `--clear` | 删 `wall_h045`；世界回到 ground/perimeter/obs×6/lite3_planar |
| `/sim/set_start` (2.0, −1.0, 30°) | 模型与 `/sim/odom_gt` 均为 x2.0 / y−1.0 / yaw30° / z0.11 |
| `/initialpose` (0, 0, 0°) | 模型与 odom 均为 x0 / y0 / yaw0° / z0.11 |

## 用法

```bash
# 场景热插拔
python3 ws/src/95_simulation/lite3_gazebo_sim/scripts/sim_scene.py --list
python3 ws/src/95_simulation/lite3_gazebo_sim/scripts/sim_scene.py --scene stairs_easy
python3 ws/src/95_simulation/lite3_gazebo_sim/scripts/sim_scene.py --clear

# Foxglove 起点：先起桥，再在 Publish 面板发 PoseStamped 到 /sim/set_start
python3 ws/src/95_simulation/lite3_gazebo_sim/scripts/sim_pose_bridge.py
```

Foxglove 侧：连接 `Rosbridge (ROS 1)` → `ws://<主机>:9090`；Publish 面板
`geometry_msgs/PoseStamped` → `/move_base_simple/goal`（终点）或 `/sim/set_start`（起点）。

## 边界

- 本批未起 `move_base`：只验位姿与消息，不声称行驶到点或导航闭环。
- 场景热插拔只适合感知/可视化/临时障碍实验；静态地图与代价图不随动，**正式导航批必须重启对应世界**（`roslaunch lite3_gazebo_sim stairstudy.launch world_file:=...`）。
- 起点桥只接受 frame 为空／`map`／`odom`；其他坐标系拒绝并回状态，不做猜测换算。
- 无真机；不改第三方、不改冻结门值。
