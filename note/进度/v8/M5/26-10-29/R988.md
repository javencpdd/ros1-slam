# R988 · 边界桥 500 Hz：遥测发布移出命令环，实测 485.8 Hz

- 时间：2026-10-31 04:46—04:49 CST（qoder）；性质＝真实 ROS/Gazebo 运动学端点的速率标定
- 依据：R984 主链 200 Hz 请求只记了功能读数，没有单独测 achieved rate；本批补 200/500 Hz。

## 一、根因与修复

- `ros_bridge` 原来在命令 tick 循环中串行 `receiver.poll()` + 50 Hz 遥测的 3 个 ROS 发布；
  实测 200/500 Hz 请求都只到 **约 60 Hz**（遥测发布占满单环）。
- 修复：把遥测接收/3 个发布移到独立线程（只更新 `NodeCore` 与 ROS 话题），命令环只做
  `tick → 33 B UDP send → 2 Hz status`；`boundary_chain_runtime` 增加 `--rate-hz`，运行前
  写 materialized graph，并用命令窗口首末 `frames_sent` 计算 achieved rate。
- 既有 `twist_stamped` 默认与 S2 回环语义不变；本批仍只动 ROS 桥入口，不改协议/帧。

  final_position 一致（1.3358/1.3032 m 量级）。
- 测试：`boundary` 14/14；V8 全树 **59 套件 0 失败**。

## 三、边界（如实）

- S3 端点是 `SetModelState` **运动学载体**，不证明接触动力学、步态或真机；命令上限/安全包络
  仍由 `CommandBridge` 限幅。
- 500 Hz 是本机 6 s 窗口的 achieved 读数，未做长时（分钟级）满速、CPU 抢占、丢包注入、
  多实例/QNX 或真机 S5；S5 仍 L2。
- R984 的 200 Hz 功能冒烟读数仍有效，但其“请求 200 Hz”不代表当时 achieved；后续引用速率
  以本批 `achieved_hz` 为准。
