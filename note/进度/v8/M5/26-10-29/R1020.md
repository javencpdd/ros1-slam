# R1020 · 命令链安全 hold 门：mux 保持零速下换命令源

- 时间：2026-10-31 16:40—18:16 CST（qoder）；性质＝命令链热替换的安全交接件
- 依据：命令链不能像只读 provider 那样重叠；换源期间必须由 mux hold 保持零速。

## 一、实现

- `hotswap.apply_instance` 新增 `pre_stop`/`post_start` 回调：调用方可在停旧前
  置 hold、在换新成功后释放 hold；核心仍不 import ROS。
- `command_hold_smoke.py`：真实 `60_safety.launch` mux，旧 `rostopic pub` 源
  0.4 m/s → hold=true → 停旧/起新 → hold=false → 新源 0.3 m/s。
- 单测覆盖回调顺序（pre → 停止/启动 → post）。

## 二、读数

- mux 初始 0；旧源 **0.4**；hold 后旧源仍发时 **0**；停旧、新源起后仍 **0**；
  释放 hold 后 **0.3**；停止退净；ok=true。
- hotswap **12/12**；V8 全树 **64 套件 0 失败**。

## 三、边界

- 这是**安全交接**：换源窗口机器人保持零速，不是零中断/连续运动。
- 只验证 mux hold 行为与回调顺序；未在真实 2D 导航栈上做 planner 实例替换，
  未接 localization/TF 所有权。
- 不新增判据；A1—A7 仍 `NOT_VALIDATED`；命令/定位链零中断仍未做。
