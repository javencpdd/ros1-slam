## 一、链路

`/rslidar_points` → 可暂停中继 `/a6_ndt/cloud` → NDT 监控器
（`~odom`/`~healthy`/`~score`/`~relocalized`，`output_role=monitor`）
→ `ndt_recovery_bridge` 把 `relocalized=true` 时的接受位姿/score 转成 A6 candidate JSON
→ `a6_recovery_node`（`~relocalize` 为 `std_srvs/Trigger`，仅在有 lease 且确实请求后收候选）
→ backend 消息 → 本批 smoke 以 NDT 原生 `~initialpose` 施加候选 → NDT 重新接受观测
→ 新 lease → `localization_state` 租约门放行 `cmd_vel`。

本批新增/收紧的接口：

1. NDT `~relocalize`：以最后接受位姿为中心，在
   `radius .5 / xy step .2 / yaw span 10° / yaw step 5°` 内做**有界完整网格**；
   预算 `.8→8 s` 内跑完才允许验收，预算耗尽即失败；`relocalize_score_max` 可独立于
   跟踪 `score_max`；结果按到中心的位移（加小权重 yaw）取**最近可接受假设**，
   并受 `relocalize_max_displacement_m` 与 yaw 界约束。搜索位姿直接发布为观测，
   不再用局部跟踪器二次精修；失败后 `accept_align_=false`，不残留旧 guess。
2. NDT `~initialpose`：外部候选只作局部跟踪种子，本身不算健康观测；
   必须等下一帧配准被接受。
3. A6 启动引导：`seen_observation=false` 或 `last_lease=0` 时，即使收到
   latched `healthy=false` 也不调用 relocalize；候选必须满足
   `phase=RELOCALIZING && requested && last_lease>0`。这修掉了
   「初始 lease 1 与候选 lease 1 撞号、RECOVERING 卡死」和启动误恢复。
4. `localization_state` 增加 `--lease-topic`/`--candidate-topic`/`--output-topic`/
   `--status-topic`，可与 A6 的 JSON candidate 同命名空间共存。

## 二、读数

### 运动旁证（不作认证）

同一脚本 `--move 0.3,0` 的一次运行：候选仍停在 prior
（候选误差 **.247788 m**），施加 `~initialpose` 后 NDT 跟踪收敛到
`(1.8496, −.0097)`，最终 XY **.050512 m**；另一次同配置复跑在初始 gate
超时，未复现。故本批只认证**静态短时失锁**；运动中的候选选择与
NDT 连续跟踪均不认证。早期调试另观察到 0.3 m 传送后 NDT 连续跟踪漂到
`.95 m`（与 R902—R905 的走廊退化一致），这是 NDT 仍为 monitor-only 的实证边界。

## 三、边界

- 平面 Gazebo kinematic 机器人；无四足接触、无物理制动、无真机。
- NDT 仍 **monitor-only**，不是连续导航后端；`/cmd_vel` 放行只说明租约门在
  NDT 观测流上的行为，不是 NDT 定位精度验收。
- 只覆盖**短时失锁、先验附近**的重定位；不做 kidnapped/长时失联全图搜索；
  全图 `global_search` 仍是原有无界路径，未在本批验收。
- 不改 A1—A7；A6 仍 **PARTIAL**；#151 formal 两键仍 pending。
