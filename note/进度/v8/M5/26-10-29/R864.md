## 一、故障与根因

`ros1-slam-sim-viz` 先前为 `Exited (127)`，`docker inspect` 报：

```
error mounting "/run/user/1000/gdm/Xauthority" to rootfs at "/tmp/.Xauthority":
not a directory: ... Check if the specified host path exists and is the expected type
```

根因：compose 的 `ros-volumes` 锚点把 `${X_AUTH_FILE:-/run/user/1000/gdm/Xauthority}` 挂到
`/tmp/.Xauthority`；该源路径只在图形会话建立后才存在，容器创建时缺失，Docker 造出目录后
挂到文件挂载点失败。容器进程未启动，故 127。

处置（工作树中已有、本批验证并收录）：移除 cookie 挂载；容器内进程以 uid 0 连宿主 X，
认证改由宿主机一次性放行 `xhost +si:localuser:root`（可用 `xhost -si:localuser:root` 撤销）。
headless 的 `sim` 域未改。

## 三、脚本语义

```bash
scripts/ops/sim_viz.sh doctor          # 只读：X、xhost、GPU、镜像、容器、GL
scripts/ops/sim_viz.sh start [world]   # xhost 放行 → compose up sim-viz → gzserver + gzclient
scripts/ops/sim_viz.sh status          # 容器/进程/窗口
scripts/ops/sim_viz.sh stop            # 按 PID 停 gzclient/gzserver → compose stop → 撤销 xhost
```

- 停止用 `pgrep -x` + `kill PID`，不用 `pkill -f`。
- `world` 支持仓库内宿主路径或容器内 `/opt/ros1-slam/...` 路径。
- 认证放行只在 `start` 加、`stop` 撤。

## 四、边界

- 本批只证明「宿主侧能看到 Gazebo 画面」，不改 `sim` 服务的 headless 口径，也不替代
  `m2_smoke.sh` 等门禁判据。
- 本次起的是 **sim-viz 容器内的独立 gzserver**（`127.0.0.1:11345`），没有起 ROS master；
  要接仿真栈（`sim` profile）与 RViz，需按 `docker/sim.sh` 起 master 后在同一网络域观测。
- `xhost +si:localuser:root` 是放宽本机 X 访问的临时动作，`stop` 会撤销；不写入持久配置。
- 第三方模型/世界文件未改。
