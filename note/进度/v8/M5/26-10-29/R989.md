# R989 · MapStore 多 map_id：目录内按图快照与显式加载

- 时间：2026-10-31 04:54—04:55 CST（qoder）；性质＝纯 Python 代码/测试切片
- 依据：R983 只支持单 map_id 的 `MapService.save/load`；本批补多图共存的存储层。

## 一、实现

- 新增 `MapStore(root)`：
  - `path_for(map_id)`：map_id 作为文件名键，仅允许 `[A-Za-z0-9_.-]`，拒绝 `/`、`..`
    路径穿越（`E_MAPSERVICE_MAP_ID`）；
  - `save(service)`：复用 `MapService.save` 的临时文件+fsync+原子替换；
  - `load(map_id)` / `ids()` / `load_all()`：显式枚举目录内 `*.json` 并逐个 `MapService.load`；
    任一文件损坏/异 map_id 使 `load_all` fail-closed（`E_MAPSERVICE_SNAPSHOT`）。
- 不同 map_id 的版本、history、applied_deltas 各自独立；目录是存储面，不是新的地图合并策略。

## 二、读数

- 两个 map_id（`svc_map`、`other_map`）各自 publish→update 到 version 2，保存为
  `svc_map.json` / `other_map.json`；`ids=['other_map','svc_map']`，新 `MapStore` `load_all`
  两件均恢复 v2 与各自 digest（`29c89f9c…` / `be0136dd…`）。
- map_id `../escape` 的路径请求被 `E_MAPSERVICE_MAP_ID` 拒绝；目录内写入坏 JSON 后
  `load_all` 抛 `E_MAPSERVICE_SNAPSHOT`，不静默跳过。
- 测试：`map_service` **11/11**；V8 全树 **59 套件 0 失败**。
  同时修了 `test_process_runner` 中 pidfile 已建但内容为空的读取竞态（仅测试件）。

## 三、边界（如实）

- 本批只做**本地目录**的多 map_id 快照/加载；跨机复制、并发写者、目录级原子事务、
  版本历史压缩未实现。
- ROS provider（`delta_map_node`）仍只持一个 map_id；多图路由/选择器未接入。
- 不改 map/delta 契约、合并语义或判据；A1—A7 仍 `NOT_VALIDATED`。
