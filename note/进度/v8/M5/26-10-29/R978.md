# R978 · 实例配置文件与 2D/3D 运行前预检

- 时间：2026-10-31 02:25—02:39 CST（qoder）；性质＝框架预检增强，不启动真实算法
- 依据：graph 只能选组件，不能给实例指定配置文件；预检只查端口/类型，不查 2D/3D 混配。

## 一、改动

1. graph 实例新增 `config: path`（相对 graph 文件或绝对路径）。启动前用同一 YAML loader 解析：
   缺失文件、语法错误、重复键、顶层非映射全部拒绝；配置 sha256 进入 assembly digest 与 plan。
2. `config` 取代该实例 manifest 的 `launch.param_files`；graph `params` 在其后覆盖。
   `include` 组件不接受实例 `config`（`E_CFG_CONFIG_KIND`），用 args/params。
3. 预检新增两条跨组件规则：
   - `nav_msgs/Path` 边两端组件 `dimensions` 必须一致（`E_GRAPH_DIMENSION`），
     2D 全局接 3D 局部会被启动前拒绝；
   - 组件自身 `dimensions` 必须与 `occupancy_grid/v1`、`support_map/v1|v2` 输入输出一致
     （`E_GRAPH_MAP_DIMENSION`），防止 2D 算法接 3D 地图。
4. selector 用同一 `graph.check`，页面现在把 local2d→local3d 显示为
   `E_GRAPH_DIMENSION`（global.path 2→3）。

## 三、边界

- 只做**语法/结构/摘要/维度/地图 schema**预检；manifest 的 `param_schema` 尚未做字段级校验。
- 真实算法（DWA/TEB/Navfn/GlobalPlanner/hdl/faster_lio）仍未 v2 化；本批只提供
  “指定配置文件并在启动前拒绝坏配置/错配”的框架能力。
- 维度规则当前只对 `nav_msgs/Path` 边生效；其他消息类型的维度语义需逐个定义。
- 未接真实 roslaunch/rosrun；热替换仍只停止后换组合；A1—A7 不变。
