# R1117 · 3D 交互 RViz 空白根因：补 world→map 静态 TF

- 时间：2026-11-02 13:05—13:22 CST（qoder）；性质＝交互入口显示缺陷修复
- 代码：`94e59972`（app_runner 在 `--rviz` 时补发单位 `world→map`）
- 证据：`evidence/R1117/`（TF、markers Hz、点击前后 status、路径、载体、JSON、日志、命令、测试、code_ref、hashes）
- 容器：ros1-slam-sim-viz

## 一、现象与根因

3D 交互入口启动后 RViz 全空。现场检查：

- `/v8/3d/viz/markers` 正常发布，约 **50 Hz**，`frame_id=map`；
- `/tf` 中**没有 `map` 帧**，`tf_echo map base_link` 报 `"map" does not exist`；
- `nav3d.rviz` 的 Fixed Frame 是 `map`，Grid/SupportMap/GlobalPath 都挂在该帧下。

3D graph 只发 Marker/Topic，不发布 TF 边；Marker 的 `frame_id` 只是字符串，不会自动建帧。
于是 RViz 解析不到 Fixed Frame，所有显示项静默为空。R1116 的“点已选中、路径已生成”
（命令行读数）成立，但**人看 RViz 时是空白**，两者并不矛盾。

## 二、修复

`framework/app_runner.py` 在 `--rviz` 时于 RViz 之前启动：

```
rosrun tf2_ros static_transform_publisher 0 0 0 0 0 0 world map
```

- 单位变换，仅用于显示帧可解析；不改 graph 输出、不写定位/建图真值；
- 退出时随 picker/RViz 一并回收，日志 `/tmp/r1103_tf_static.log`，结果 JSON 的 `logs` 增 `tf_static`；
- `docker/README.md` 同步写入该机制与 RViz 空白排查读数。
