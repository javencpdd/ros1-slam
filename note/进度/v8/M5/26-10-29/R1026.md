# R1026 · 语义地图接入规划：support 面转换与版本联动

- 时间：2026-10-31 20:25—20:45 CST（qoder）；性质＝语义地图消费者到规划的闭环
- 依据：R1004/R1008 只有语义 provider 与只读目录，规划器没有语义入口；
  README 的「语义地图消费者/规划联动」一直列为未实现。

## 一、实现

- `semantic_support_bridge.py`：把 `attributes.role == "support_surface"` 的
  `box` 要素转换为 map.v1 支撑面（盒顶为 z_reference、厚度为盒高、XY 为足迹，
  `attributes.edges` 沿用 map.v1 边形状）；结果统一走 `support_map.build_support_map`
  的契约校验；非 box 几何、非法面 id、无面、断开面均 fail-closed。
- `semantic_support_bridge_node.py`：订阅语义地图 String，发布同一版本的
  support_map（latch）与状态；解析/转换失败只发错误状态，不发布旧图。
- 组件与图：`v8.fw.semantic_provider_support`、`v8.fw.semantic_bridge`、
  `graph_semantic_planning.yaml`（provider→bridge→`v8.fw.local_native`）与
  实例配置 `local_native_sem.yaml`（`map_topic=/v8/support_map_sem`）。
- `semantic_planning_smoke.py`：按图经 ProcessRunner 启动三实例，冒烟注入
  语义 v2 更新。

## 三、边界

- `role=support_surface` + `box` 是新增的语义解释约定，不是冻结契约；
  只有轴对齐盒可转换，polygon/line/point 不解释。
- 语义更新由冒烟直接发布注入（provider 节点仍只读文件）。
- 语义层到规划的联动是「支撑面」这一种消费者；障碍、语义标签与规划代价
  尚未接入。
- 不新增判据；A1—A7 仍 `NOT_VALIDATED`。
