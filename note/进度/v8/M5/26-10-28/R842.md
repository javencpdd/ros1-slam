# R842／批491：A5 ROS step 用例修复——终段完成不再由时钟单独认证接触

更新时间：2026-10-28

## 1. 问题与根因

R841 的 `a5_ros_v2_step_fail.json`：step 例 4/5 中的唯一红——起点 (−0.4, 0, 0) → 目标 (0.6, 0, 0.15)，
末接触 (0.2000386, 0, 0.15000966)、轨迹 30 点，状态停在 `E_LOCAL_SUPPORT`，
节点日志重复「start requires exactly one matching z support」。

复现链（离线，用记录末位姿直接调 `plan()`）：

```
plan(layers(), (0.20003863304891153, 0, 0.15000965826222787), (0.6,0,0.15))
→ E_LOCAL_SUPPORT: start requires exactly one matching z support
|z − 0.15| = 9.66e-6 > 1e-6（resolve 的精确匹配门）
```

成因在控制器而不是地图或评价器：

- step 的规划是 3 点＋驻留：`(-0.4,0,0)@t0 → (0.2,0,0.15)@t0+1.2 → (0.6,0,0.15)@t0+2.4 → 驻留@t0+3.6`，
  `valid_until = t0+1.5`；
- 旧 `track_segment` 对**终段**（`planned_distance ≤ 1e-12`）只要 `now >= target[3]` 就报
  `complete`——**时钟一到就认证接触**，不看实际是否已到面；
- 第一段到面后仍在毫米以下的残余收敛（在途指令继续推动载体），旧规则在下一次
  控制拍就宣布完成；清掉轨迹后从离面 9.66e-6 的位姿重规划 → `E_LOCAL_SUPPORT` →
  永远拒动。判据 `1e-6` 与评价器均未改动。

## 2. 改法

`local_planner/local_native.py::track_segment`：终段在 `now < target[3]` 时仍只保持；
`now >= target[3]` 后**不再按时钟直接 complete**，而是落入与实际相同的完成判据
`max(距离, 观测距离) + uncertainty_m ≤ 1e-6`——不满足就继续按反馈收拢（docking），
满足才 `complete`。即：**时钟不能单独认证接触，完成必须由实际位姿给证**。
没有放宽 `resolve` 的 1e-6、没有改 `evaluate.py`、没有吸附落点、没有丢弃执行采样。

新增单测 `test_terminal_clock_does_not_certify_contact_with_command_in_flight`：
在段末时刻把位姿放在离面 9.66e-6（x +3.9e-5）处——旧规则报 complete，新规则不报、
且 z 速度为负（向面收拢）；位姿精确到面时才 complete。

## 4. 另起句：F5「dynamic 段 3 碰撞」的口径（不改 R841 旧文）

`dynamic_collision` 样点、段 3），**不是** `a5_ros_v2_step_fail.json`（v2：dynamic 755 点、评价 ok）。
