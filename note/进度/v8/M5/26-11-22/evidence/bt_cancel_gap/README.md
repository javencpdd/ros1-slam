## 为什么单独做锚点复核件

第十一节通篇靠「文件:行号」立论，一共 35 枚锚点。行号是会漂的代理量：只要有人往
`bt_console.cpp` 里插一行，整节论证就静默指到别处，**而没有任何闸会变红**（坑 60／61 那一族）。
所以把锚点做成表，任一枚 MISS 就打 `rc=5` 并把「实际那一行」原样打出来，让复核一眼分清是行号漂了
还是符号改了名。

## 两件东西

| 文件 | 作用 |
|---|---|
| `_anchor_check.sh` | 35 枚锚点逐枚 `sed -n Np` + `grep -qE`；含两条反控 |
| `anchors.log` | 上面这件最近一次的 stdout 落盘（`--log` 产出）。★只 `print` 不留档＝自报，本仓不收★ |

用法：

```
bash note/进度/v8/M5/26-11-22/evidence/bt_cancel_gap/_anchor_check.sh        # 只看
bash note/进度/v8/M5/26-11-22/evidence/bt_cancel_gap/_anchor_check.sh --log  # 同时刷 anchors.log
```

退出码：`0`＝27 枚全命中且两条反控都没退化；`5`＝有锚点漂了或反控失效；`9`＝前置缺失（不在 git 仓内）。

## 两条反控在防什么

1. **不存在的行号**（第 999999 行）必须取不到内容 —— 防 `check()` 被写成恒返回 0；
2. **正则在无关行上不误命中** —— 防正则退化成 `.*` 这种「怎么都绿」的空控。

两条都 MISS 才算本件活着。这两条不是装饰：锚表是手抄的，抄错一枚就会把「漂移」误报成「没漂」，
而误报的方向恰好是**静默通过**。

## 一次真实的抄错（留档，说明反控为什么必要）

第一版表里把「满队才拒」写成 `bt_console.cpp:966` + 正则 `goal queue full`，实测 MISS ——
966 是 `last_event = "queue_full"`，日志串在 967。诊断正文写的是区间 `:966-969`，没有错；
错的是锚表这一枚的取值。改成 `967` 后 27 枚全命中。**这正是本件要抓的那类偏差。**
