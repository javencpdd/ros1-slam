## 二、镜像构建（只在需要重建时做）

```bash
cd /home/jack/ysc-code/ros1-slam/docker
cp .env.example .env        # 首次；若已有 .env 请看下面的"注意"
bash lint.sh                # 构建前静态自检，必须全绿

SLIM=1 PROFILE=sim docker compose --profile sim build sim
```

`docker/.env` 里三个值不要乱改（本机实测过的组合）：

| 键 | 值 | 为什么 |
|---|---|---|
| `ROS_BASE_IMAGE` | `fishros2/ros` | 本机已有该镜像（4.77GB），**零拉取**。直连 Docker Hub 是 000 超时 |
| `ROS_BASE_TAG` | `noetic-desktop-full` | 含 Gazebo 11.15.1 + 234 个 ros-noetic 包，省一大半 apt |
| `SLIM` | `1` | 只编仿真需要的包，省掉 fast_gicp / SCAN 五包 / 真机驱动 |

> **注意**：`docker/.env` 若是从旧版 `.env.example` 拷的，会缺 `ROS_BASE_IMAGE` / `SLIM` /
> `BUILD_HTTP_PROXY` 这几行——`cp .env.example .env` 重拷一次最省事。

镜像产物约 **7.5 GB**，构建耗时：deps 层缓存命中时约 5–6 分钟（其中 catkin 编译约 260 秒）。

## 三、启动步骤（分层，按你要做的事选）

### 3.1 只跑判据（无头，最省资源）

```bash
cd /home/jack/ysc-code/ros1-slam/docker
docker compose --profile sim up -d sim
docker compose exec sim bash /opt/ros1-slam/docker/sim.sh clean        # 先清残留（强烈建议）
docker compose exec sim bash /opt/ros1-slam/docker/sim.sh smoke stageA
```

`sim.sh smoke` 支持 `stageA` / `stageB` / `stageC` / `all`。
**Stage A** = 闭环回归（漂移/转向/回程/点云频率/IMU 频率/飞点/RTF）；
**Stage B** = teb 物理闭环导航；**Stage C** = hdl 重定位（需要 `data/maps/lite3.pcd` 样张，仓库里通常没有）。

### 3.2 判据 + 旁观（一边跑一边看）

**关键：旁观者必须与 smoke 在同一个容器里**（另一个 `docker compose exec`）。
原因：`sim` 容器的 `ROS_IP` 是 `127.0.0.1`，跨容器时 master 会把 `127.0.0.1` 通告给别人，连不上。

终端 1（跑判据）：
```bash
docker compose exec sim bash /opt/ros1-slam/docker/sim.sh smoke stageA
```

终端 2（看 Gazebo 3D）：
```bash
docker compose exec sim bash -lc 'VIZ_HOST_X=1 bash /opt/ros1-slam/docker/viz.sh gzclient'
```

终端 3（看雷达点云 / 建图）：
```bash
docker compose exec sim bash -lc 'VIZ_HOST_X=1 bash /opt/ros1-slam/docker/viz.sh rviz-raw'
```

> **旁观者会在判据跑完时自己退出**——这是正常的：`m2_smoke.sh` 的退净判据要求
> `kill_all` 把 gzserver 关掉，gzclient/rviz 连的 Gazebo/ROS master 消失，它们随之退出。
> 想长时间看画面，请用 3.3（不跑判据，只起场地）。

### 3.3 只看仿真（不跑判据，长时间观察）

```bash
docker compose exec -d sim bash -lc 'VIZ_HOST_X=1 setsid nohup bash /opt/ros1-slam/docker/sim.sh gazebo > /tmp/gz.log 2>&1 < /dev/null'
docker compose exec sim bash -lc 'VIZ_HOST_X=1 bash /opt/ros1-slam/docker/viz.sh rviz-raw'     # 或 gzclient
```

`sim.sh gazebo` 只起**场地 + 伪狗 + sim_adapter**（不含建图）。
要看建图过程得另起 faster_lio——`viz.sh rviz-map` 会自动检测 `/cloud_registered`，
没有就自己把 `m2_mapping.launch` 拉起来。

### 3.4 收尾

```bash
docker compose exec sim bash /opt/ros1-slam/docker/sim.sh clean   # 清进程，看端口是否归零
docker compose --profile sim down                                  # 停容器（命名卷保留，重启秒起）
```

## 四、可视化使用文档

### 4.1 `viz.sh` 五个子命令

| 命令 | 看什么 | 前提 |
|---|---|---|
| `viz.sh check` | 自检：DISPLAY / X 套接字 / OpenGL renderer / gzclient·rviz 是否就位 / 当前话题 | 无 |
| `viz.sh gzclient` | Gazebo 3D 客户端：世界件、伪狗、雷达 | 场地在跑（或会自动连场地一起起） |
| `viz.sh rviz-raw` | **雷达原始点云**（`/rslidar_points`，Fixed Frame=`rslidar`） | 只要场地起着 |
| `viz.sh rviz-map` | **建图过程**（`/cloud_registered` + `/cloud_registered_body`，Fixed Frame=`camera_init`） | 需要 faster_lio；没有会自动拉起来 |
| `viz.sh rviz-nav` | 导航（代价图/路径） | 需 SCAN 规划器（`SLIM=1` 镜像**不含** `30_3rd`，会提示只有 Axes） |

前缀 `VIZ_HOST_X=1` 表示"直通宿主机 X"；不加则用容器内 Xvfb 软渲染（看不到窗口，只适合截图/无人值守）。

### 4.2 为什么 `/livox/lidar` 不能直接看

`/livox/lidar` 是 `livox_laser_simulation/CustomMsg`（自定义消息），rviz 没有对应插件。
`sim_adapter` 已经把它转成 `/rslidar_points`（`sensor_msgs/PointCloud2`，frame=`rslidar`），
**rviz 一律看 `/rslidar_points`**。

### 4.3 三条可视化路线

| 场景 | 路线 | 怎么做 |
|---|---|---|
| 坐在这台机器前（有桌面） | **A · 宿主机 X 直通** | `VIZ_HOST_X=1`，compose 已挂好 X 套接字 + cookie |
| 远程 SSH，想用浏览器 | **B · Foxglove 网页端** | `docker compose --profile extras up -d rosbridge`，浏览器连 `ws://<IP>:9090`，用 `lite3_bringup/mapping_viz.launch` |
| 远程 SSH，只有 VNC 客户端 | **C · 容器内 VNC** | `Xvfb :99` + `x11vnc -display :99 -rfbport 5900`，镜像已装 `x11vnc` |

## 六、踩过的坑（都已修进配置，照抄即可，别重踩）

| # | 现象 | 根因 | 处置位置 |
|---|---|---|---|
| 1 | 构建报满屏 `Unable to locate package` | compose 把调用方 shell 的 `HTTP_PROXY=127.0.0.1:xxxx` 继承进构建容器，那个端口在容器内不存在 | compose 改用 `BUILD_HTTP_PROXY`（不再同名继承）+ Dockerfile 加 FATAL 自检 |
| 2 | ROS 包装不上（`mbf_costmap_nav` 等 8 个） | 基础镜像自带 tuna 源 403、`packages.ros.org` 的 key `F42ED6FBAB17C654` 过期 | Dockerfile 源切 USTC + `apt-key adv --keyserver keyserver.ubuntu.com` 刷新 |
| 3 | `rospack find livox_ros_driver2` 找不到 | 上游只给 `package_ROS1.xml` / `package_ROS2.xml`，没有 `package.xml` | 构建时 `cp package_ROS1.xml package.xml`（上游 README 的前置步骤） |
| 4 | `tf/transform_broadcaster.h: No such file` | `lite3_gazebo_sim/CMakeLists.txt` 没把 tf 声明为 catkin 组件 | 构建期设 `CPATH=/opt/ros/noetic/include`（不改项目源码） |
| 5 | `pcap.h: No such file` | 漏了 `libpcap-dev`（`lslidar_driver` 需要） | Dockerfile apt 清单 |
| 6 | `fatal error: livox_laser_simulation/CustomMsg.h` | 第三方包缺 `add_dependencies` 到自己的 `*_generate_messages_cpp`；**与 `-j` 无关**，是目标排序 | `docker/catkin_build.sh` 三步法：只跑 cmake → 用 `make help` 枚举预生成消息头 → 正式并行编译 |
| 7 | 判据「退净/进程面」必 FAIL | 容器 PID 1 是 `sleep infinity`，被 kill 的子进程变 `<defunct>` 僵尸，不收割 | compose 给各服务加 **`init: true`**（PID 1 = `docker-init`） |
| 8 | rviz 卡在 `RViz: waiting for master` | `docker compose exec` 会话里 `ROS_MASTER_URI` 是**空值**（entrypoint 只在自身进程树转换 `ROS1_MASTER_URI`） | compose 的 `sim`/`sim-viz` 同时显式给 `ROS_MASTER_URI` |
| 9 | rviz 只有 Axes、没有点云 | ① `sim.sh gazebo` 不含建图，`/cloud_registered` 不存在；② 用 SCAN 的 rviz 配置看 LIO 话题 | 新增 `rviz-raw`（看 `/rslidar_points`）与 `rviz-map`（自动补建图），配置从 `loam_livox.rviz` 派生 |
| 10 | rviz 窗口一堆 `failed to load driver: nvidia-drm`，个别程序黑屏 | 宿主机 X 走 DRI3 点名 NVIDIA，容器无 NVIDIA 运行时；而宿主机 X 本身就是 `llvmpipe` | `viz.sh` 的宿主 X 模式显式 `LIBGL_ALWAYS_SOFTWARE=1` |
| 11 | 反复起停后出现 2 个 `rosmaster` / 2 个 `gzserver`，rviz 连到另一个图 | 残留未清 | 新增 `sim.sh clean`（对齐退净判据：清进程 + 查端口） |
| 12 | 手写 rviz 配置后 Displays 面板空白 | rviz 对配置字段挑剔，写错会静默丢 display | 改为**从项目已有的 `loam_livox.rviz` 派生**，只改必要字段 |

> 通用教训（两次同型）：**compose 的 `${VAR:-default}` 会静默继承调用方 shell 的同名变量**。
> 凡"宿主机语义"的变量（代理、`XAUTHORITY`）都不要用原名，一律加前缀（`BUILD_*` / `X_*`）。

## 七、已知限制

1. **未跑 Stage B / Stage C**：Stage B 需要 `mbf_costmap_nav` 全链（镜像已装）但耗时更长；
   Stage C 需要 `data/maps/lite3.pcd` 样张，仓库里通常没有。
2. **`rviz-nav` 在 `SLIM=1` 镜像里没有意义**：`30_3rd` SCAN 五包被瘦身跳过，
   要用它得 `SLIM=0` 全量构建。
3. **渲染是软件（llvmpipe）**：宿主机 X 本身就 `Accelerated: no`，容器改不了。
   gzclient/rviz 能用、帧率有限（实测 rviz 约 9–10 fps）。
4. **GUI 需要宿主机有 X**：纯 SSH 无 X 的环境走 Foxglove 或 VNC（见 4.3）。
5. **判据证据默认落在容器 `/tmp`**：容器一删就没了。要留证据请 `docker cp` 出来
   （本次已把 Stage A 证据拷到 `证据/logs_stageA/`）。
6. **`SLIM=1` 的瘦身只作用于镜像构建阶段**：`build.sh` 故意不提供 `--slim`，
   因为 `ws/src` 是 bind-mount 的宿主机目录，在容器里打 `CATKIN_IGNORE` 会写回工作区。
