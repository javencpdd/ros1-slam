# n 稿：把「球形 blind」换成「机体长方体」自遮挡模型（主理人 2026-10-10 提出；本稿只做几何与代价，不改任何代码/配置）

> 出处：主理人指令——「你不是有 lite3 自身的尺寸参数吗，为什么不建立更适合的模型呢，通过球形来过滤会浪费不少数据，用长方体来代指？但要主机雷达与 lite3 的相对位置。障碍物的位置不变，同时建立更适合 lite3 的过滤模型，真机也是一样」。
> 一句话结论：**这条比在册的 C9（改 blind 数值）与 C10（挪 P4 注入距离）都更对，而且便宜**——判据就写在"原始点在雷达系里的坐标"上，机体盒在雷达系是**常量**，连 TF 都不用查。本稿给出可算的部分、算不了的部分、三种落地案与代价，以及必须先实测的三个数。**未自落任何改动**。

## 2 几何事实（能算的部分，逐条给来源）

### 2.1 仿真侧（在册 URDF，纯算术可得）

- `base_to_rslidar` 固定关节 `origin xyz="0 0 0.38" rpy="0 0 0"` ⇒ 雷达原点在 `base_link` 正上方 0.38 m，**无俯仰/偏航安装偏角**（来源：`ws/src/95_simulation/lite3_gazebo_sim/urdf/lite3_planar.urdf.xacro:52-55`）。
- 躯干碰撞盒 `box size="0.42 0.31 0.22"`，其 visual/collision 的 `origin xyz="0 0 0"`（来源：同文件 `:25-32`，link 名保持官方 `TORSO`，M2R5 起恒等挂于 `base_link` 下）。
- ⇒ 在**雷达系**里躯干盒＝心 `(0, 0, −0.38)`、半宽 `(0.210, 0.155, 0.110)`；
  - **最近面**＝正下方顶面，距离 **0.38 − 0.11 = 0.27 m**；
  - **最远角**＝`(0.210, 0.155, −0.490)`，距离 **√(0.210²+0.155²+0.490²) = 0.555 m**。
- ⇒ **仿真里"机体自身回波"整个包络被 0.56 m 罩住**，而 `blind` 切在 1.0 m。

### 2.2 真机侧（手册给的外形，安装位不给）

- 站立尺寸 长×宽×高 **610×370×436 mm**、趴地 **680×370×145 mm**、整机 12.2 kg、有效负载 4.5 kg（来源：`docs/绝影Lite3探索版产品手册 V2.0.0.pdf` §本体规格，`pdftotext -layout` 第 191–195 行）。
- 用站立包络做同一套算术：若雷达装在顶面附近，机体最远角（底面外沿）到雷达 ≈ **0.53 m**（水平半长 0.305、垂直 0.43）；加腿的外张与加装支架会把它推大一些，**但推不到 1.0 m**。
- **两处不能装作已知**：①真机雷达的实际安装高/俯仰（我们 xacro 里的 0.38 是**约定值不是实测值**，R80 已登记）；②加装 Mid-360 后的线缆/支架是否会进入视场。**这两个数必须现场量**（量的动作要真机窗口，见 §5）。

### 2.3 球形判据浪费了多少（可比的部分）

| 口径 | 体积 | 相对躯干盒 |

### 7.2 最重要的一条不是"盒更好"，而是**"换盒不能只换盒"**

球形 `blind` 在我们这条链上一直在替我们干一件**没人记账的活**：删掉插件那 70% 的 `(0,0,0)` 无命中占位点
（它们 r＝0，落在任何半径的球里）。

| 形状 | 障碍保留（收益） | 下游总点数（负载） |
|---|---|---|
| 现网 球 1.0 | 3993（×1.00） | 47943（×1.00） |
| 球 0.2 | 27214（×6.82） | 71164（×1.48） |
| **盒 m=0.05（只换盒，不剔零）** | 27214（×6.82） | **280000（×5.84）** |
| **盒 m=0.05 ∪ 显式剔零** | 27214（×6.82） | 71164（×1.48） |
| 盒 ∪ 剔零 ∪ 球 0.3 | 26048（×6.52） | 69998（×1.46） |

⇒ **正确形状＝「机体长方体 ∪ 显式剔除占位点」**。只说"换成盒"会把 ×5.84 的原点伪点灌进 `/cloud_registered`
与 SCAN 栅格，沿机体轨迹堆出一坨自己造的障碍；而这条链已经因点数超载回退过一次
（`faster_lio_outdoor.yaml:15` 的 `filter_size_surf 0.15→0.3` 注记）。剔零在真机侧无害（真机驱动不发 (0,0,0)）。

### 7.3 两列在仿真里注定为 0，不许当通过（§3 甲/乙/丙 的验证面因此有缺口）

`自回波` 与 `近地面点` 两列 14 站全 0，原因不是干净，而是**仿真里没有可打的东西**：
① 插件排掉整个模型（7.1①）；② 在册 `lite3_planar.urdf.xacro` **只有 TORSO 一个盒、没有腿**，而真机的腿外张超出躯干盒
——这恰是盒方案真正的难点；③ 实算 r<1.2m 的非零回波世界 z 全在 **0.37–0.80m**（只有障碍箱的面），**近场地面点一个都没有**。

⇒ 于是 §3 的取舍表要改口径：**甲/乙/丙 三案在"省数据"这一面已被仿真证清（×6.82，且盒≡球0.2）；
   在"挡自回波"这一面仿真测不了**，必须补一个**带腿＋地面碰撞的机体件**（无狗可做，已列任务）或直接真机。
   另：`盒 m=0.25` 开始吃障碍（25801＜27214）⇒ 外扩不能凭手感给，等带腿实测定。

### 8.1 三条从网格才看得出来的结论

1. **收益对"外扩"极不敏感、对"兜底球"极敏感**：外扩从 0 加到 0.20 一点收益都没丢（27214 不动），
   而兜底球只要加到 0.3 就立刻丢 4.3%、加到 0.6 丢一半。**⇒ 想省数据，力气要花在"别用球"上，不是"把盒画小"上。**
2. **均匀外扩是错的形状**（这是网格给的最有用的一条）：`m≥0.25` 开始**盒自己吃掉障碍**；
   但真机需要挡的是**腿**——腿向下与向两侧超出躯干，而**向前超出得少**（真机站立 610×370mm，
   仿真躯干盒 420×310mm ⇒ 首尾各需 ≈0.095m、左右各需 ≈0.030m——**两个方向差三倍**，
   而竖直方向腿是从体底一直伸到脚，根本不是"外扩一点"能表达的）。
   ⇒ 该做的是**两级盒**（躯干盒小外扩 ＋ 腿部包络盒单独给尺寸、主要在下方与侧向），
   而不是一级均匀 `m`；均匀 `m` 要么挡不住腿、要么把正前方一起吃掉。
3. **盒阴影半径是"外扩的代价"的正确显示方式**：`m=0.20` 时盒的最远角已到 **0.878m**——
   离现网球半径 1.0m 只差 0.12m，也就是说**大外扩会把"球形浪费"换个形状重新引进来**。
   `m=0.05` 时阴影 0.398–0.633m，只有现网的一半 ⇒ 与结论 2 合起来＝**躯干盒取小外扩、腿部另做一级**。

### 8.2 边界声明（别把这张表读成尺寸已定）

网格全部来自**仿真落盘帧**：收益与负载两列可信；但"外扩该取多少"的真约束是**自回波覆盖**（腿＋加装支架＋真机安装高），
而仿真**无腿、无近场地面回波**（§7.3）⇒ 本表给的是**上界侧的几何证据**（超过 m=0.25 一定吃障碍），
**不是最终尺寸**；最终尺寸等 **B15** 结合真机量，验证面缺口由 **B16** 决定（补带腿＋地面的机体件或真机）。
⇒ 也正因为"超过 0.25 一定吃障碍"这条**上界**是可信的，B15 若按均匀外扩做，可用区间已经很窄（0–0.20m）。
