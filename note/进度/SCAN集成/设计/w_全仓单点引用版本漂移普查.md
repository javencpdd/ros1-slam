## 3. 本稿新暴露的三格（是"规矩"缺口，不是"错题"）

- **甲·件名多义比行号漂移更靠上游。** 裸名 `CMakeLists.txt` 在**仓内同名 348 件、系统域 2 件**（本件实测计数），写 `CMakeLists.txt` 第 192 行 时没有任何读者能确定指哪一个——而 **坑52 只要求"写全名"，没有要求"防同名"**。建议口径（不成闸、待裁）：凡盘上同名 >1 的被引件，引用必须给**到根的全路径或 git 可解的 `commit:path`**。
- **乙·符号链接件的行号由"装的是哪一版"决定，不由本仓 git 史决定。** `ws/src/CMakeLists.txt` 是 mode **120000** 的符号链接 → `/opt/ros/noetic/share/catkin/cmake/toplevel.cmake`（现 71 行）；git 里存的是链接文本（1 行）。⇒ **坑60 的"版本限定"要再加一维：链接件／安装版本**。这类引用的行号既不能被本仓 `git show` 重放、也不能被 VCC 的覆盖面判红——只能标"不可判"。
- **丙·"在册勘误句"的保护有缺口。** VCC 的 FIXUP 词表按同句关键词判，本轮实测两处：① 5 条 RED 里有 **2 条**被本稿判为「在册勘误句内」——`note/00_README.md:82`（真在册勘误：它把 04:237 那条错引当"写成"示例登记）与 `note/计划书v4/21_…-v4.1-雷达翻案补丁.md` 第 125 行；而后者其实是句里的「**历史**安装」（指 ysc 旧安装）撞上 FIXUP 的「历史」一词 ⇒ **真在册勘误只有 1 条**，另 1 条是误标（不修正 VCC 词表，只在此如实标出）。若不扩面＋不做本稿的 basename 回找，这两条都会被当活错报出去；② 反过来，误标也说明 FIXUP 词表要加"句内角色"约束才能成闸。

## 6. 本件自己的四处缺陷（都是这一轮跑出来的，不是事后编的解释）

1. **git 史维度对符号链接件量到的是 blob**：首版对 `ws/src/CMakeLists.txt` 报「该件历史最多 **1** 行」——那是链接文本的长度，不是内容长度 ⇒ 假读数。修法：先判 `islink` 且实身在仓外，直接标「git 史不可判（行号由安装版本限定）」，不再跑历史扫描。
2. **回找原句时用了 VCC 解析后的全路径**：VCC 会把简写解析成仓内全路径（`lvr2 CMakeLists.txt` 第 192 行 ⇒ `ws/src/CMakeLists.txt` 第 192 行），首版按解析后的串去文档里找 ⇒ 3 条「本档位置未找回」。修法：按 **`basename:行号`** 找原文，并顺带产出同名件个数（就是 §3 甲那格的来源）。
3. **把 yaml 点路径判成"键名错"**：`mapping.extrinsic_est_en`／`preprocess.blind` 在嵌套 yaml 里**永不字面出现**，首版判 2 条键名错=**件的匹配面缺陷**。修法：点路径先取叶名二次判定，命中则改标「口径松（在册写点路径、件内是嵌套键）」。
4. **件把 VCC 的三份面输出写到了仓根**：件内先 `cd "$ROOT"`、被重定向的输出名却是相对名 ⇒ `vcc_full.out`/`vcc_live.out`/`vcc_evidence.out` 落在 `/home/ros1-slam` 而不是证据目录（`git status` 里以三个未跟踪件现形，才被抓到）。这不是读数错，是**件污染工作树**——同族于坑50（动作落点没算清）与坑59（证据存在≠证据可达）。修法＝输出路径一律由 `$SELF` 的目录推（`OUTDIR=$(dirname "$SELF")`）；仓根那三个误落件在本批提交前删净（未入任何台账引用、未提交，故不另存）。
   四处都在首版/本轮、未入在册读数 ⇒ 依本仓约定不另存旧件，错误登记在本节。
