## 3. J2 死配置单源化

### 3.1 现状与「谁是权威」的机制事实

8 键双写：config/scan_params.yaml:2-10 与 advanced_param.xml:112-119 逐字同值（**该 yaml 后按主理人裁定删除**，现由 `v_scan_o1.sh` 的 B-6a 断言它"已不在位"；此处保留是当时的事实），但**加载点为零**（§1.1 第 4 条实测）⇒ yaml 是影子。真实生效链：xml 的 8 条顶层 param（文件内 :112-119，**不在任何 <node>/<group ns> 内 ⇒ 落根命名空间**）→ 全名 /closed_loop_controller/<key> → closed_loop_controller 的私有句柄 nh("~")（main :232；ros::init :230 节点名 closed_loop_controller，70_scan.launch:60 未加 ns ⇒ 私有 ns 恰为 /closed_loop_controller）→ :63-70 的 loadRequiredParam 逐键读取。静态实证（roslaunch --dump-params，本轮实跑）：/closed_loop_controller/finish_dist: 0.15，另 7 键齐，且 /body_pose_topic: /LIO/odom_vehicle、/scan_planner_node/fsm/thresh_replan: 1.0 同表可见。

### 3.2 派单/坑22 的两个选项，各有一处必须纠正

- 「壳包真加载」的 ns 必须落在**closed_loop_controller 的私有 ns**，不是坑22 处置一示例写的 scan_planner_node：后者会把键放进 /scan_planner_node/ 之下，:63-70 读不到 ⇒ 造出第二个死配置。消费者身份的代码依据：读键句柄 = closed_loop_controller 的 nh("~")（:232＋:63-70），写键方 = xml:112-119 的根级 param（与 scan_planner_node 无关，后者读的是自己的 fsm/* 与 grid_map/* 私有键，见 scan_replan_fsm.cpp:42-54）。
- 三个形态我用了 /tmp 探针实测（探针已删，零节点）：
  1. rosparam file=… ns=closed_loop_controller ⇒ dump 出 **/closed_loop_controller/closed_loop_controller/finish_dist**（双嵌套）。因为 scan_params.yaml 的**顶层键已经是 closed_loop_controller**（:2），再套同名 ns 就重复一次 ⇒ 这正是坑22 的复刻形态，而且它「看起来加载了」。
  2. rosparam file=… 不带 ns（根级） ⇒ /closed_loop_controller/finish_dist（与读取路径对得上）。⇒ **若将来真要壳包覆写，写法必须是「不带 ns」**。

- 结论：**「壳包真加载＋删 xml 重复键」这个选项整体作废**——后半句是对 30_3rd 的删除动作，撞 §2.3 的同一红线（且 xml 的 :112-119 不在 pcd2grid 那种「死件」位置，它是唯一生效来源，删之即参数全缺、:63-70 直接 ROS_ERROR_STREAM 退出）。选项空间只剩「删 yaml」。

### 3.3 推荐（J2）＝ 删除 config/scan_params.yaml，参数唯一来源＝advanced_param.xml:112-119

- 理由三条：(1) 删 yaml 是**零行为变化**（它本就无人读，sha 层面 ws/src/40_navigation/lite3_scan 是自有件，不涉基线）；(2) 真加载会把双源问题从「影子=死的」变成「影子=活的、靠行序裁决」，并把 xml:116 的 max_vx（值为 $(arg max_vel)，与 :19 的 arg 和 :102 的 optimization/max_vel 三处联动）从 arg 手里抢走 ⇒ 命令行 max_vel:= 对控制器静默失效，yaml:7 那句「两处必须同值」的人工注释约束升级为无人看守的纪律；(3) 单源化后，「改 yaml 以为改了参数」这个坑的物理入口消失，不必靠纪律记忆。

### 3.4 机判判据（改后如何证明参数真的生效）—— 见 §5 表 B
