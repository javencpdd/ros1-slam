# z 高度契约实测（2026-11-27）

## 结论先行
- 静止 30 s 的 `contract.pose.z` **稳定**：n=23，min −0.0643，max −0.0637，median −0.0637，
  std **0.0003**，p95 −0.0637，30 s 内漂移 +0.0007。
- 支撑面 `z_reference = 0.0`，`support_tol_m` 默认 **1e-6** ⇒ 残差 0.0637 ≫ 容差，必拒。
  detail 原文：`start requires a matching z support | start=(5.2095,2.4614,-0.0417) goal=(6.5,2.6,0.0)`。

## 这是"稳定的偏置"，不是"漂移"
std 3e-4 对偏置 6.4e-2 ⇒ 噪声比 1:200。所以：
- **不能**用"加大容差"掩盖（0.05/0.25 会同时放过多层误配）；
- **也不能**简单把某一次采样值写死进配置（不同次运行观测到 −0.0417 / −0.0614 / −0.0637，
  说明它随初始状态变化，不是常量）。

## 语义拆解（两侧基准不同）
- `local_native` 的 z 语义是**足底/接触高度**（模块 docstring 明写）；
- LIO 给的 `pose.z` 是**机体原点**在 map 系的高度；
- `base_link` 离地约 0.11 m（URDF `lidar_z=0.34 = 目标 0.45 − 稳态基座 0.11`）。
⇒ 需要的是"机体原点 → 支撑参考点"的**一次**刚体偏移，且该偏移应由几何给出，
   而不是按验收误差拟合。

## 下一步（需裁决的最小接口方案）
把"支撑面关联容差"从"碰撞/净空/轨迹验证容差"里**独立**出来：
- 新增 `support_assoc_tol_m`（默认沿用 1e-6，只在装配处显式给值）；
- 参考点转换 `plan_ref_z` 由几何常量给出（体高），并在图里显式声明来源；
- 两者都必须有负控：同 XY 不同楼层、错误高度、坡面、台阶、净空。
