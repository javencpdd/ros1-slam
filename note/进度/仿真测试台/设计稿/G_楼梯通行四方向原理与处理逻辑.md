# G · 「让 Lite3 会走楼梯」的四个开源方向：原理与处理逻辑（含方向一选定理由与包线对账）
> 定位：设计域说明件，**不是实现、不改任何门值/判据**（方向一的真实现仍受 #6 §9「小张接口复核＋主理人批准」双闸与 #46 路线裁定约束）。
> 写它的目的：把"为什么先做方向一"从我的口头理由变成可复核的机理描述，并顺手记下四件事各自的**判别力边界**——尤其"同一串台阶，凭什么说该上而不是该绕"。
> 实证依据在括号里给出（均为本仓盘上/在册事实，不是推测）。

## 0. 一条链上的五个位置（四方向分别作用在不同段，这是它们不能互相替代的原因）
```
① 几何/高程表征      点云/深度 → 高程图 / ESDF / 语义栅格
② 可通行性判据        坡度·台阶·粗糙度·周期性 / 可达性 / 标签
③ 代价与地图          层组合、覆写、 inflation
④ 规划                全局路径形状 + 局部轨迹优化
⑤ 执行/控制           步态、落脚、平衡、接触
```
**当前我们仿真能闭合到 ④，⑤ 结构性缺位**（载体是刚体盒子：`lite3_planar.urdf.xacro` 只有 fixed 关节，插件用 `SetLinearVel`/`SetWorldPose` 推进）。在册早已把这条边界写死三处：#6 §7「2.5D 单高度假设＝永久放弃悬挑/多层/桥洞」、X4 裁决「仿真仅证规划质量，真越障归真机/MuJoCo」、A 文分工「3D 复杂地形（真机台阶坡道）＝SCAN 全（真机侧）」。
四方向的落点：**一 = ①+②，二 = ③+④，三 = ⑤（并把②的定义权从地图转移到机体），四 = ①+②的先验注入**。

## 1. 方向一：高程图 + 三通道可通行性（elevation_mapping / grid_map 一族）
- **表征原理**：对每个 (x,y) 列维护**一个高度值 + 质量（方差/有效性）**，即 2.5D；从点云逐列做统计（中位/P50 抗毛刺），随机器人移动增量融合。**代价**：同一列的"上行空域"被压掉 ⇒ 悬挑、桥洞、多层从表征上就不可表达（这正是 §7"永久放弃"的机理，不是保守措辞）。
- **处理逻辑（数据流）**：
  1) 点云 → TF 到 map 系 → 栅格索引（0.1m）；
  2) 每列取高度统计（P50）＋邻接 8 域取 `step = max|Δh|`；列内取 `roughness`（z 一阶差分 RMS）；由邻列高差取 `slope`；
  3) **三通道判据**：`slope>θs 或 step>θh 或 rough>θr ⇒ cost=100`；零覆盖列 ⇒ `−1 未知`（N1 禁令：未覆盖≠自由）；
  4) 输出代价栅格 → ③（进 costmap 或我方层）→ ④ 规划绕行/放行；
  5) 观测健康：`NaN 率>30% ⇒ WARN`（建图质量与"能不能判"解耦，别让无图当自由）。
- **楼梯在这里怎么被"看懂"**：梯级产生**等间距的 step 序列**。若只用"台阶高"单判据，上行楼梯与矮墙侧壁都可能超阈 ⇒ 都判障碍；判别力来自**踏步深度与周期性**（前进方向 z 剖面的自相关/谱峰 + 平台深度 ≥ 足端落域）⇒ 这是我们要在方向一里补的第四通道，也正好是 O-8 缺口的另一半（O-8 现况：在册穿墙式只看"离最近占据点"，实证同一轮里"轨迹离箱心 0.128m"与"离任意占据 0.262m"并存，判成"不穿墙"）。
- **在本仓的可行性实证**：`grid_map_msgs`/`grid-map-*` 全族在装且实测可导入（R59 §8.1）；吞吐实测在**目标平台本机**（`/proc/device-tree/compatible=nvidia,tegra194`、6 核）中位 224ms/帧、向量化 ≈127ms，未触在册 0.5s/帧降级线，但 10Hz 输入侧需隔帧或 C++（§8.2）；GPU/CuPy 路线已被红线排除（无独显 + GLFW segfault 实证）。

## 2. 方向二：SCAN（3D ESDF + 轨迹优化）——它**不判可上性**
- 原理：`plan_env` 把点云建成 ESDF（带距离场），FSM→轨迹优化在 3D 自由空间里找可行轨迹；局部规划器眼里**几何障碍只有"占不占"**。
- 楼梯处理逻辑：**梯级 = 一组体素障碍**，除非代价层把可上区域标成低代价，它一定绕。所以二不是"会爬"的解，是"按地图说的走"的解——这也是 A7 P4 的机理性根因（扰动后新轨迹仍从注入箱心 0.128/0.190m 处穿过，说明它优化的是代价值和光滑度，不是"可上性"）。
- 结论：**二必须与一合流**（一给代价，二照代价规划）。二者不并列。

## 3. 方向三：腿式动力学与控制（OCS2/legged_control、MuJoCo 步态）——唯一能回答"上得去吗"
- 原理：**可通行性的定义权从地图转移到机体**：判据不再是"坡度小于某值"，而是"在当前步态下，是否存在稳定的落脚序列与足端轨迹"（可达域、支撑多边形、接触力裕度、能耗）。
- 处理逻辑：地图（一的输出）给候选落脚与成本 → 控制器 MPC/WBC 选落脚、发关节力矩 → 接触物理决定成败；反馈再修正代价（摔/滑的样本）。
- 物料与缺口：`lite3_description/urdf/Lite3.urdf` **12 个 revolute 关节已在仓**（半件物料齐了）；缺控制器、接触参数标定、真实质量惯量，且**验收载体必须换**（真机或 MuJoCo/Isaac）——刚体盒子测不了，测出来的"成功"是假的（P4 已经演示过被物理搅浑结论长什么样：顶撞→位姿跳千米→"未到达"读数不可引用）。
- 定位：**后置**。它不解锁任何当前挂账（P4 甲/乙、#6 路线、O-8 都不依赖它），却是"真机能在楼里走"的唯一路径 ⇒ 应作为独立立项，排在"选得对"之后。

## 4. 方向四：语义/先验层——最省事也最可靠，但要人喂
- 原理：可上性不由几何推，而由**外部事实注入**：地图标签、区域注册、人工标注"此梯常通/此梯禁行/此梯仅限空手"。
- 处理逻辑：语义区域 → 覆写或抬升底层代价 → 规划照旧。Nav2 的 costmap 多图层叠加就是这套骨架。
- 为什么它对我们有现成抓手：C9 `variants` 档位机制（三档在仓）＋第 4 档 `scan_3d.yaml`（A 文已定义键面：场景→跟踪器速度上限、ESDF 分辨率、mux 源使能）。
- **两个今天刚抓到的前置**：①三档 variants 至今无人加载（其自记前置 Q11 早在 P6 结案，见 02 坑44）；②双 `StaticLayer` 的叠加语义是"后加载者整图覆盖"（R59 §8.3），语义层想覆写底图必须先解这条（#46）。
- 结论：先做**先行子集**（区域禁行 + 档位开关），把它当一的"先验注入口"，而不是先建一套语义建图。

## 5. 判别力矩阵（"同一串台阶，该上还是该绕"到底谁能答）
| 情形 | 坡度 | 台阶高 | 踏步深度/周期性（一·补） | 足端可达性（三） | 语义（四） |
|---|---|---|---|---|---|
| 上行楼梯（可上） | 可能超阈 ⇒ 误判障碍 | 单级高在阈内 ⇒ 判通 | **能分**（周期性＋深度≥落域） | 能分（需机体模型） | 能分（需标注） |
| 矮墙／梯侧壁 | 很陡 ⇒ 判障碍（对） | 一次大落差 ⇒ 判障碍（对） | **能分**（无周期、无落域平台） | 能分 | 能分 |
| 斜坡（可上） | 判通 | 判通 | 判通（单调斜面） | 能分 | 能分 |
| 悬挑/桥洞/多层 | **一结构性看不见** | 同左 | 同左 | 三可 | 四可（标注） |
| 湿滑/碎石（几何可上、物理不可上） | 判通（错） | 判通（错） | 判通（错） | **只有它能判** | 靠人禁行 |
读法：**一（含第四通道）覆盖到"几何/结构可分"这一层；三覆盖"物理可行"；四覆盖"意图与规则"**。三者不是竞争关系，是三层。

## 6. 方向一选定的理由（可复核版）
① 唯一能**在当前载体上闭环**的方向（② 只到地图与判据、④ 已通、⑤ 不参与）；② 物料已在（grid_map 在装、SCAN 作消费者已在跑、§4.3 三通道已定稿）；③ 它**同时喂两项卡住的挂账**（O-8 的第二维度、P4 甲项所需的"该不该当通道"证据）；④ 它**天然绕开 #46**（我方层直接产出合并代价，而不是塞第二个 StaticLayer）；⑤ 成本已被目标平台实测量化，降级路径（隔帧/降 res）在册内。

## 7. 附录：能力包线对账（厂商键 ↔ 设计三通道），以及一条必须承认的不可核
| 量 | 厂商 `deeprobotics_local_height_map/config` | 我们 #6 §4.3 | 关系 |
|---|---|---|---|
| 台阶高 | `step_z_max: 0.10`（h_safe）／`0.20`（v_hei） | `step>0.15m ⇒ cost 100` | **夹住了我们的值**：保守档比 §4.3 严、激进档比它松 ⇒ 0.15 既不是保守也不是激进，属"没标定过的中间值"（坑43 同族：同一语义两套数） |
| 前向步长 | `step_forward_max: 0.20 / 0.23` | 无此通道 | 缺失项：这正是"踏步深度"的机体上限 ⇒ 第四通道该用它作标定锚 |
| 坡度 | `slope_threshold: 0.839`（method1）／`0.577`（method2） | `slope>25°` | **量纲不可核**（下条） |
| 其他 | `slope_inflation 1.1`、`slope_change 0.02`、`slope_method 1` | 无 | 对应"膨胀缓冲/相邻列差/判据模式"，落地时逐项对齐，别自造 |
- **量纲不可核（本次实证）**：该包**闭源**——`find` 结果 63 个文件、**代码件 0**，节点是预编译二进制。所以 `0.839` 到底是 `tanθ`、`cosθ` 还是"高差/格边"比，**不能从源码确认**。若按 `tanθ` 解释：0.839≈**40°**、0.577≈**30°** ⇒ 与 §4.3 的 25° 明显不同量级，差异可能全在量纲而不是保守程度。**处置**：①向厂商索取参数定义与能力表（步态最大台阶/坡度/载荷）；②拿不到就走**自标定**（平地逐级升台阶高到首次失败，取 ≤0.8× 作包线，坡度同理）。在此之前，§4.3 的 25°/0.15m 一律标注为"未标定的施工值"，不得当真机能力上限引用。
- 附带发现：`step_forward_max` 的存在说明厂商把"落脚深度"当作能力参数 ⇒ 我们的第四通道不必自己发明判据，方向明确。

## 8. 落地顺序（不待批准的部分先做，剩下交闸门）
1. **(c) 包线对账**＝本文 §7（已交付）＋向厂商索取清单；

3. **(b) 离线结构判据预检**：对合成点云验"周期性＋踏步深度"能否分开"可上楼梯 vs 矮墙"，产出阈值建议表；

5. 方向一的实现开工仍等 **#6 §9 双闸 + #46 路线**。
