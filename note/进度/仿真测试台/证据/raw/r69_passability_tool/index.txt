一、这套工具答哪一个问题
H 稿 C-5 实证「同几何楼梯＋中段一根立柱」在 2 传感臂 × 3 分辨率八格里全不可分 ⇒ 「这级梯此刻能不能用」
几何答不了，只能人标（I 稿＝v4.3 补丁 X3 的"四做先行子集"）。工具只做三件事：
让**人写的标注自洽**、把它**变成机器可读栅格**、改动后**给出可粘进台账的三列摘要**。
它不生成语义、不生成地图、不改门值，也**不生成 costmap 的第二个 StaticLayer**（X2 已实测两 StaticLayer 不能叠加）。

二、命令与产物
    python3 ws/src/95_simulation/tools/passability/passability.py selftest        # 10 道自检，rc=0
    ... check [--src f --map data/maps/lite3.yaml]                                # 只校验
    ... build [--src f --out DIR]                                                 # 出 mask+json+png
    ... verify-built --src f --out DIR                                            # 生成物是否对得上源/底图
    ... diff --src f --out DIR                                                    # 三列变更摘要
产物三件（同尺寸同原点于底图 299×290、resolution 0.05、origin [-8.8,-4.35]）：
  passability_mask.pgm  每格 0=unknown / 1=blocked / 2=passable；头部自带注释「不是 map_server 占用栅格，勿直接加载」
  passability_mask.json 源文件 sha、底图 sha、尺寸、区清单与 poly 摘要 ⇒ 可判"是否过期/被手改"
  passability_preview.png 底图灰度＋绿(可通行)／红(不可通行)叠画 ⇒ 给运维核对"有没有标错地方"

三、三条写死在代码里的红线（不靠自觉）
  ①未标注永远＝unknown，任何路径不塌陷成"可走"（I 稿 R-c）；
  ②同格语义冲突＝直接红且 build 拒绝产出，**不实现"后写的赢"**（I 稿 R-d 的前半）；
  ③生成物与源/底图 sha 不符＝红（防有人直接编辑产物，或底图换了 mask 已错位）。

五、权限面（C7 选 C 的落地状态，含一处当场修掉的自用缺陷）
实测：本仓目录属主是 ros1-slam，我以 ysc 写文件，默认 ACL 只给 ysc ⇒ 我建的文件 ros1-slam **连读都读不到**；
且 setfacl 改他人目录的 ACL 被拒（`Operation not permitted`，只有属主或 root 能改）。
本批处置：`config/passability/` 这个目录是我新建的 ⇒ **我自己就能配**：已落 `default:user:ros1-slam:rw-` ＋
`default:user:ysc:rw-`，并把模板文件从 600 修成双方可读写（实测新建文件自动继承、带 `user:ros1-slam:rw-`）。
仍需 root 的只剩**既有目录**（如 `note/进度/仿真测试台`）⇒ 工单 `scripts/ops/passability_pre_acl.sh`：
dry-run 列现状与命令；`--apply` 非 root 直接拒（实测 rc=2）；`--verify` 查默认 ACL 到位与双向可写。
