### 复现6 ── 退净姿势对照：R419 做到的「绝对零」**不是**运气，是拆解顺序

见件的 sha 现读：四扇窗（R419／R429／R436／R441）的 `witness.sh` sha **全等＝`1727dc594b3cf110…`** ⇒ 四窗的见证口径同标、计数可比（这条是问题一①「可比性」的事实底座，另见 §2① 末段）。

四窗基线—退后对照（全部现读在册件）：

```
R419  起前=0 → 退后=0（witness_before / witness_after 皆 五名计数=0、端口 0）＝绝对零达成
R429  起前=0 → 首采=2（1 rosmaster＋1 rosout，11313 有 LISTEN）→ 重采=1（1 rosout）＝漏 1（本窗 29682）
R436  起前=1 → 首采=3（1 rosmaster＋2 rosout，11313 有 LISTEN）→ 2/3 采=2＝漏 1（本窗 49554）
R441  起前=2 → 首采=4（1 rosmaster＋3 rosout，11313 有 LISTEN）→ 2/3/4 采=3＝漏 1（本窗 59754）
⇒ 每窗恰漏 1 枚自有 rosout，基线单调累加：0 →（R429 后）1 →（R436 后）2 →（R441 后）3
```

**机制（现读证死，不是推测）**：`roscore` 是 roslaunch 父进程（uuid 目录里那个 `roslaunch-…-<wrapper_pid>.log` 就是它的日志）。它对 **SIGTERM/SIGINT** 会跑完整级联；R419 的拆解只用了 `kill`（默认 SIGTERM）——
```
$ grep -nE 'rosout-1\]|process\[master\]' /opt/ros1-slam/logs/57c1487c-…/roslaunch-99957655604a-2996.log | tail
[19:45:09] ProcessMonitor exit: killing rosout-1
[19:45:09] [rosout-1] killing on exit
[19:45:09] [rosout-1] sending SIGINT to pgid [3210]
[19:45:09] process[rosout-1]: SIGINT killed with return value 0
[19:45:09] process[master]: SIGINT killed with return value 0
```
R429／R436／R441 的步9 则在**见证重采之前**、对 `ss -lntp` 全表里 cmdline 含 rosmaster|roscore 的 pid 一律 **`kill -9`**（R441 日志：`收 master holder pid=59542`＝wrapper 本身、`pid=59681`＝rosmaster）。SIGKILL 掉的 wrapper **永远跑不到级联**，rosout 当场成孤儿；等脚本末尾 `trap cleanup EXIT` 再发 SIGTERM 时，那个 pid 已经是死号。三窗的 roslaunch 日志一律停在 `… roslaunch parent running, waiting for process exit / [roslaunch][INFO] spin`、**无任何 killing 行**：
```
$ tail -2 …/a5a08fe6-…/roslaunch-99957655604a-59542.log   # R441
[02:41:56] ... roslaunch parent running, waiting for process exit
[02:41:56] spin                                              ← 到此为止，没有 shutdown 段
```
⇒ **「绝对零靠本窗自己已不可能达到」这个前提被否证**：在基线=0 的容器里（R419 形），只要按 SIGTERM 级联拆，本窗自己就能达绝对零；R429 起之所以做不到，是**步9 把 SIGKILL 插在了级联之前**这个施工缺陷，不是环境决定的不可达。
⇒ 附带一条**反向红线暴露**（比漏杀更重）：R429/R436/R441 的补救循环枚举的是 `ss -lntp` **全部** LISTEN 进程（未过滤端口），而 R419 那一版是 `grep -o ':11313.*pid=[0-9]*'`（**过滤了端口**）。现读容器内三枚 rosout 各持 `0.0.0.0:58907/43163/45115/48121/33229/38437/38437…` 之类高位 LISTEN 口——也就是说：**只要别的会话（Lite3 侧、或人类手动在容器里起的 roscore）在任意端口上 LISTEN 且 cmdline 含 rosmaster/roscore，这三版脚本就会把它 SIGKILL 掉**，而脚本注释写的是「只收★本窗★master holder」。「只 kill 本窗 PID」这条红线在**两个方向上都不自洽**：对本窗派生它漏杀，对他人进程它可能误杀。

## §2 问题一（定形）裁定

# 裁：采 **乙**（差集／相对基线），但必须是「**带本窗零漏杀义务的乙**」，并附 4 条硬约束。丙否、甲否（甲降为「基线=0 时的特例」继续挂着）。

**达标式（今后 L1 一律按这一行判）**

```
退净达标 ⇔ ① 退后五名计数 ≤ 基线（基线＝起前见证的五名计数，须如实入册并报出）
          ∧ ② 本窗派生差集 D 全清（D 的认定法见下）
          ∧ ③ 端口 11311/11312/11313 的 TCP ∧ UDP ＝ 0 条
          ∧ ④ D 中若存在「不带本窗 uuid」的新增 ⇒ 不判 PASS、判 INVALID 并上报（不得 kill 之）
```

### ① 与 R419 那种「绝对零窗」仍不可比吗？——仍可比，且是**严格嵌套**

- 基线=0 时，乙的四合取项**逐字退化为甲**（①0≤0 ∧ ②差集全清 ∧ ③端口0 ∧ ④不适用）。故 **甲达标 ⇒ 乙达标**，R419 那类窗在乙口径下自动判绿，**不需要重跑、不需要加注「口径已改故不可比」**。
- 真正可比的是「**本窗 attributable 的那一半**」。甲把两件事塞进同一个数：本窗自洁 ＋ 容器恰好干净。后者不是本窗的性质，是环境的性质；把它当闸，就出现 07 件那种「本窗怎么努力都 FAIL」和（更糟的）「用别人的脏给自己遮丑」两种失真——现读四采 4→3→3→3 与基线 0/1/2/3 的单调累加就是这两条同时发作。乙把环境项**拆出来单列成「基线」字段**，本窗项**留在 ②** 一点没松。
- 事实底座：四窗 `witness.sh` sha 全等（见复现6 首段）⇒ 计数式一字未变，基线字段本身就同标可读。

### ② 「本窗派生差集 D」在起窗脚本里如何**可复核地**认定（我认可的算法）

不采信「拿 ps 差集直接当 kill 集」这种粗法（正是它把 59831 含混进来的）。我认可**双键快照 ＋ uuid 单一归属 ＋ 二者必须同集合**：

```
(a) 起前快照 S0（步0b 之后、roscore 之前）：
      ps -eo pid=,lstart=,comm=,args= | grep -E '^(roslaunch|rosmaster|rosout|gzserver|gzclient|rosbag|costmap_2d_node)$'
      → 落 "$RUN/S0_witness.tsv"；键＝(pid, lstart) 双键，**防 pid 复用**（只比 pid 会串）。
(b) 归属令牌（roscore 起后、master_ready 一确认就立刻钉，别晚读）：
      UUID=$(basename "$(readlink -f $ROS_LOG_DIR/latest)")
      [ -f "$ROS_LOG_DIR/$UUID/roslaunch-$(hostname)-$ROSMASTER_WRAPPER_PID.log" ] || { say "★uuid 自校验失败⇒INVALID"; exit 9; }
      → 落 "$RUN/OWNERSHIP.txt"（UUID ＋ wrapper pid ＋ 时刻）。
    （复现3 已证这个令牌在 R429/R436/R441/R419 四次都精确落位：文件名内嵌的正是 `$!` 那个 pid。）
(c) 退后快照 S1，同样落盘。 D ＝ { p ∈ S1 ∖ S0（双键不等）∧ p.lstart ∈ [T0, T_现在] }。
(d) 授权 kill 集 K ＝ { p ∈ D ∪ $PIDS ∪ $seg_pids ：
        p 的 args 含 "__log:=$ROS_LOG_DIR/$UUID/"  ∨  p ∈ ($PIDS ∪ $seg_pids) }。
    ⇒ **红线靠 uuid 守，不靠名字猜**：Lite3 侧或人类手动起的会话带的是它自己的 uuid，永不含本窗 UUID ⇒ 结构上进不了 K。
(e) 交叉校验（这一条才是「可复核」的来源）：D∖K ≠ ∅（差集里有来历不明者）⇒ 判 **INVALID**、一个都不许多杀，
    并在窗日志把该 pid 的 cmdline 逐字入册。K 清完仍 D≠∅ ⇒ 同样 INVALID。
(f) 判定行必须**同条命令**打：基线值／D 枚数／K 枚数／D∖K 枚数／端口数，五个数一起，缺一不判。
```
