## §8.2 吞吐探针 —— 结论：**本机就是设计稿说的 Tegra**，实测未触 0.5s 降级门槛，但 10Hz 输入侧撑不住单线程 numpy
  硬件自证：/proc/device-tree/compatible=nvidia,tegra194（Xavier，p3668 载板）、aarch64、nproc=6、5.10.120-tegra ⇒ 不存在「拿开发机折算 Tegra」的问题，本机即目标平台。
  单帧（11.7 万点：刚体变换→0.1m 栅格索引→逐列中位高度→全图 105,600 格 int8 序列化）：min 162 / **中位 224** / max 319 ms（8 次）
  分解：变换＋栅格索引 ≈117 ms（大头）、逐列 python 中位循环 ≈97 ms、向量化统计（均值版）仅 ≈3 ms、序列化 ≈6 ms ⇒ 向量化后合计 ≈127 ms
  对照在册门槛：「超 0.5s/帧→降 res 0.15 或降 fps」⇒ **224ms 未触发**；但 10Hz 的周期只有 100ms ⇒ 单线程 numpy 连向量化版(127ms)都跟不上输入侧。
  ⇒ 给立项的三条出路（都不改判据，属实现选择）：①隔帧/抽样输入（设计本就写输出 1–2Hz latched）；②C++/多线程；③按 §8.2 降 res 或降 fps。
  诚实边界：单线程 numpy 上界**不证明** C++ 实现达标，也不否证；「达标」要等实现后按 A0 RTF≥0.25 实测。P50 与均值语义不同，本探针不替实现决定统计量。

## §8.3 StaticLayer 双实例同栈 —— 结论：**能挂，但组合语义是「后加载者整图覆盖」，不是叠加**（A 档的关键发现）
  对照矩阵（同一 costmap_2d_node、同一对源图；100 区来自 map_a，−1 行来自 map_b）：
    单实例 static_a           → 100 区读回 [100,100,100,100,100]（图层生效）
    单实例 static_b           → −1 行读回 [-1,-1,-1,-1,-1]（图层生效）
    双实例 [a, b]             → 100 区读回 [0,0,0,0,0]，−1 行保留 ⇒ **前者被吃掉**
    双实例 [b, a]（换序）      → 100 区读回 [100,100,100,100,100]，−1 行变 0 ⇒ **赢家跟着顺序走**
  combination_method 取 0 与 1 都试过，未改变「后者覆盖」的结果 ⇒ 在册那句「多实例同名类型不同名可挂」只对**装载**成立，对**组合**不成立。
  ⇒ A 档（设计 §5 表 A 行）**不能默认 elevation 层与 /map 底图并存**：必须显式解决组合，否则底图会被抹掉；这条要么归 B 档（自研 Layer 插件），要么在 A 档补一个能叠合的配置验证。设计稿 §5 需要按此修订（走 v2.1 勘误，不静默改）。
  附带发现：源图**中间值 50** 在 costmap 读回 **0** ⇒ StaticLayer 的代价映射不是恒等透传，§4.3 的连续代价映射不能假设「写多少读多少」。

## §8.4 unknown=−1 与 0 的解释差异 —— 结论：**未知被尊重**（−1 → −1，不塌成自由）
