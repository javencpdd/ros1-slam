## 二、★判读前提：本会话在 user namespace 里，ACL 判据失真★

这一节必须写在读数前面，否则后面所有红都会被误读。

```
$ cat /proc/self/uid_map
         0       1000          1
```

**只映射了 1 个 uid**（namespace 内的 0 ↔ 外部 1000/jack）。uid 998 在本 namespace 内**没有映射**。三个后果，逐个实测过：

| 现象 | 实测 |
|---|---|
| ACL xattr 里的 uid | 二进制解析出 `0xffffffff`（-1），不是 998 |
| getfacl 输出 | `user:4294967295:r--` 而不是 `user:ros1-slam:r--` |
| setfacl 设置 | 报「无效的参数」（P1 探针那两行 stderr 即是） |
| fork+setuid(998) 后读文件 | 5 个抽样件全部失败 |
| sudo | `sudo.conf is owned by uid 65534` ⇒ 根本起不来 |

⇒ **判 VAR 的红之前，先 `cat /proc/self/uid_map`。**

这条已经写进作业单第四节。尤其重要的一点：作业单里那句 `sudo -u ros1-slam test -r note/04` 在本会话恒 FAIL——**那是 sudo 坏了，不是权限坏了**。机侧在真机上测出 READ-OK 是对的，两边都对，差别在 namespace。绝不可拿本会话的 FAIL 让机侧返工。

## 四、★5 件「违规」逐件定性：没有一件是权限债★

**第 1—3 件**：三个 `roslog/latest`
```
note/进度/v7/S1/SCAN集成/证据/log/raw/r93_batch2_live_20261010_152710/roslog/latest
note/进度/v7/S1/SCAN集成/证据/log/raw/r93_batch2_live_20261010_153503/roslog/latest
note/进度/v7/S1/SCAN集成/证据/log/raw/r93_batch2_live_20261010_153849/roslog/latest
```
异常标注 `FileNotFoundError`。实测均为**悬空符号链接**，目标形如：
```
/home/ros1-slam/note/进度/SCAN集成/证据/log/raw/r93_batch2_live_20261010_152710/roslog/03f53412-...
```
指向**开发机仓根的绝对路径** ⇒ 搬到本机后失效。

顺带解出一个小疑问：账号为什么叫 `ros1-slam`？因为开发机上的用户就是它，仓在它的 home 下。这个链接正好把那段历史留在盘上了。

**第 4 件**：`ws/src/CMakeLists.txt`，同样 `FileNotFoundError`。catkin 工作区的标准符号链接，目标 `/opt/ros/noetic/share/catkin/cmake/toplevel.cmake`，而**本机 `/opt/ros/noetic` 根本不存在**（ROS 装在容器里）⇒ 悬空。

**第 5 件**：`note/进度/v7/S3/note/R561建议稿原件_3D仿真环境搭建解决方案.md`——**唯一值得细看的一件**。

```
mode = 0640   （other 位无 r）
ACL  = user:4294967295:r--   ← 条目在
mask = r--                   ← 未掐空
```

按 POSIX 手算：查询者 uid 998 ≠ owner(0)；other 位无 r；退到具名条目——`ros1-slam` 给 r，且 mask 含 r ⇒ **可读**。

VAR 判它不可读，是因为 getfacl 把 uid 998 打印成 `4294967295`，而件内判据写的是 `if who in nu`（`who`＝字符串 `'ros1-slam'`）⇒ 查不到 ⇒ `return False`。

**这是 namespace 的 uid 未映射导致的判据失真，不是文件权限问题。**

⇒ **结论：本仓权限面实质已通过，全仓无真正私锁件。**

还有一个副产品观察：全仓「other 位无 r、必须靠 ACL 才能读」的件**只有这一件**（其余 12319 件靠 other 位即可读）。说明 ACL 面开得比实际需要宽——宽开无害，且 `d:` 默认 ACL 保证新建件继承，保留。

### 坑：负查询无缓存，慢 100 倍

```python
def readable(path, who, cache={}):
    st = os.stat(path)
    if who not in cache:
        try:
            pu = pwd.getpwnam(who)
            cache[who] = (...)      # ← 写在 try 的末行
        except KeyError:
            return None             # ← 异常路径不写缓存
```

`getpwnam` 抛 KeyError 时**缓存不写入** ⇒ 账号不存在时，每个文件都重试一次失败的查询。

实测：`USERS` 含本机不存在的 `ysc` 时，note 普查 **>115 秒仍跑不完**（被 timeout 杀掉，rc=124）；只留 `ros1-slam` 后 **1.102 秒**。

**慢 100 倍以上。** 而且症状极具迷惑性——看起来是「普查太慢跑不完」，实质是「缓存写在了异常路径之后」。

（顺带：`ysc` 不存在时 `readable` 返回 `None`，而判据写的是 `if readable(...) is False` ⇒ `None is False` 为假 ⇒ 不产生违规。所以它只拖慢速度，不制造假红。）

### 坑：悬空符号链接被算作权限违规

```python
except Exception as e:
    unreadable.setdefault(p, []).append('%s(计算异常:%s)' % (who, type(e).__name__))
```

普查循环用 `except Exception` 兜底，把 `FileNotFoundError` 一律记成「不可读」并点名。悬空链接和权限是两码事，混在一起会让「证据可达」这条判据的读数失真——本批 5 件里 4 件是这类。
