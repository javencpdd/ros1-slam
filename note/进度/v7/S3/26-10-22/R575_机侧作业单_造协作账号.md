- 本机此前没有这个账号 ⇒ `pwd.getpwnam('ros1-slam')` 抛 KeyError ⇒ 判读函数返回 `None` ⇒ 探针 P1b 必不过 ⇒ **VAR 恒 rc=9，是「没判」不是「通过」也不是「件坏了」**。

## 二、账号形制（真人明令，逐字）

```
系统账号、nologin

sudo useradd -r -M -s /usr/sbin/nologin ros1-slam
```

- `-r`＝系统账号（UID 落在 SYS_UID_MIN—SYS_UID_MAX，本机实测该区间在用 100、101、102… 故会分到 9xx 段）
- `-M`＝不建家目录（纯 ACL 判据用，不需要登录，也就不需要 home）
- `-s /usr/sbin/nologin`＝禁止登录（本单只借它的 uid 判 ACL，不借它执行任何东西）
- **可逆**：撤销＝`sudo userdel ros1-slam`（因 `-M` 无家目录，`userdel` 不需 `-r`；建议仍写 `userdel -r` 以防家目录被别处建出来）

## 三、执行（机侧照抄，逐条）

**步骤 1｜造账号**
```
sudo useradd -r -M -s /usr/sbin/nologin ros1-slam
```

**步骤 2｜核验账号形制（三条都要看）**
```
id ros1-slam
getent passwd ros1-slam
```
期望：`id` 输出 `uid=9xx(ros1-slam) gid=9xx(ros1-slam) 组=9xx(ros1-slam)`（无 `groups=` 其他组，正常）；`getent` 末段为 `/usr/sbin/nologin`。

**步骤 3｜核验 nologin 真的挡住登录**
```
sudo -u ros1-slam -s /bin/sh -c 'echo 不该出现' 2>&1 | head -2
```
期望：被 nologin 拒绝（打印 `This account is currently not available.` 或等价），**不打印「不该出现」**。
> 注意：这条只验 shell 侧。`sudo -u` 仍可代它执行，这是 sudo 的语义，不是账号漏。

**步骤 4｜给仓内证据面开协作读（ACL，不做 chown）**
> ★为什么用 ACL 不用 chown★＝chown 会把属主从 root 换成 ros1-slam，后续 root 写的仓位权限漂移（坑17 同源）。ACL 只加具名条目，属主不动。

```
cd /home/jack/ysc-code/ros1-slam
sudo setfacl -R -m u:ros1-slam:rX -m d:u:ros1-slam:rX note/
sudo setfacl -R -m u:ros1-slam:rX ws/src/ scripts/
```
- `rX`（大写 X）＝目录始终给 x（可进入），普通文件只在「本来就有任一位 x」时才给 x ⇒ **不会把脚本以外的东西变成可执行**。
- `d:` 前缀＝默认 ACL，让 `note/` 下**新落盘**的件也自动继承（否则下一批新写的证据件又回到不可读，VAR 每批都红一次）。
- 面选择＝VAR 的普查面（件内缺省三根 `note`、`ws/src`、`scripts`），与 `claim_face.txt` 一致。

**步骤 5｜核验 ACL 生效（不是看命令回显，要看 `#effective`）**
```
getfacl -p note/ 2>/dev/null | grep -E 'user:ros1-slam|mask|effective' | head -6
sudo -u ros1-slam test -r note/04_配置改动diff.md && echo "READ-OK" || echo "READ-FAIL"
```
期望：`getfacl` 里能看到 `user:ros1-slam:r-x` 且 **mask 不小于 r-x**（若 `mask::---` 则条目被掐空＝坑17 的形态，须 `sudo setfacl -m m::r-x` 补 mask）；`test -r` 打印 `READ-OK`。
> ★只信 `user:ros1-slam:` 那一行出现＝未证★：条目存在 ≠ 生效，必须看 mask 与 `#effective:`。
