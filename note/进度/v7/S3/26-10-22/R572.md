## 四、真根因：`Layer::enabled_` 恒 false，框架按它逐层筛（坑88）

### 定位链（五步，前四步都是否定）

1. **探针不打印**：把诊断探针插进 `updateBounds`／`updateCosts` 首位，编进 `.so`，跑真景 —— ★一行都不打印★。⇒ 不是「进去了走早退」，是**两个函数根本没被调用**。
2. **`objdump` 看框架**：`LayeredCostmap::updateMap` @`0x4b9c0` 首句 `cmpb $0x0,0x11(%rdi); je <跳过>` ⇒ 框架按某字节成员**逐层筛**。
3. **落实偏移**：`Layer::Layer()` @`0x4b320` 是 `xor %eax,%eax; mov %ax,0x10(%rdi)` —— 一次写 2 字节，**同时**覆盖 `current_(0x10)` 与 `enabled_(0x11)`。
4. **`Layer::initialize()` @`0x4b380` 全文只有三件事**：赋 `layered_costmap_`、`tf_`、`name_`，末尾虚调 `onInitialize()`。★一次不读 `"enabled"` 参数、一次不写 `0x11`★；`strings libcostmap_2d.so | grep -c enabled` = **0**。
5. **对照件**：`sob_layer` 与 `spatio_temporal_voxel_layer` 各自 `.so` 里都有 **2 处** `enabled`（自己读参数、自己置位）；★本层 0 处★。

### 结论与修法

★任何不自带启用的层都被框架静默排除出更新回路★：`updateBounds`／`updateCosts` 一次不进，**无任何 WARN**。

修法是两件事、缺一不可：

- **订阅门**（批224 上一轮已修）：本层自有 `enabled_param_`（`pnh.param("enabled", …)`）管订阅。缺 `enabled` ⇒ 不订阅 ⇒ 连 `Received` 都没有。
- **回路门**（本批修，决定性）：★`onInitialize()` 末尾必须显式 `enabled_ = true`★。

★只做订阅门的症状最阴★＝**收得到、用不上**（`Received` 双侧正常增长、代价零写入）——本批就死在这里，绕了一整圈才回到框架代码。

## 五、负向控制带出的另外两枚真缺陷

### 5.1 节流写法把告警关掉（坑89）

`refuse_write_` 分支的 `ROS_ERROR` 原形 `if (refuse_log_count_++ % 100 == 0)`。该计数器**只在拒写分支自增**，而拒写分支恰恰每次都早退 ⇒ 第一次 `++` 后为 1、`1 % 100 != 0` ⇒ **一行都不打**。

实测：`use_maximum=false` 窗里在位行 `refuse_write=1` 打印 **2 次**，`updateCosts` 里那条解释「为什么拒写」的 `ROS_ERROR` 打印 **0 次**。

修＝「前 3 次逐次打、之后每 100 次打一次」：`++refuse_log_count_; if (refuse_log_count_ <= 3 || refuse_log_count_ % 100 == 0)`。修后同一窗留痕。

### 5.2 「本窗写入」原来是 `ROS_DEBUG`，默认不可见

`ROS_DEBUG` 默认不出 ⇒「到底写没写」在日志上**无从判定**，这也是绕圈的另一半原因。修＝提为 `ROS_INFO` 常设计数，并加累计口径：`本窗写入 N 格（累计 W 窗 / C 格；use_maximum=…、res=…）`。

顺带入册一枚头文件成员：`write_windows_`／`write_cells_` 与 `callback_count_` 一起构成**本层活体四联**＝收包数／写窗数／写格数／拒写次数。
