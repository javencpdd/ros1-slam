## 三、③ VAR 走甲案

### 裁定
勾**甲**（造 `ros1-slam` 账号），**乙否**（不改探针账号解析）。

真人理由：判据件一字不动、两机同口径——「VAR 判协作账号可读」这句话在 Lite3 与 x86 从此是同一个判据，名＝口径跨机成立；乙要在判据面里开「按机分义」的分支，口径分叉的代价远大于一次性造个系统账号。

### 账号形制（真人明令）
```
系统账号、nologin
sudo useradd -r -M -s /usr/sbin/nologin ros1-slam
```
可逆（`userdel` 即撤）。

### 施工侧为什么只出作业单、不执行
实测两条：
```
$ id ros1-slam
id: "ros1-slam": 无此用户
$ sudo -n true
sudo: /etc/sudo.conf is owned by uid 65534, should be 0
```
⇒ 本机 **sudo 通道本身不可用**（不是缺权限，是 sudo 配置件属主异常）。按真人「sudo 这一步施工侧无权、归机侧」，落成机侧作业单。

### 作业单
`note/进度/v7/S3/26-10-22/R575_机侧作业单_造协作账号.md`

六步：造账号 ⇒ `id`／`getent` 双核 ⇒ nologin 实测 ⇒ **ACL 而非 chown** 开 `rX`（含 `d:` 默认 ACL）⇒ 核验必须看 `#effective`／mask 而不只看条目行 ⇒ 撤销三步。

两条要点值得在这里重述：
- **为什么用 ACL 不用 chown**：chown 会把属主从 root 换成 ros1-slam，后续 root 写的仓位权限漂移（坑17 同源）。ACL 只加具名条目，属主不动。
- **为什么必须有 `d:` 默认 ACL**：否则 `note/` 下**新落盘**的证据件不继承，下一批 VAR 又红一次——这不是「修好了」，是「这批发完就复发」。
