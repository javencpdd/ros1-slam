## 二、替代式的判据设计（不依赖任何原文行）

两侧都**现取**，谁都不写死：

- **稿侧**＝每个补丁稿自身**首个一级标题**里的版本章（`^# ` 行里的 `v7\.N`）。★不取正文引用★——正文里满是「与 v7.1 的关系」这类句子，取正文会把别人的版本章算成自己的。
- **载体侧**＝中心计划书 `v7.md` 正文里出现的全部 `v7\.N`。

然后做**双向差集**：

| 差集 | 含义 |
|---|---|
| 稿侧有、正文无 | 该稿的改读**没有落在载体上** |
| 正文有、稿侧无 | 正文**引了不成立的稿** |

★本件不判「谁该落册」★——落册与否归真人裁；它只判「有稿必有形迹、有形迹必有稿」。

## 五、★本批自曝三枚（都是我自己的错）★

### 5.1 文件名与内容不符：`.sh` 里装的是裸 python

第一版把 python 源码直接写成 `v_patch_landing.sh`（无 shebang、无 heredoc），`bash` 一跑当场 `SyntaxError`；更糟的是沙箱把这次执行报成 rc=137，我差点当成「环境被杀了」。

⇒ 本仓的形是「`.sh` 壳 ＋ `python3 - "$ARGS" <<'PYEOF'` 内嵌」，**照抄既有件**（`v_citation_check.sh` 就是这么写的）。

### 5.2 反控把我自己的短路读成了缺陷

反控写成 `declared - (in_body | {fake})`。而状态正常时 `declared ⊂ in_body`，所以这个差集**本来就恒空**——塞不塞假章都是空，于是反控**永远报「失败」**，本件永远绿不了。

★根因＝**反控要反的是触发路径，不是外层表达式的值**★。正形＝把假章塞进正文集合后，去算**另一支**（正文有、稿侧无）：假章只进正文、不进稿侧 ⇒ 它必然落进那一支 ⇒ 该支必须翻红。

### 5.3 SYN 件的「双条件跨行」漏检（★本仓门禁的一枚真缺口★）

`v_sh_py_syntax.sh` 判「这段 heredoc 是 python」的条件是「**同一行**里既有 `python` 调用、又有 heredoc 重定向」。而本件的分派形是：

```
if [ ... ]; then python3 - --selftest; else ...; python3 - "$ROOT"; fi <<'PYEOF'
```

★python 调用在 `then`／`else` 行，重定向在最末尾的 `fi` 行 ⇒ 两条件跨行 ⇒ SYN 判「该件无内嵌 python 段」并**印绿**★。也就是说：这段 python 里写错一行，SYN 抓不到。

处置＝★不改 SYN 件本体（门禁串成员，改动须真人明令）★，改**本件的书写形**：把分派压成一行、`python3 - "$SEED" <<'PYEOF'` 紧跟其后。改后 SYN 单件读数从「段数 0」变「段数 1（L24-L187）」。

**负向控制（真跑）**：往里植一行 `this is not python at all (` ⇒ SYN 当场 `FAIL rc=1`（段内行 49: invalid syntax）；还原即 `rc=0`。⇒ 这一支**真受检、非默认绿**。

★这条是本批最有价值的副产品★：它说明「判据看得见、缺陷不在判据里」这族（坑88）**也存在于本仓自己的门禁件里**——SYN 一直在给一批「其实没被检查」的件印绿。
