# 跨 Agent 与跨主机任务交接

> 最新更新时间：2026-11-06 22:42:50 CST。工程标准真源：`note/架构/工程标准.md`。当前命令与格式见[协作工具](../../scripts/agent/README.md)，共同约束见[跨工具契约](../09_跨工具协作契约.md)。旧教程中的Git提交整套.ai、远端tar覆盖和后台watcher方式退出当前流程，原文可由Git历史追溯。

## 1. 工具与数据的分工

| 位置 | 职责与分发 |
| --- | --- |
| `scripts/agent/bridge.py`及其模块 | Git版本化命令本体；每台机器取得相应提交后可用 |
| `.ai/bridge.py`、`AGENTS.md` | bootstrap生成的本机薄入口和契约指针，继续忽略、不提交 |
| `.ai/state.json`、任务卡、HANDOFF/TASKS/JOURNAL | 本机协作状态，由bridge生成；保留本机其他任务，不整库合并或覆盖 |
| 本机host身份 | UUID与明确平台，bootstrap建立；不按CPU猜机器人，不跨机复制身份文件 |
| 单任务交接包 | 选定任务、scope、摘要、证据索引和绑定信息；只在明确交接时分发 |
| Git代码/本机资产 | 代码按提交独立同步；地图、local.env、网络、SDK和build/devel由各机管理 |

Agent的聊天记忆不作为共享记录；工具从同一项目契约和任务游标接续。原卡/摘要是自由文本，导出前检查敏感内容，工具不自动脱敏。跨主机交接包不携带程序、凭据、整套.ai或构建缓存，也不执行包内文本。

## 2. 同一工作区切换工具

先读取项目根AGENTS指针、note当前入口和任务卡。已有本机状态时直接使用resume，不重新init：

```bash
python3 .ai/bridge.py resume --as codex
python3 .ai/bridge.py check
```

原工具记录已完成/未完成、代码提交、证据、已试失败方案及禁止改动范围，再handoff给接收工具。示例中的任务ID应换成当前实际任务：

```bash
TASK_ID=T-YYYYMMDD-NN
AI_BRIDGE_AGENT=codex python3 .ai/bridge.py handoff "$TASK_ID" \
  --to qoder --summary '已完成内容、剩余步骤、证据位置与禁止改动范围'
python3 .ai/bridge.py resume --as qoder
python3 .ai/bridge.py claim "$TASK_ID" --as qoder
python3 .ai/bridge.py check
```

接收工具必须按resume打印的顺序读卡、核Git状态与实际证据后接续。没有当前任务时只按新授权建卡，不从旧取消项或历史“下一步”选任务。

## 3. 首次进入另一台机器

先取得工具所在代码提交，检查该机Git状态和本机配置。仅git pull不会带来被忽略的.ai、AGENTS或地图。新机从Git中的canonical入口执行bootstrap，按[工具说明](../../scripts/agent/README.md)明确平台和Agent身份；它保留已有状态，生成薄入口/指针和本机host身份。

平台字段用于核对交接目标，不启用ROS、训练或设备控制。Lite3/M20仅真机运行依赖，x86承担仿真与训练开发；M20真实适配仍未实现。不要把一台机器的host身份或ROS网络配置复制到另一台。

协作工具安装与ROS运行环境分开；本次不修env.sh旧devel入口。真机运行前仍须按目标构建说明选择目标专属产物，核本机地图、配置、网络与现场条件。

## 4. 跨主机的完整往返

| 顺序 | 操作者 | 动作与结果 |
| --- | --- | --- |
| 1 | 目标机 | bootstrap/host输出本机票据，带UUID、平台和代码提交；将票据交回源端 |
| 2 | 源机 | 核当前任务、scope与已提交代码；所选范围不能夹带未提交施工 |
| 3 | 源机 | export所选任务到指定接收主机；先保存私有outbox并提交源端transferred状态，再发布包 |
| 4 | 操作者 | 使用已授权、可信的文件通道传递JSON包；工具不自动SSH、推Git或连接设备 |
| 5 | 目标机 | inspect校验包结构/摘要并展示接收身份、提交和有效期；本机条件在import核对 |
| 6 | 目标机 | import再次校验并落成本机任务，状态review；有其他当前任务时拒绝覆盖，源ID撞号时保留来源映射 |
| 7 | 目标Agent | resume/check、读卡和核本机环境/授权后claim；不继承源路径、地图或运动许可 |
| 8 | 接续 | 按阶段验证/独立复核/四要素/本地commit执行，普通工具内note/handoff/done继续兼容 |
| 9 | 需要返回 | 原接收机对同一任务按受支持的直接peer回流流程导出，原机核host/链与新提交后接收 |

主机的epoch只表示该机状态版本，不是可跨机比较的全局时钟。任务通过task UUID、交接包ID和hop保留来源；不通过覆盖state.json让两台机器的epoch看起来相同。

源端transferred表示已移交，不表示任务完成；正常claim/note/handoff/done不能在源继续写该任务。该保护只约束当前canonical工具，不能阻止任意手工编辑或旧工具绕行，不构成全局分布式锁。

## 5. 重复、过期、冲突与中断

| 情形 | 处理 |
| --- | --- |
| 同一包再次导入 | 核同一不可变core后返回已有回执，不新建任务、不bump、不复活已完成任务 |
| 同包ID但core变化 | 拒绝，不把SHA当来源认证或用新内容覆盖旧任务 |
| 错主机/平台/提交、包损坏或未支持格式 | 明确拒绝，目标不自动fetch/checkout、不改本机任务或配置 |
| 同ID已有其他任务 | 不覆盖；按工具分配本地ID并记录源映射 |
| 目标已有当前任务 | 先按原规则处理该任务；工具不提供盲覆盖 |
| 公开包写出失败 | 源继续保持移交约束，按私有outbox重发，不回滚成双端可写 |
| 尚未导入且租约过期 | 源按renew续期同一core/目标/hop，仍保持transferred；目标接有效续期包 |
| 已导入后收到旧包/续期包 | 只读返回原接收结果，不重新激活 |
| 未发布事务中断留下pending | 正常写命令拒绝继续；按recover恢复受限本机事务，并重新check，不能手改state或回滚已发布移交 |
| 多跳绕回/任意合并 | 初版不自动解除旧fence，只支持明确的直接peer回流；不以FORCE跳过链校验 |

普通异常回滚、pending恢复和已发布状态是不同阶段；具体可恢复出口与限制按工具实测说明。包和票据须经操作者信任的通道取得，SHA仅校验完整性，不是数字签名。

## 6. 证据、完成与真实设备

交接摘要应足够定位：目标/非目标、剩余最小步骤、scope、代码提交、定向测试、首失败、目标环境未验项、证据位置及可获取性。证据索引不等于证据已随包传递，接收端须核实际可取性。

实现、自动化、目标环境、证据四要素分别记账，修改文档带最新更新时间；只暂存本任务文件并本地git commit，push由用户决定。目标未验证不得因源端测试或移交成功改为PASS。

真机先做已授权的只读/环境检查、目标构建和安全链验证；实际运动、现场外参/actual和正式签署按各自已有授权处理。导入review本身不会新增动作许可。旧算法/地图/真机取消排程不因换机恢复。

旧root install.sh或ssh+tar整目录方式不再用于当前任务接续；不得git add被忽略的.ai、AGENTS或凭据来绕过分发工具。当前完整命令示例与输入限额只维护在[工具README](../../scripts/agent/README.md)，本件维护流程，不复制第二套CLI规范。
