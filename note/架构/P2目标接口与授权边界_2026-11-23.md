## 2. 确认的缺陷

### D1（功能性，已修）：graph + FAR 目标路由断裂

- **现象**：BT 的规划请求发到 `/v8/3d/global/goal`，FAR 只订阅 `/v8/global/goal`，两者之间**没有任何桥或 remap** ⇒ 目标永远到不了 FAR。
- **根因（两层）**：
  1. `render.py:135-140` 对 `kind: include` 的实例**直接 `continue`**，不生成 remap；而 FAR 正是 include 型（`far_stack.launch`）。所以边 `bt.planner_goal → global.goal` 只被"记进图里"，不产生接线。
  2. `graph.check` / `cli.py plan` 只校验**端口存在与消息类型**，不校验 topic 是否相等 ⇒ 返回 `ok:true`，缺陷静默。
- **修复**：把两处 FAR 图的 `global.goal_topic` 由 `/v8/global/goal` 改为 `/v8/3d/global/goal`（与 `bt.planner_goal_topic` 同名），单行配置，不动代码。
- **验证**：`cli.py plan` 渲染后 FAR 的 `goal_topic` arg 与 BT 的 `planner_goal_topic` param 一致；新增测试守住该不变量（回退即 2 处失败）。

### D2（授权边界，已定位，未修）：传统 launch 里 gate 的输出无人消费

- **现象**：传统链启动 `goal_gate.py` 并写 `/v8/3d/global/goal`，但该话题在传统链**没有任何订阅者**（规划器读 `/v8/global/goal`，path_goal 读 `Path`）。真正驱动运动的是 `path_goal` 直接把路径末点写 `/v8/local/goal`——**执行目标从未经过 gate**。
- **性质**：不是崩溃类缺陷（任务能跑、取消链正常），是**"所有权声明与实现不符"**：launch 注释称 gate 是 `/v8/3d/global/goal` 的唯一预期写者，但这条通路不参与执行。
- **为什么不修**：两条修法都超出"最小安全修改"——
  1. 删掉 gate：改变传统链的进程集与对外表述，且无运行时测试覆盖；
  2. 让执行目标过 gate：等于改契约（谁写 `/v8/local/goal` 需重设计），必须带运行时验证。
- **影响**：不影响当前受支持路径的功能正确性；影响的是"谁授权运动"的判断。已列入 P2 后续研究项。

### D3（澄清，非缺陷）：gate 丢弃不会让 BT 卡超时

`FollowPath` 是 `SyncActionNode`，发完即返回 SUCCESS（`bt_console.cpp:472-533`），**不等待 gate 回执**；BT 的等待发生在 `WaitArrival`（位姿/arrival 信号）与取消回执（`cancel_ack`，由 local 提供）。所以"gate 丢弃导致不必要超时"的担心在当前实现里不成立。

## 6. 四问四答

1. **P2 是否存在真实缺陷？** 有。一个功能性（graph+FAR 目标无人消费，D1），一个授权边界（传统链 gate 死写、执行不经 gate，D2）。
2. **是否已修复？** D1 已修并加回归测试；D2 已定位但未修，修法需重设计契约或删进程，超出最小修改范围。
3. **两套启动方式的差异是否合理且已验证？** 差异是设计使然（传统＝BT 请求路径 + `path_goal` 执行；graph＝BT 全权，FAR 版再交 `path_goal` 执行），静态接线已逐条核对并修掉断裂；**运行期行为未实测**。
4. **是否仍有影响当前受支持路径的未解决问题？** 功能上无（四条路径目标均可到达后端）；但传统链的"运动授权"表述仍与实际不符（D2），属解释性风险，列入 P2 后续。

### 7.1 D1 只修了 1/3：path 与 status 仍断

首轮只对齐了 goal。复核渲染产物发现 FAR 图里 BT 的两个**返回**订阅仍是旧话题：

| 方向 | FAR 实际输出 | BT 订阅（修前） | 结果 |
| --- | --- | --- | --- |
| goal | 订阅 `/v8/3d/global/goal` | 发 `/v8/3d/global/goal` | ✅ 已对齐 |
| path | 发 `/global_path` | 读 `/v8/3d/global/path` | ❌ 断 |
| status | 发 `/global_path/status` | 读 `/v8/3d/global/status` | ❌ 断 |

**为什么 remap 救不了**：`render.py` 给普通节点生成的 `<remap from=…>` 用的是 **manifest 默认端口话题**，而 BT 的这些端口在 graph 里被参数覆盖成了别的名字 ⇒ remap 的 `from` 与节点实际订阅名不匹配，等于空转。渲染产物里能直接看到：BT 节点上只有 `/global_path → /global_path` 这种**恒等 remap**，而它的 `path_topic` 参数是 `/v8/3d/global/path`。

修复：两份 FAR 图（lite3 与 gazebo 夹具）把 `bt.path_topic` 改为 `/global_path`、`bt.path_status_topic` 改为 `/global_path/status`，与 FAR 实际输出一致。support 图未动（两侧本来就是同名 `/v8/3d/global/path`）。

### 7.4 D2 的最终定性：不是"演示遗留"，但也不是"授权边界"

| 判断依据 | 结论 |
| --- | --- |
| gate 输出 `/v8/3d/global/goal` 有无消费者 | **四条启动方式下都没有**（3D 链执行目标由 path_goal 或 bt.out_goal 直写 local） |
| 是否有别的链依赖该节点 | **有**：`real_preflight.py` 的 `REQUIRED_NODES` 含 `v8_goal_gate`，真机 SCAN 链把它当节点契约 |
| lease 有无其他消费者 | 有：`navigation_executor.py` 订阅 `/v8/bt/lease` |

⇒ 两条候选处置都不成立：**删**会破 preflight 契约（那是验收门，不能顺手改）；**改造成授权口**需要新设计（把执行目标纳入 gate 必经路径），属契约变更且必须运行期验证。

**本轮采取**：保留节点，**改写 `bt_console.launch` 的边界说明**（删掉"gate 是唯一预期写者"的误导表述，写明四条边界：callerid 是软过滤 / BT 是目标所有者 / local 有时效与取消检查 / mux 做速度仲裁，四者不可互代），并用测试把现状钉住——将来谁真把 gate 接进执行链，测试会失败并强制同步文档。

### 7.5 速度链更正（此前把「转发」当成了「仲裁」）

四组合的速度执行链**不是同一条**，不能一律写「过 mux」：

| 组合 | 速度链 | 单写者 | 转发 | 仲裁 | 限速 | hold / stop |
| --- | --- | --- | --- | --- | --- | --- |
| 传统 + support | `local → /cmd_vel_raw → m2_cmd_relay → /cmd_vel → lite3_planar_drive` | `/cmd_vel` 唯一写者＝relay | **是**（纯 Twist 转发） | **无** | **无** | **无** |
| 传统 + FAR | 同上（FAR 只换全局，不换速度段） | 同上 | 同上 | **无** | **无** | **无** |
| graph + support | `local.cmd_twist → mux.cmd → /cmd_vel` | `/cmd_vel` 唯一写者＝`safe_cmd_vel_mux` | 无 | **有**（源优先级 / 超时淘汰 / 无源零速 / 恒 20 Hz） | **有**（`speed_cap`，过期退 blind_cap） | **有**（`/lite3/supervisor/hold` 直出零速） |
| graph + FAR | 同上 | 同上 | 无 | **有** | **有** | **有** |

依据：`m2_cmd_relay.py` 头注释自述「M6 safe_cmd_vel_mux **不在仿真闭环内**，此 relay 仅 sim 域（master 11313）」，实现是 `Pub(dst) ← Sub(src)` 的转发器；`safe_cmd_vel_mux.py` 头注释列明四设计（优先级表/超时淘汰/无源零速/20 Hz）与 v4 增补（hold、唯一写者）。

⇒ 传统仿真链的边界是**隔离仿真域 + 单写者转发**，不是仲裁；把它写成「安全仲裁」是错的，本轮已改。

**未验证事实**：BT 的 Stop 节点发 `/lite3/teleop/app_cmd_vel`，**仓内无任何订阅者**；真机侧 teleop 桥是否订阅在仓内不可证（外部件），故本文不断言「stop 生效」。
