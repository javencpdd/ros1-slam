# TF 生产链与 GT 隔离（2026-11-27）

## 现状：生产链确实间接消费 GT（可执行判据）
```
$ scripts/verify/tf_chain_audit.py
CHAIN rslidar <- base_link <- odom <- map
PROBLEM {"kind": "production_uses_gt", "chain": ["base_link", "odom", "map"], "gt_frames": ["odom"]}
VERDICT FAIL
```
`odom→base_link` 由 `lite3_planar_drive` 用 **Gazebo WorldPose**（真值）发布，
而 FAR `on_cloud` 用 `map→rslidar` 变换点云 ⇒ 地形与障碍感知走的位姿里有 GT 成分。
`/v8/local/pose` 来自 LIO **不能**证明整条生产链已隔离。

## 已做的准备（不改默认行为）
`lite3_planar.urdf.xacro` 里插件帧名参数化：
```xml
<xacro:arg name="gt_odom_frame" default="odom"/>
<xacro:arg name="gt_base_frame" default="base_link"/>
<odometryFrame>$(arg gt_odom_frame)</odometryFrame>
<robotBaseFrame>$(arg gt_base_frame)</robotBaseFrame>
```
默认展开仍是 `odom` / `base_link`（已用 xacro 实测核对），既有场景行为不变。

## 隔离方案（需裁决后接线）
M2 验收场景改用：
1. 生成时传 `gt_odom_frame:=gt_odom gt_base_frame:=gt_base`
   ⇒ GT 落进独立评价域：`gt_odom→gt_base`（仅供评价与 3D 显示）。
2. 生产链补 `body→base_link` 恒等边（`body` 是 LIO 的机体帧，`camera_init→body` 已存在）
   ⇒ `map→camera_init→body→base_link→rslidar` 全程估计量，URDF 只管传感器外参。
3. 删除 `map→odom` 恒等边（它是当前 GT 混入的入口）。
4. `/sim/odom_gt` 话题保留（评价用），但**不再进 TF 生产链**。

单父不变量：`base_link` 从此只有 `body` 一个父；`gt_base` 只有 `gt_odom` 一个父。

## 必须跑的五组负控（判定用 tf_chain_audit + 导航探针）
| # | 负控 | 期望 |
|---|---|---|
| 1 | 关掉 GT TF（不发布 gt_odom→gt_base） | 生产 TF 与点云转换仍工作，`map→rslidar` 可达 |
| 2 | 关掉 `/sim/odom_gt` 话题 | 仅评价数据缺失；生产链与规划不受影响 |
| 3 | EST 失效（loc 停发 / localization_ok=false），GT 正常 | 运动许可必须失效，**不得**由 GT 接管 |
| 4 | EST 恢复 | 不自动续跑旧任务，需新任务授权 |
| 5 | 人为制造双父 / 双写 / 超龄边 | tf_chain_audit 判 FAIL（double_parent / stale） |

## 未做与风险
- 改帧名会影响任何写死 `base_link`/`odom` 的消费者（RViz 布局、部分脚本），需逐处核。
- `tf_chain_audit` 的 GT 帧名单目前是常量 `{'odom'}`，改帧名后要同步，否则会假 PASS。
