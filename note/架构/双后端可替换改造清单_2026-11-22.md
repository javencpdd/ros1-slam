## 0. 目标与非目标

### 目标（验收定义）
1. 全局后端可在**配置层**二选一：`support`（现有 `support_planner`）或 `far`（FAR Planner 适配）。
2. BT 仍是**同一棵** `lite3_bt`，树文件不因后端变化。
3. 安全链仍是**同一条**：`/cmd_vel_raw → safe_cmd_vel_mux → /cmd_vel`，`/cmd_vel` 唯一写者不变。
4. 局部规划仍是 `local_native`（A 链），不因全局后端变化。
5. B 链（move_base/TEB）**降级为候选**，不删除，保留 revert 路径。

### 非目标（本清单不做）
- 不改 BT 树结构、不改 `gait_guard`、不改安全 mux 源表。
- 不删除 B 链文件、不改其配置。
- 不做真机 L2 现场验收（属真人）。
- 不引入 TARE / go2w 进主线。

## 2. 设计约定（统一抽象）

1. **全局后端统一契约**（两种后端都必须满足）：
   - 输入：`start`/`goal` = `geometry_msgs/PoseStamped`；`far` 额外需要 `cloud` = `sensor_msgs/PointCloud2`、`pose` = `PoseStamped`。
   - 输出：`path` = `nav_msgs/Path`（**3D pose**，末点为局部目标）、`status` = `std_msgs/String`。
2. **只允许写 `/cmd_vel_raw` 或其上游**，不得新增 `/cmd_vel` 写者。
3. **BT 不感知后端**：树里只认 `/v8/global/path`、`/global_path/status`、`/v8/local/goal`。
4. **FAR 不 fork 进仓**：以独立节点运行，加一层适配节点桥接（License 与上游维护风险最小）。
5. **双 graph 而非改 app_runner**：先用两份 graph + app 选择，避免动框架解析器。

### 7.2 三条会改动设计的发现

**(A) 输入契约与自研完全不同 —— 不是「点云进、路径出」，而是「地形语义云进、航点出」。**

| FAR 话题 | 类型 | 说明 |
|---|---|---|
| `/odom_world` | `nav_msgs/Odometry` | 位姿；未初始化前所有回调直接 return（`is_odom_init_`） |
| `/terrain_cloud` | `PointCloud2` | **地形语义云**，见下 |
| `/terrain_local_cloud` | `PointCloud2` | 局部地形云（本项目可 remap 成同一份） |
| `/scan_cloud` | `PointCloud2` | **`is_static_env=True` 时完全不用**（`ScanCallBack` 首行即 return）⇒ 本项目静态场景可不提供 |
| `/way_point` | `PointStamped` | 输出航点 |
| `/far_reach_goal_status` | `Bool` | 到位标志，可映射 status |

**(B) `terrain_cloud` 的 `intensity` 就是「离地高」，判据阈值 0.2 m。**

`utility.cpp` 的 `ExtractFreeAndObsCloud()` 逐点判 `p.intensity < FARUtil::kFreeZ`：小于 ⇒ 归 free 云，否则 ⇒ 归 obs 云；`kFreeZ` 由 `Util/terrain_free_Z: 0.2` 给。

> **这条是意外的好消息**：本项目高程层 `elevation_gridmap_publisher.py` 的 `h` 语义正是「相对局部地面离地高、米、正上、地面 h≡0」，与 FAR 的 intensity 语义**同构**。⇒ N1 只需把高程层每格打成一个点、把 `h` 写进 `intensity`（free 格写 0、occupied 格写 h 或饱和值），**不需要另建一套地形处理**。

**(C) 多层必须显式开启，否则 goal 的 z 会被改写。**

`graph_planner.cpp:349`：`if (!FARUtil::IsMultiLayer) { goal_node_ptr_->position.z = NearestTerrainHeightofNavPoint(...) + vehicle_height; }` —— 单层模式下**规划器主动把目标 z 压回「最近地形高度＋车高」**，3D 目标的 z 被吃掉。多层分支见 `contour_graph.cpp:134-138`：`IsMultiLayer` 为真时改为「不同层且非 frontier 的节点不连边」＋ 全局检查。

> ⇒ 本项目是多楼层语义，`config/default.yaml` 必须设 `is_multi_layer: true`，否则「3D 后端」名不副实（z 被压平到单层）。这也是 B0 门控里最容易被漏掉的一条。

### 7.3 对原清单的修正
