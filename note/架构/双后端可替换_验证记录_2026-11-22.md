## 二、B0 期间发现并已修的环境缺口：容器看不到 `archive/`

现读事实：

| 项 | 读数 |
|---|---|
| 容器内 `/opt/ros1-slam/` 目录（修前） | 有 `data docker logs note opt scripts sim_repo sim_ws subprojects tooling ws`，**无 `archive`** |
| `docker/docker-compose.yml` 挂载表（修前） | `&ros-volumes` 锚点与 sim-viz 自写列表**都未挂 `archive`** |
| 容器内预检（修前） | `[①ISO] ISO_RC=1`，ISO 件报 `[v8-isolation] rejected: moved costmap plugin package missing from both ws/src and archive` |
| 临时容器补挂 `archive` 只读后 | `PREFLIGHT VERDICT rc=0`（放行），整条窗口 `rc=0` |
| 正式补挂 `&ros-volumes` 并在规范容器重建后 | `[①ISO] ISO_RC=0`，窗口 `BT_NATIVE_RUNTIME_RC=0` |

根因：B 链窗口被拒窗的是**挂载面缺口**，不是代码缺陷、也不是本卡改造引入。

来源：2026-11-22 退役批次 `b38ec273` 把 `lite3_costmap_layers` 整包 `git mv` 进仓根 `archive/`，而容器只挂到 `ws/src` 等子目录；该批 04 段末已自留「ISO 与 DC 的定性仍须机器侧看到具体行」——本次在机器侧看到了，红因即此。

影响面：凡在容器内跑 ISO 闸的路径都会红（窗口预检、B5 门禁串），**不止本卡**。

处置（已做）：`docker/docker-compose.yml` 的 `&ros-volumes` 锚点补一行 `- ../archive:/opt/ros1-slam/archive:ro`（`sim`／`slam`／`slam-host` 均生效），`docker compose up -d --no-deps --force-recreate slam` 与 `... sim` 重建两个容器。只读是安全的：`archive/` 不参与 catkin 构建，`pyst_face.txt` 注记也明写归档副本不再受 PYST，没有门禁会往里写 `__pycache__`。

遗留：`sim-viz` 走自己的挂载列表、未补 `archive`。该容器只做 GUI 显示、不跑门禁与窗口，暂不动；若将来要在它里面跑预检，先补挂。

### 6.3 本节最贵的一条：`vehicle_height` 是「odom 离地高」，不是「雷达安装高」

far 分支起得来但 `WAYPOINTS` 恒 0、`/FAR_obs_debug` 恒 0、`/FAR_terrain_height_debug` 恒 0。定因过程与读数：

1. 纯合成台架（`evidence/b2_far_harness/`）能建图：`V-Graph Initialized`、36 航点 ⇒ 上游件与参数面没问题，问题在数据或时序。
2. 录一帧真实点云复放（`evidence/b2_far_recplay/real_cloud.npz`，19965 点、`obs_frac=0.145`）：位姿 z 用录值 0 → 失败；位姿 z 抬到 0.436 → 成功（`far_P1` vs `far_P4`）。用合成墙做同构造对照，`z=0` 失败／`z=0.436` 成功（`far_A/B/C/D`，交替 4 相，排除「第几相」的顺序效应）。
3. 把整片点云整体下移 0.436 也成功（`far_G`）⇒ 关键量是 **机器人与地面点的相对高差**，不是绝对 z。
4. 临时在 overlay 打点（已还原并核 42 件 sha256）拿到断裂点：`DIAG1 obs=77 → DIAG2 after_grid obs=77 → DIAG3 surround_obs=0`。写入成功、读取为空，抹掉它的是 `UpdateTerrainHeightGrid` 末尾的 `ObsNeighborCloudWithTerrain`。
5. 上游 `TraversableAnalysis`（`map_handler.cpp:459` 附近）启动地形连通搜索的条件是 `|terrain_h − robot.z + vehicle_height| ≤ height_voxel_dim(0.3)`。本栈 `/v8/local/pose` 的 z 与地面同高，故该差恒等于 `vehicle_height`；填 0.436 时 0.436 > 0.3 ⇒ 地形图不初始化 ⇒ 可见障碍格被全部滤掉 ⇒ 可见图不建。
6. 定为 0.0 后同一帧真实数据：`surround_obs` 0→131、航点 0→49（`far_K` vs `far_L`）。

`0.436` 是雷达安装高（`MID360_MOUNT_Z` 一族），与「odom 原点离地高」是两件事，不能互相回填。上游默认 0.75 同理是大型平台车的 odom 离地高。

### 6.4 两条现状读数（不是缺陷，但会影响验收脚本写法）

- **冷启动预热**：FAR 约 30 s 才建好可见图，此前 BT 连续收到 `E_FAR_WARMUP`（`ACCEPT_WARMUP_REFUSED=2`，`WARM_ATTEMPTS=2`）。首个任务在冷启动后直接下发会落空一次。
- **仿真时钟**：`/use_sim_time=True`，实测 24.0 s 墙钟只推进 10.5 s ROS 时间（≈0.44）。`waypoint_timeout_s=10` 折合墙钟约 23 s，验收窗口按墙钟 18 s 会误判「超时门不生效」。

### 6.5 保留的可调开关与未采信的假设

- `far_terrain_flatten`（默认 true）：曾假设「地形点被压到地面导致 obs 恒 0」，用 `flatten=false` 对照后 obs 仍 0，假设被否，开关保留但**不是**本问题的解。
- `/scan_cloud` 直通：`is_static_env=true` 时上游 `ScanCallBack` 首句 return，这条链路当前不消费。
