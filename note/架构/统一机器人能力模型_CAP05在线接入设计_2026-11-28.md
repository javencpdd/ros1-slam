## 1. GlobalRoute → LocalTrajectory 契约

新增 `ws/src/80_algorithm/v8_algorithm/planner/route_contract.py`（schema `route/v1`）。必填：

| 字段 | 语义 |
|---|---|
| `backend` | `support` / `far`；表达路线来源，不改变算法 |
| `map.map_id/map_version` | 生成该路线时的地图身份，下游版本不符即拒绝 |
| `capability.robot_id/capability_version` | `robot_id` + `robot.v2` 能力版本（如 `robot.v2:tested:<sha>`） |
| `path[]` | **完整**路线点；support 点必须有 `surface_id`，FAR 可暂缺 |
| `transitions[]` | `from_index/to_index/kind`；kind ∈ `flat/slope/step/terrain`；顺序不重叠 |
| `cost_decomposition` | `distance_m/time_s/risk_expected_m/risk_known`；未知风险必须 null |

已实现校验：完整路线 ≥2 点、版本必填、surface 与 transition 两端一致、flat 不得跨面、slope/step 必须跨面、未知风险不得伪造为 0。8 项契约测试通过。

**未完成**：`from_support_plan` 的 transition kind 需要从地图边补入（调用方传 `transition_kinds`）；FAR 两路点没有 surface 语义，需先做路线到支撑面/地形的关联，不能直接冒充 support 路线。

## 2. 在线消费链（目标态）

```
BT goal / task identity
  -> GlobalRoute (route/v1, complete path + transitions + capability/map versions + cost)
  -> LocalTrajectory adapter
       * hard capability check (query_capabilities/authorize_capabilities)
       * map_version / capability_version / task identity 同源校验
       * forbid risk weights until evidence
  -> local_native / FAR backend
  -> safety mux -> carrier
```

约束：

1. **硬约束先于代价**：任何坡度/台阶/净空/速度不满足的路线在 adapter 处拒绝或改线，不进入局部轨迹。
2. **能力值只来自 tested+allowed**；declared/prohibited/simulated/unknown 不可转成运动授权。
3. **未知风险不按 0 处理**；只有具备样本量、测试环境、报告和适用边界的成功率才能进入代价分解。
4. **地图/能力/任务三版本**：`map_version`、`capability_version`、BT task identity 均须随路线传递；缺失即 fail-closed。
5. **BT 不写速度**：BT 只拥有目标/取消/状态/租约；执行后端通过统一生命周期启动/停止。
6. **Action/Topic 双后端**：先做适配层（同一个 BT 树，Topic 与 Action 两后端等价），不把 Action 语义塞进 `local_native`。
7. **Task 权威身份**：`request_id`/`seq`/mission 代次只允许由 BT 任务层生成；路线与局部轨迹只读携带，不得重新编号。

## 3. 与现有技术债的关系

- 债 B（BT/执行后端解耦、Action/Topic 生命周期）：本设计给出目标接口，未施工；需先完成 Action 适配层。
- 债 C（Task 全语义/身份）：路线契约要求携带权威身份；现有四处假 PASS 未修，在线接入前必须闭合。
- 债 D（FAR/Support 路线语义）：FAR 只有两点、无 surface；必须先补 terrain→surface/接触点关联，不能只加 capability 字段。
- 债 E（统一能力模型在线接入）：CAP-01—04 只到离线/查询层；本设计不改变在线规划。
- 本件不新增债号；施工触发器与出口仍以 `note/08_技术债台账.md` 为准。

## 4. 启用门禁（全部满足才允许在线接入）

1. CAP-01/02 的机器人资产有 tested/report、样本量、环境和适用边界；未知项保持 unknown。
2. CAP-03 查询/拒绝接口被独立复核，且“更严格上限/更保守下限”有反控。
3. CAP-04 离线代价在真实回放/多层地图上复跑，风险与成功率未伪造。
4. CAP-05 route/v1 契约在 Support 与 FAR 两个后端都能产出完整路线；FAR 的 surface/接触点关联完成。
5. BT/执行后端 Action 与 Topic 两形态行为等价，任务身份/取消/生命周期有 ACK 证据。
6. 本地化闸门同时约束估计 TF 与导航位姿（A3 已验证）；GT 不进入生产链。
7. 通过 M2 四组用例与 Stage A 精度门禁；不降低 `support_tol_m`、不启用未批准的 0.08。
