## STD-01 阶段提交

每完成一个阶段或最小可验收切片，必须依次完成：定向验证 → 与影响范围相称的检查 → 四要素落账 → 现查 `git status`／差异 → 仅暂存本任务文件 → **本地 `git commit`** → 更新 `.ai` 交接。四要素是实现状态、自动化验证、目标环境验证及证据路径；环境未具备须明确写未验证。未提交的阶段不算收口，不能先执行下一阶段再补多阶段混合提交。

提交消息说明做了什么、为什么及记录在哪里；**push 由用户决定**。只读答疑不要求空提交。保留既存或他人修改，不用 `git add .` 混入。实际提交失败要记录命令、错误和已暂存范围；恢复后先核当前状态再补同一提交。不得把失败的提交记作完成。

## STD-02 平台分工与构建边界

| 目标 | 职责 | 构建与运行约束 |
| --- | --- | --- |
| `lite3` / `m20`，`real_robot` | 真机传感、建图、定位、导航、安全与设备适配 | 原生部署；只构建该机器人所需的公共接口、算法、硬件适配与安全依赖闭包；**不编译仿真环境、不安装或运行 Gazebo/MuJoCo/训练依赖** |
| `x86_sim`，`simulation` / `training` | 算法开发回归、Gazebo/MuJoCo、运动学与动力学实验、可复现模型/策略训练 | 仿真和训练依赖留在开发端；不得解析或启动真实运动桥；独立地图、日志、端口与模型资产 |

平台是目标身份与用途，不用 CPU 架构猜机器人：M20 的架构、系统、设备协议和 ROS 适配须在接入时核定，不从 Lite3 模板推断。Lite3 当前使用原生 ROS1/Noetic；M20 是待接入目标，尚无真实适配。x86 承担训练职责不表示仓内已有训练器，当前外部 ONNX 推理/评测不能称为训练闭环。经目标验证的模型推理运行时可属于机器人算法依赖；推理与训练环境分别管理。

构建入口应显式选择目标并校验 package 依赖闭包；真机与仿真分别使用 build/devel/install 空间。公共接口/算法不应无条件依赖仿真包，仿真插件、测试和训练环境放独立适配层。禁止向绑定的第三方源码写 `CATKIN_IGNORE` 来实现隔离。

[目标构建器](../../tooling/build/README.md)显式选择 `lite3` / `x86_sim`，按受审查根包解析普通构建/运行依赖，拒绝机器人传递仿真/训练依赖；M20 尚未适配，入口明确拒绝。它不证明 XML 未声明的系统依赖已安装，也不证明原生目标已编译。Docker 镜像与容器内重编统一固定选择 `x86_sim`，只支持仿真开发；`PROFILE=core` 和旧 `SLIM=1` 明确拒绝，不能据名称推断真机构建隔离。生成视图和身份与 build/devel/install 使用目标专属空间及卷，旧全量卷保留且不自动接入；构建与容器入口不再补写原源码。启动模式校验与目标环境验证仍是缺口，不提供全量 `catkin_make` 作为机器人标准构建命令。

## STD-03 可替换的算法与稳定接口

业务任务仅依赖稳定契约；组件通过 manifest 声明职责与接口，经适配器、graph/config 选择后端。替换建图、定位、导航算法时，以不改任务业务逻辑、安全仲裁和独立评价器为目标；允许新增后端适配器与版本化契约，禁止把修改第三方实现当作标准接缝。

| 职责 | 稳定边界与替换要求 |
| --- | --- |
| odometry / global_localization | 连续局部位姿与地图内定位/重定位分别声明，输出位姿、质量、状态和来源；真值不能冒充估计定位 |
| mapping / map_server | 建图生产与地图加载/查询分开；地图 ID、revision、坐标、数据哈希与 unknown 语义一致 |
| representation / global_planner | 表征 schema 与空间维度明确；路线保留地图版本、支撑面、起终点及可通行走廊 |
| local_planner / controller | 路线、带时间的轨迹和速度建议区分；取消、限幅、过期与停车语义一致 |
| trajectory_validator / safety_arbiter | 独立检查候选轨迹；最终运动命令唯一所有者，换规划器不绕过停止链 |
| robot_adapter / simulator / evaluator | 真实驱动、仿真载体与评价器独立；不同机器人用各自协议/模型，评价真值不流入被测算法 |

每份接口合同必须定义：消息类型与 schema/version、维度、坐标系、参考点、SI 单位、测量时间与时钟来源、新鲜度/有效期、地图与机器人版本、所有权及故障行为。字段尚不被现有 schema 接受时，先在适配合同中登记缺口，再走显式版本迁移；不能往 `additionalProperties=false` 的 v2 端口硬塞新字段并绕过验证。

goal / feedback / result / cancel 保持同一任务语义；成功、无路、预算耗尽、取消、输入非法、组件失败、安全停车分别映射，不能全部记 timeout。生命周期覆盖 configure/start/ready/health/stop；ready 依据可观测条件，启动失败回滚已启动组件，停止时保留安全仲裁直到其他命令源退出。

声明、静态兼容、契约测试、仿真验证、真机验证分别记录。**注册过、图检查通过、编译成功都不等于可以替换实跑。** 校验图、渲染计划与实际进程必须消费同一 I/O 解析结果；换后端后仍须复核真实消息类型、TF、时间、取消和停止。当前 app 目录选择、graph 边运行接线、参数校验与热替换均有受限范围，不宣称任意算法即插即用或无缝热换。

## STD-04 坐标、时间与运动安全

每条 TF 及每个 child 的发布者唯一；同一 parent/child 由两组件发布也须拒绝。map→odom→base 职责分离，不把修改 `frame_id` 当几何变换。map 系速度进入机体控制前显式旋转并核参考点；2D 投影和末点适配必须写明丢失的信息，不能当成完整 3D 路线跟踪。

测量关联使用 ROS 时间，进程看门狗与停钟保护使用单调墙钟。检查消息/TF 的源时间戳，不把“旧 TF 还能查询”当作持续新鲜；时间倒退、输入过期、定位失效、地图换版时撤销旧轨迹并停车。最终命令注明来源、坐标、租约与有效期；停止和限幅不能依赖规划器自律。

运行前应从 app/graph 到进程明确 `execution_mode` 与机器人身份，拒绝仿真接真实驱动、真机接仿真载体及错误底盘适配。受支持框架入口通过manifest/v3声明、assembly_plan/v2身份绑定和统一守卫核对模式/机器人，见[30号补丁](../计划书v8/30_目标隔离与运行域契约.md)；旧v2仅离线兼容，混合图不能据静态通过执行。这是框架兼容检查，不能代替任意终端rosrun/传统launch管理或现场许可。Lite3速度坐标、TF健康和真实目标环境尚未闭合前，不据模式匹配或静态图通过启动真机。本轮审查不构成硬件动作或现场参数授权。

## STD-05 调度与授权

仅从当前用户授权范围选择依赖已满足、状态明确的任务。取消、废弃、被替代的任务跳过；缺状态或依赖证据不足不自动选入。不得把“始终有下一项”解释为恢复已取消的算法、地图或真机排程；无获授权下一项时如实记录，不凭旧计划的“下一步”扩张范围。

常规已授权工作持续推进；L1 判据/独立复核交独立代理，L2 红线、真机、官方表述笔权或授权面外新决策交用户。无需用户扮演中间角色。规则维护、静态审查不要求报仿真窗号；真正启动运行前才按现行调度单报窗、登记回执并跑适用预检。

**不挂后台看守、不轮询等窗、不用 FORCE 绕过预检。** 预检未达标不启动运行；可继续作用域内不依赖运行窗的工作。负载阈值和门禁成员从各自脚本/清单现读，skills 不维护固定数字副本。须呈报的缺口带实证、选项、后果和推荐；既有授权范围内的实施不反复索取确认。

## STD-06 验证、训练资产与文档

实验结果使用 PASS / FAIL / INVALID；环境前置不足不归为算法成功，INVALID 不吸收并存 FAIL。历史判据仅用于其原范围，新契约正反控不代替旧门禁；不得为得到绿灯改阈值、删失败项或重写旧证据。静态规则检查只证明其覆盖的文本/结构一致性。

训练与推理分别记录。训练交付至少绑定机器人/场景/模型版本、观测和动作定义、坐标/单位/缩放/频率/限幅、数据/环境、奖励与优化器、种子、依赖、checkpoint/导出模型哈希及独立评测。外部 MJCF/mesh/ONNX 记录来源、许可和路径。运动学、动力学、策略训练和真机能力各有证据出口，不相互晋级。

关键验证与交接证据保存到随仓记录或仓外持久归档，并登记恢复路径；临时目录不能作为唯一交接载体。编辑的文档带最新更新时间；路径引用随改动同步。源码在 `ws/src/`，工具代码在 `scripts/` 或 `tooling/`，`note/` 只放文档和证据数据。代码/文档以 Git 追溯，历史证据快照和清单保留原时点；当前技能派生清单在覆盖件写完后按生成器生命周期整体重建并核对名册，改前字节由 Git/快照追溯，新增规则检查不得整行豁免“历史/现读/指针”等词。
