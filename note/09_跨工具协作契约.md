## 3. 任务纪律（防串台）

1. **同一时刻只有一条战线**：全局只有 `current_task` 一个，`resume` 只吐它。
   被要求做别的事，先 `handoff` / `done` 再 `new`。
2. **作用域白名单**：任务卡写明 scope（如 `ws/src/40_navigation/`），**不在列表里的文件不要改**，
   哪怕看起来该顺手重构。
3. **状态迁移必须走脚本**：`TASKS.md` / `HANDOFF.md` / `state.json` 由 `bridge.py` 生成，**禁止手改**。
   唯一可手写追加的是任务卡里的「工作笔记」。
4. **epoch 核对**：`HANDOFF.md` 顶部 `epoch: N` 小于 `bridge.py json` 输出的当前值 = 读到旧快照，重跑 `resume`。
5. **按授权分流**：常规已授权任务继续核证推进；L1 判据与独立复核交独立代理，L2 真机/红线/官方表述笔权/授权外新决策交用户。上机 actual flag、雷达外参、真实 TF 等不得自行改定。待裁事项带实证登记，不因普通实现选择重复索取确认。

## 8. 为什么不做别的方案

| 方案 | 结论 |
|---|---|
| 互导两边私有记忆 | ✘ 格式闭源 + 厂商可能变更 + 有写坏库风险 |
| memU（14.5k star, Apache-2.0） | △ 定位合适但官方 host 矩阵不覆盖 zcode / qoder，需自写 adapter + 自备 embedding |
| MCP 记忆服务 | △ 引入 DB 依赖，对一个 ROS 沙箱过重 |
| **共享黑板 + bridge.py** ✔ | 零依赖、纯文本、可 git diff、人和 LLM 都能读、换任何工具都不失效 |

> AGENTS.md 类指令的遵守率是**概率性**的（超 200 行明显下降、冲突指令随机取舍）。

> 它不写回 Codex，也不参与日常状态迁移；日常接力仍只认 `.ai/`。

## 9. 常设授权：非 L2 一律自动推进（真人 2026-10-25 明令入 harness）

> 原文要点（逐字可查于当日会话）：「继续任务。非 L2 停手类的停顿（礼貌等待、不确定可否动）一律自动推进：按协议选件规则（依赖闭合内优先级最高）选下一件；阶段出口将满时把下阶段首件排入待办队列，规划好任务队列。若属 L2（红线／真机／官方表述笔权／授权面外新决策族），不要硬走——带齐证据、读数和你的推荐选项来一句，我只对选项勾。你也可以参考我选择的习惯自行勾选并继续开发。」

1. **默认动作＝推进**：出现「要不要等一句」「不确定能不能动」「礼貌性请示」这类停顿，一律不停，按依赖闭合内优先级最高的下一件继续做，并把结论与证据写进对应进度卡与登记面。
2. **选件规则**：先看当前阶段出口所需件；同优先级按依赖先后；出口将满时，把下一阶段首件排入待办队列（`.ai` 任务表与 23 号队列的接续段各记一处），不提前开工。
3. **停手四类（L2）**：红线（真机、第三方原件、旧判据门值、历史证据）、真机及其参数、官方表述笔权（对外签字、许可结论、正式验收措辞）、授权面外的新决策族。命中止步，一次呈报证据、读数与推荐选项，供真人勾选。
4. **代勾边界**：允许参考真人的勾选习惯自行勾选并继续开发，但不得据此代替权利方发许可结论、代替判据面签正式 A0、或扩大已授作用域；代勾须在登记面写明「代勾＋依据＋可撤销」。
5. **与既有纪律的关系**：本条不放宽作用域白名单、ACL／属主、A6 单向流、三态通道与 P8 回写；与 `.ai` 单任务游标并用时，换线仍须 handoff。

6. **连续自动化（2026-10-26 真人再明确）**：本条是**连续工作**授权，不是「做完一片就停下等一句」。每收口一个最小纵向切片（定向测试＋相称门禁＋登记＋本地 commit），**立即按依赖顺序选下一片继续**，不因「要不要继续」「下一片做哪个」而停工；只有命中四类 L2 才停。切片边界只用于控制单次改动面与可回滚性，不是停手点；跨切片连续推进时，进度面按片登记、更新时间照写。
7. **自动选件的判据形式（可复核）**：开工前先实查——队列状态列、进度目录最新证据、代码与测试实物三者对齐；取「依赖已满足且最早未闭合」的一件；若上一件只有代码、缺自动化或目标环境验收，先补它，不跳级。该判据可写成一句话自查：有代码？有定向测试？有目标环境证据？三者缺一即未完。
8. **阶段提交纪律**（真人 2026-10-26 明令）：每完成一个阶段（或其最小纵向切片）并落账后，当值工具**必须 git commit 入库**（push 可选，由真人决定）；commit 消息沿用批次格式（做了什么／为什么做／去看哪里）。未 commit 的阶段不算收口；「不提交不 push」旧批尾语自本条起废止。工作树状态在每批收口前须现查（git status），不得沿用上一批的未提交结论。
9. **遇到问题不停（2026-10-26 真人明令）**：调试属于推进，不是停顿。发现缺陷、红灯或联调不通时，就地定位根因、修掉、复跑取读数；**不得把「我先报告一下再等你」当成处置**。只有命中四类 L2，或同一问题连续三次修复仍无新进展（此时带证据与推荐选项呈报）才停。报告里必须写清「试了什么、读数是什么、下一步改哪里」，不许只写「失败了」。
