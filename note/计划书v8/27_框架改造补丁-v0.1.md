## 0. 定位

- 现有 v8 主线 V8-00—V8-15 已完成窄口径收口，V8-X1/X2/X3 未开工；本补丁不重开这些任务。
- 本补丁解决的是“**组件接入一次，用户用 YAML 选择实例、参数与连线；仿真独立验证组合**”的框架层。
- 首版**只做 ROS1**；ROS2、热插拔、运行期改线不在本补丁。
- 具体地图/算法/M20 协议不要求实现；用测试替身证明可接入、可替换、可停止。
- 向后兼容优先：v1 manifest、现有 composer/registry/orchestrator、mux 唯一写者、A1—A7 状态均不变。

## 1. 目标模型

```text
manifest v2（组件类型：roles / ports / launch / evidence）
        │  registry 加载
        ▼
graph.yaml（实例、参数、命名端口、显式边、外部输入、反馈策略）
        │  check（类型/schema/启动DAG/命令唯一/锁）
        ▼
assembly plan ──► launch adapter ──► ProcessRunner / Orchestrator
        │                                   │
        │                                   └─ ready/stop/cleanup
        ▼
地图 provider（2D/3D/语义）· 机器人 adapter（Lite3/M20 测试替身）· 中间处理组件
        │
        └─ 独立验证配置（MuJoCo/Gazebo；真值只给评价器）
```

四条硬规则：

1. **单一组件源**：组件只由 manifest 定义，不另建 catalog。
2. **实例与类型分离**：同一类型可多实例；连接必须落到命名端口。
3. **启动图与数据图分离**：反馈边必须显式并带策略，不参与启动 DAG。
4. **仿真不进核心依赖**：核心框架不 import MuJoCo/Gazebo；仿真只消费组合结果做验证。
