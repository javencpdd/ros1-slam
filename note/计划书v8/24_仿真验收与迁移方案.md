## 2. 仿真分层与信息隔离

| 层级 | 输入与载体 | 能证明的能力 | 出口限制 |
| --- | --- | --- | --- |
| L0 离线几何 | 固定地图、机器人包络、小图参考解 | 地图语义、支撑连通、路径/轨迹碰撞、正反例正确性 | 不证明感知、跟踪或动力学 |
| L1 导航闭环 | 真实场景几何、传感器模拟、受支撑约束的运动学载体 | 感知/规划/控制命令/运动更新闭环与故障停车 | 必须声明简化支撑/运动模型；不证明真实步态 |
| L2 四足动力学 | 关节、碰撞、接触、摩擦、力矩与腿控制器 | 指定模型与参数范围内的爬坡/爬阶执行 | 需要专项标定；仍需真机验证迁移 |

L1 分为 GT 与 EST 两轨：GT 用真值位姿只评价规划与跟踪；EST 使用被测定位估计，真值仅给独立评价器。预建地图与在线建图也分别登记，不把已知完整地图的结果标成探索/未知环境能力。

运动学载体可以沿已验证支撑面更新机体高度/姿态，但必须由控制命令驱动，不能直接沿规划轨迹回放、瞬移楼层或自动纠正错误路线。仿真支撑真值只属于载体物理近似，不可直接泄漏到 EST 的感知地图。评价器用独立场景几何检查碰撞与支撑，不能只信规划器自报。

### 4.1 数值定标与冻结

以下是**新实验的设计要求**，不是旧判据改值或既有实测结果：

- 确定性合同正负例全部满足预期；强制安全约束不得出现碰撞、穿楼板、悬空跨越、错误楼层到达或双写运动命令。
- 初始覆盖设计为每个适用闭环场景至少 3 个预登记 seed、每 seed 3 次重复；固定几何无随机量时改用 3 组不同起终点。不支持某场景的组件不强跑，但必须在兼容层拒绝，不能从报告中静默删掉该场景。
- p95 全局/局部时延、取消与停车时间、到达 XYZ/yaw 容差、最大定位误差、资源上限和成功率门槛，由 V8-12 按硬件与机器人模型定标；记录实测依据和独立复核。未冻结之前只能做开发实验，不能报正式验收。
- 停车距离预算必须覆盖感知延迟、规划/控制延迟及制动过程；由模型和观测支撑，不能只给一个无来源的距离阈值。
- 地图规模、分辨率、机器人速度、传感器频率与实时因子随结果一起报告。先给小/中/大规模曲线，再判断需要图压缩或并行加速。

V8-12 的定标集合与 V8-13 正式集合分开，封版后不得根据失败样本删除目标或放宽门槛。必要变更生成新实验版本，并同时保留旧版本结果。当前未定数值是明确的实施前置，不是让算法无期限调参的许可。

### 4.2 三态与分母

PASS：有效实验满足该场景预登记的预期；因此「正确无路」和「按要求停车」也可为 PASS。

FAIL：有效运行违反目标或契约；含算法预算耗尽、未按要求停车、错误到达与被测组件崩溃。若同时有环境异常和已观测的安全失败，保留失败事实，不得用 INVALID 吸收。

INVALID：环境/证据前置不成立，无法对本测试目标作有效判断，例如仿真未启动、输入未加载、必需真值缺失。缺陷来源先分辨：被测组件运行后崩溃不能简单改成环境无效；预期注入故障被系统正确处理则依该场景判 PASS。

报告至少列 N_total、N_valid、N_invalid、N_pass、N_fail 及逐例理由；成功率按预登记有效分母计算，同时报告有效覆盖率。重跑保留首次结果与新 run_id，不选最好一次；不同组件版本、配置、载体代际和 GT/EST 结果分别统计。

## 5. 运行与定位失败的顺序

每轮依次执行：锁文件与实物核对 → 仿真隔离与资源预检 → 地图/传感器/TF/时钟就绪 → 起终点和参考连通性检查 → 启动任务 → 事件注入与独立取证 → 任务终态 → 清理与退净 → 报告与哈希归档。

出现失败时，按以下顺序找第一个失效环节：

1. **载体与观测**：传感器起点是否自碰撞、点是否零填充、几何覆盖和 IMU 是否可信。
2. **定位与时间**：TF 是否唯一且新鲜、frame 与外参是否正确、sim/wall 时限是否一致。
3. **表征**：地图范围、未知编码、支撑面连通与机器人净空是否正确。
4. **规划**：输入有效后再查搜索、启发式、预算、平滑和取消；同时保存节点展开与失败类别。
5. **执行与评价**：轨迹是否正确到达跟踪器、命令是否经过仲裁、载体是否真实响应、评价器是否读对版本。

P4/动态障碍专项必须保存时序：初始有效轨迹 → 障碍注入 → 被传感器/地图确认 → 原路线失效 → 触发重规划 → 新轨迹采用或停车 → 到达/失败终态。没有这些事件，仅看到轨迹变形或目标最终到达，不能证明重规划链达成。

每个 run 的最小证据包含锁文件、环境清单、场景/起终点/seed、输入覆盖、状态/事件日志、地图与轨迹版本、关键 rosbag 或等价采样、评价 JSON、stdout/stderr、资源采样、退出与清理结果、SHA256 清单。大数据可在独立产物目录保存，仓内登记稳定位置和获取方式，不能只留会消失的 /tmp 路径。

## 6. 迁移与删除规则

迁移采用旁路实现、同场对比、逐入口切换、最后退役。用户允许重建不代表必须全部推倒；保留的依据是正确性与可复用性，删除的依据是替代覆盖和维护成本。

| 旧资产 | 迁移做法 | 可以移除的条件 |
| --- | --- | --- |
| 硬编码 launch 组合、专用 SCAN 任务分支 | 先注册为适配器，建立统一目标与取消合同 | 新入口覆盖相同功能，旧入口调用方已迁移且有回退方法 |
| 单层高程/二维 costmap | 保留适用场景；多层主线另建模型 | 无消费者且对照资产已归档，不因多层上线就删二维能力 |
| 包内自研算法与第三方副本 | 算法实现和适配壳分离；依赖版本可追踪 | 替代方案通过合同与场景回归，来源/许可证清楚 |
| 旧断言与门禁 | 建立旧目标→新检查的覆盖映射，修复路径或前提 | 证明过期或重复，并有迁移记录；安全/有效性覆盖不能降低 |
| 旧计划、旧队列、历史日志/证据 | 标记历史及新入口，原判定不回改 | 本期不删除；新结论通过新批次指向旧证据纠偏 |

V8-01 应逐项归类「直接复用／需适配／待复核／可退役」并给证据。V8-15 才执行最终入口退役与删除；发生回归时恢复旧入口和对应版本锁，新失败记录保留。不要用改变世界件、隐藏无效样本、增大未知区自由空间或删除检查来伪造回归通过。
