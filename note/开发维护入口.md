# 开发维护入口（当前基线 v8.1）

> 本页只解决「怎么动手」：构建、启动、调试、测试、门禁、操作规范。
> 系统是什么见[根 README](../README.md)；历史过程见[历史追溯入口](历史追溯入口.md)，日常开发不需要。

## 1. 统一入口：`scripts/dev/dev.py`

七个子命令，宿主上自动切容器，退出码约定 `0 成功｜1 有失败项｜2 用法错｜9 环境前置缺失`：

| 子命令 | 用途 | 备注 |
| --- | --- | --- |
| `status` | 环境自检（在哪、容器在不在、ROS/devel 就绪否） | 先跑这个 |
| `build [--plan|--clean]` | 编译工作区 | `--plan` 只读，看闭包 |
| `test [路径…]` | 跑单测 | 缺省扫 `v8_platform`；其他包显式给路径 |
| `gate [成员,…]` | 跑门禁串并**汇总退出码** | `run_gate_chain.sh` 本身 rc 恒 0，看它解析的 rc |
| `smoke [stage]` | 仿真冒烟 | 缺省 `stageA` |
| `docs --check` | 索引层与源是否一致 | 不一致返回 5 |
| `lint` | 文档断链/孤儿/同名/戳失真/空件 | 有问题返回 5 |

## 2. 构建

```bash
bash docker/build.sh --plan     # 只读：打印 38 包闭包 + rosdep 命令，不编译
bash docker/build.sh            # 真编译（容器内 catkin，JOBS 可调）
bash docker/build.sh --clean    # 清构建缓存（会动卷，慎用）
```

- 闭包定义在 `tooling/build/profiles.json`：`lite3`（真机，不装仿真）、`x86_sim`（仿真，38 包）、`m20`（**明确拒绝**）。
- 生成视图在 `ws/.profiles/<target>/`，是忽略面，不是源码。
- 编译必须在容器内（宿主无 Noetic）；`ros1-slam-dev` 限额 1 GiB 会 OOM，用 `sim` 或 `sim-viz`。

## 3. 启动

| 场景 | 命令 |
| --- | --- |
| 起整套容器 | `cd docker && docker compose --env-file .env up -d`（7 服务常驻） |
| 仿真 + BT 3D 导航 | `roslaunch lite3_bringup mode_sim_bt.launch`（`global_backend:=support|far`） |
| 仿真 2D 交互导航 | `roslaunch lite3_bringup interactive_2d.launch rviz:=true` |
| 只起场地 | `bash /opt/ros1-slam/docker/sim.sh gazebo` |
| 环境自检（GL/插件/端口） | `bash /opt/ros1-slam/docker/sim.sh probe` |
| 冒烟判据 | `bash /opt/ros1-slam/docker/sim.sh smoke stageA` |
| 真机 | `roslaunch lite3_bringup mode_navigation.launch`（`enable_motion`/`enable_bt` 缺省 **false**，需现场授权） |

ROS 环境姿势：先 `source /opt/ros/noetic/setup.bash` 再 `source ws/devel/setup.bash`，`PYTHONNOUSERSITE=1`。

## 5. 测试

```bash
python3 scripts/dev/dev.py test                              # 缺省：v8_platform 344 项
python3 scripts/dev/dev.py test ws/src/80_algorithm/v8_algorithm/local_planner
```

- 逐包跑法（包根）：`cd <包> && python3 -m unittest discover -p "test_*.py"`。四个算法子包分别 161／77／68／63 项。
- **注意**：从 `v8_algorithm` 根直接 discover 会得 **0 项 OK**（子包无 `__init__.py`，不递归）——这不是通过，是没跑。
- **七项导入错误已修**（提交 `7989c859`）：`local_planner` 2 项、`representation` 5 项曾因同目录 `import test_xxx` 平铺导入失败；修复后两包分别为 **161 项 OK**、**77 项 OK**（修法：两处 `tests/__init__.py` 把本目录 append 进 `sys.path`，**未改测试代码**）。读数见[收尾验证](进度/00_专题/00_治理收尾验证_2026-11-23.md)。
- **仍未解决的两类（与上面 7 项无关，别混）**：
  1. **包根 discover 假绿**：`v8_algorithm` 等上层目录无 `__init__.py`，discover 不递归，输出 `Ran 0 tests, OK`——**这是没跑，不是通过**；
  2. **同进程联合发现冲突**：`planner/ros_node.py` 与 `local_planner/ros_node.py` 同名，多个套件挤在同一个进程里会互相覆盖（实测 293 项 / 84 errors + 1 failure）。清空 `sys.path` 垫片前后读数一模一样 ⇒ 属既有布局属性，不是 `7989c859` 引入。**正确用法：按套件分进程跑。**

## 6. 门禁

```bash
python3 scripts/dev/dev.py gate                 # 全部 11 成员并汇总
python3 scripts/dev/dev.py gate SYN,PYST,DC     # 只跑指定成员
GATE_ONLY=ISO bash scripts/verify/run_gate_chain.sh   # 单成员，看件自身 rc
```

- 成员名单与 rc 语义：`scripts/verify/gate_chain.txt`（**11 成员**）。
- **VCC 是在册基线 rc=6 / RED=39**（历史台账里的旧引用），不是本轮引入；取全量明细须显式放大 `VCC_MAX=500`，否则只打印前 20 条。

## 9. 常见坑（都在台账里，别重复踩）

| 现象 | 原因 | 去哪看 |
| --- | --- | --- |
| 门禁 rc=0 但件报红 | 运行器「只报不判」，rc 恒 0 | 上文 §6；看件自身 rc |
| compose exec 挂住 | 本机 docker compose exec 会卡 | 改用 `docker exec -u 1000 -w /opt/ros1-slam <容器> bash -lc '…'` |
| 包根 discover 0 项 | 子包无 `__init__.py` | §5 |
| 改 `web/serve.py` 不生效 | bind mount 只让页面生效，代码要重启容器 | `docker restart ros1-slam-web` |
