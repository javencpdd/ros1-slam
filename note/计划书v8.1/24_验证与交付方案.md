## 4. 场景与故障覆盖

沿用SC编号定位覆盖类别，不直接复用旧分母。每个获授权实验先固定几何、地图、起终点、模型、外参、动态事件、组合及预期结果。

| 类别 | 覆盖与必需正反例 |
| --- | --- |
| SC01 平层/窄通道 | 合包络可达，窄于包络拒绝，2D适配等价 |
| SC02 障碍/死胡同 | 绕行与隔离无路，区分连通和预算 |
| SC03 坡道连接 | 上下双向、超过配置能力拒绝 |
| SC04 楼梯几何/转角 | 合法连接和关键平台保留；几何可行不称物理上阶 |
| SC05 同XY上下层 | 不跳层/误到达，只能走合法连接 |
| SC06 桥上/桥下 | 同XY独立路线和净空、层身份 |
| SC07 低顶/悬挑 | 地面可行但机身净空不足拒绝，连续包络 |
| SC08 断桥/支撑消失 | 无支撑不跨越，有绕行重规划 |
| SC09 动态堵路可绕 | 原路线失效→新轨迹采用→到达的事件链 |
| SC10 动态堵路不可绕 | 撤销、命令归零与明确无路/安全终态 |
| SC11 未知/图外/坏观测 | 零/NaN/空点等拒绝，不生成假自由带 |
| SC12 TF/时间/传感器 | 双写/环/缺变换、旧/未来/倒退戳、停钟与停更，拒绝/实际停车 |
| SC13 定位质量/跳变 | GT/EST独立误差、失锁/重定位与旧轨迹撤销；不可只测匹配分数 |
| SC14 生命周期 | 取消/崩溃/重复启动/超时，终态、仲裁保持、资源退净和他任务隔离 |

支撑图障碍设计层原有SC02/05/06派生9例留在原报告。MuJoCo阶面三例从deck初始化，几何同源map/v2，只证明该阶面支撑域内避障/拒动；完整地面→阶面、四足过沿、后腿换位及稳定前进必须另验。外部ONNX→PD→力矩→接触执行也不能作本仓训练器证据。

## 5. 定标、三态与统计

先核适用已冻结配置和原范围；新目标/模型/范围变化时另立定标版本和独立复核，不覆盖旧值。正式集与定标集分离，未冻结的新关键量仅可报开发实验，不能正式签收。已有冻结件不因本次换代失效或自动适用于新范围。

应绑定：预算/规划与harness时限、p95时延、取消/停车时距、XYZ/yaw/层身份到达容差、定位质量/误差、资源、采样、重复/种子、分母和重跑规则。停止预算覆盖感知、通信、规划/控制延迟及制动，数据和模型不足时保留缺项，不添无来源门值。

保留旧v8的初始覆盖设计：适用闭环场景至少3个预登记seed、每seed3次；确定几何无随机量时使用3组预登记起终点。它是后续新实验的设计要求，不重算旧样本；调整须新版本和独立复核，失败后不删场景或放宽门槛。

实验按PASS/FAIL/INVALID报告；INVALID不吸收同时存在的FAIL。报告N_total、N_valid、N_invalid、N_pass、N_fail及预登记未完成项，满足N_valid=N_pass+N_fail、N_total=N_valid+N_invalid。有效覆盖率在N_total>0时为N_valid/N_total，N_total=0时记不适用；成功率仅在N_valid>0时为N_pass/N_valid，否则记不适用。缺前置与未跑项显式保留，不偷偷移出计划覆盖面。

## 6. 运行因果、证据与交付

实际流程：核当前授权/锁与实物 → 隔离/资源预检rc0 → 地图/传感器/TF/时钟就绪 → 目标及参考连通性 → 启动/事件注入 → 独立取证 → 终态/停止 → 清理退净 → 原始报告/哈希。

失败按第一个失效环节定位：载体/传感 → 定位/时间 → 表征/覆盖 → 搜索/预算/平滑 → 跟踪/命令/评价。不同失败签名不能统一归算力；TF/环境或无效输入不当算法成功。动态障碍必须有初始轨迹、注入、感知/地图确认、旧路线失效、重规划、新轨迹采用或停车、最终结果的时序证据。

最小证据：代码提交、有效参数与输入哈希、target/模式、地图/机器人/场景、来源/依赖、seed/时钟、状态事件、实际话题/命令和独立测量、stdout/stderr、资源、退出/退净、结果JSON与SHA256。有限密采样评价与连续几何证明分别说明。大资产放稳定持久目录，仓内留获取和摘要；不只留/tmp，不在note新增可执行代码副本。

来源/许可按实际使用的代码、地图、模型、SDK和ONNX逐项核身份/适用性/可回取性；缺证保留责任与解除动作，不由规划代签许可或修改第三方。交付同时给支持/不支持组合、源/devel与install-only范围、干净复现命令、诊断和回退；性能按声明规模曲线说明，不给无依据通用实时承诺。
