# 22 · v8.1 架构与接口契约

> 最新更新时间：2026-11-06 15:24:22 CST。工程标准真源：`note/架构/工程标准.md`。本件区分现有实现与待实施合同；新要求不表示现有schema已经接受对应字段。

## 1. 分层与所有者

| 层/职责 | 现有源码 | 稳定边界与目标 |
| --- | --- | --- |
| 应用与任务 | `framework/app_config.py`、`app_runner.py`、`orchestrator/` | app选择任务/地图/机器人/graph；业务不按具体算法名写分支 |
| 契约、目录、组合 | `contracts/`、`registry/`、`composer/` | 标签检索、兼容判定、能力证据分别保存；未知元数据拒绝自动运行 |
| 图与装配 | `framework/{graph,render,runtime,execution}.py` | 同一有效解析结果供检查、计划、XML和真实命令；当前尚未全部贯通 |
| odometry/global_localization | `adapters/`、`framework/localization_node.py`、`v8_ndt_odom`及现有SLAM/定位包 | 里程计、地图内定位与重定位分责，来源和质量明确 |
| mapping/map_server/representation | `framework/map_from_pcd.py`、`representation/`及现有建图壳 | 建图生产、加载/查询、算法表征分开；地图版本和unknown一致 |
| global_planner/local_planner/controller | `planner/`、`local_planner/`及MBF/SCAN适配 | GlobalRoute、LocalTrajectory、MotionCommand语义分开，不把末点当完整路线 |
| trajectory_validator/safety_arbiter | `validator/`、`framework/safety.py`、生产mux与cmd3d mux | 独立否决、唯一最终命令出口；不同mux的维度/用途不能混用 |
| robot_adapter/simulator/evaluator | `boundary/`、`v8_simulation`、Gazebo/dynamics、verification/evaluate | 真机、载体、独立打分分离；评价真值不进入EST算法链 |

四项架构约束承接旧框架设计：manifest是组件类型定义的单一来源，catalog仅作加载派生索引，当前catalog目录/composer接缝仍须统一；组件类型与运行实例分离，同类型可多实例但端口/资源按实例检查；启动DAG与反馈数据图分离；仿真/验证依赖归独立适配和companion，不进入公共合同/算法内核。ROS适配器可按自身入口导入ROS，不能泛称整个framework不依赖ROS。

组件可以同时承担多个role，但真实行为必须声明。TEB/DWA是规划/控制一体后端时不改称“只输出候选轨迹”；标签quadruped、stairs、3D不能代替已验证能力。

## 2. 当前版本与待迁移字段

| 对象 | 当前实物 | v8.1实施要求 |
| --- | --- | --- |
| manifest | v1/v2原schema保留，v3新增显式execution | 未声明模式/机器人不能靠role或CPU推断；旧v2仅离线兼容，不据静态通过运行 |
| graph/app | 实例/参数/命名端口/边、显式反馈和模式身份 | 默认、配置文件、覆盖参数的优先级可追溯；执行消费已校验的有效值 |
| assembly plan | assembly_plan/v2、组件/报告/模式身份摘要 | 绑定防止检查后篡改重签，不能将摘要当操作许可或全计划授权 |
| ports/param_schema | 已有type/schema/topic等，完整语义和参数schema执行不足 | 通过显式新版本或受审适配合同迁移frame/unit/clock/freshness等；不能向additionalProperties=false旧schema硬塞字段 |
| robot/map/scene/verification | 已有独立schema与配置/夹具 | 机器人真实能力、测试替身、GT/EST、地图语义及模型版本分别绑定 |

目标语义至少覆盖：类型/schema/version、方向、维度、参考点/frame、SI单位、源时间/时钟、新鲜度/租约、地图/机器人身份、所有权、取消/失效/停止行为和能力证据。缺失与明确矛盾应分别报告；不能两份同错声明互相匹配就判兼容。

运行锁定产物应含源码/适配器提交与哈希、有效参数及来源、组件版本、地图/场景/机器人/模型、设备外参、TF/命令所有者、I/O解析、环境依赖或镜像摘要、时钟、种子、预算、评价器和证据范围。不写敏感凭据；输入变化生成新运行版本，不回写旧锁。

## 3. 数据与任务合同

下表是实施验收要求，不宣称现有标准消息已经携带全部字段。

| 数据 | 必须保留 | 典型拒绝情形 |
| --- | --- | --- |
| PoseEstimate | 测量源stamp、实际frame/参考点、位置/姿态、质量/失效状态、来源 | 零/旧/未来/倒退源戳，定位质量不允许导航，改frame标签冒充变换 |
| RobotProfile/SceneProfile | 包络、运动学/制动来源、支撑/连接、覆盖、真实或简化载体、版本 | 把手册或实验配置自动当实测能力，图外/无点/零填充当自由 |
| SupportMap/MapDelta | 地图ID/revision/digest、surface/cells/支撑/净空、三态、显式边、base_version/delta_id | 换版后用旧轨迹、旧base提交、无变化膨胀版本、未知当可通行 |
| NavigationGoal | goal_id、frame/XYZ、yaw/朝向要求、参考点、目标面/消歧、容差和时限来源 | 同XY异层直接成功，忽略请求朝向，缺失或歧义靠猜最近楼层补齐 |
| GlobalRoute | route_id、地图/robot身份、面序列、转层边、关键点/走廊与有效范围 | 仅传末点，绕行走廊/地图版本丢失，路线无真实支撑连接 |
| LocalTrajectory | trajectory_id、route_id、时间、参考轨迹/包络、有效期、来源版本 | 无时间路径冒充轨迹、过期轨迹、丢失全局约束 |
| MotionCommand | 来源、坐标/参考点、发布时间、租约/有效期、执行接口、停止义 | 计算时有效但发布时失效、多源直写最终cmd、取消后续旧速度 |

当前原生local主要处理XYZ；目标合同若带朝向要求而后端不支持，必须显式拒绝，不得静默丢yaw后报成功。

任务保持goal/feedback/result/cancel语义；至少区分成功、无路、预算耗尽、取消、输入非法、组件失败和安全停止，保留具体诊断，不统一写timeout。标准ROS消息可作为载荷；配套语义须以同一ID/版本可靠绑定，不能靠松散话题大概对应。

## 4. 统一装配与安全替换

目标解析顺序：加载/版本校验 → 有效参数 → role/端口/地图与运动学匹配 → 显式适配及损失说明 → TF/命令/资源/模式所有权 → 确定装配与锁。反馈边显式声明且不计启动DAG；无法表达的node/include/nodelet接线必须明确拒绝。

- 当前graph检查尚未统一TF所有权；composer同边双发布会覆盖。V81-01必须在真实启动准备入口拒绝同边双写、同child异parent、自环和多边环，保留发布者实例身份。
- 当前render按图边生成remap，default_command主要读manifest remap。V81-02/V81-03先核真实载荷，再以“只改图边/a→/b”证明XML、argv与真实连接同变或明确拒绝。
- 当前hotswap保留执行域守卫，但未完整比对维度/运动学/TF/frame/time，并硬写tf_edges_preserved。V81-05消费统一合同，先验证再stop/factory；不兼容时旧组合不受破坏，失败回退和安全仲裁保留。
- 最终/cmd_vel由组合声明的唯一safety_arbiter持有。框架允许validator缺席，这是现状限制；目标3D执行链必须接入独立轨迹否决，缺席不能作为可执行豁免。实际graph须核接入、消息级结果/心跳时效、超时和拒绝即停，V81-03/V81-04/V81-09分别闭合接线、语义和运行证据，不能只引用框架功能。

生命周期覆盖configure/start/ready/health/stop；ready由地图/TF/数据的实际可观测条件建立。启动失败只回滚本组合资源；停止保留安全仲裁至其他命令源退出。预算包含启动、规划、反馈和取消，不让harness先超时再误判算法。

## 5. 坐标、时间和机器人边界

采用明确配置的map→odom→base职责，不猜现场帧名或外参。支撑z、传感器原点、base原点和地面高度分别记录。平面投影说明丢失信息、支撑面和适用范围，跨层不隐式压平成2D。

Lite3Carrier与LocalControl已采用源stamp/单调进展及同base原点yaw平面转换：yaw=π/2时map(1,0)→body(0,-1)，plain拒绝超过1e-6数值零容差的vz；原Stamped保持map，关闭plain保留三维。失效/epoch撤销旧结果和预测，双发布/worker接受与回调撤销互斥。该容差是既有数值零策略，不是新设备能力门值。

上述修正仅覆盖已改adapter；`localization_node.py`仍有重贴frame/接收now及ROS Rate路径，V81-06须核源stamp、实际变换、navigation_allowed/质量和停钟。航向平面不等于完整6D、roll/pitch控制或参考点高度补偿；真实设备协议和停止时距另验。现场actual、外参、门值不由计划填常数。

Lite3/M20仅选择机器人运行依赖；x86_sim选择仿真/开发依赖。M20构建/运行当前拒绝，不以测试替身或改supported布尔值假装接入。推理运行时可在目标验证后作为机器人依赖；训练仍在x86隔离环境。

## 6. 地图、完整路线与多后端

| 消费环节 | 当前必须保留的版本限制 |
| --- | --- |
| map/v2及带obstacles的v3 | 需要显式障碍opt-in；非空障碍包络半径/高度须有来源，按机身连续扫掠核验 |
| MapService/MapDelta | 已有版本、防回退、幂等、原子、通知实物；默认校验未打开障碍消费，delta仍主要操作surface |
| support_planner | 已消费障碍及v3 cells；精确端点/多门户/部分连续连接保证仍有限定v2分支 |
| local/validator/provider | 分别建立生产者→服务→全局→局部→检查器接受版本矩阵，不据某一入口接受v3推断全链同语义 |

地图外/未知不当自由，同XY多层保留面身份；层间只走显式真实连接。全局保持有界搜索与无路/预算/取消分因；小图参考解、完整包络和连续碰撞依据分别提供。不承诺连续空间全局完备。

当前path_goal仅取Path末点且补now/缺省frame，可保留为明确的有限适配器。V81-07新增版本化路线消费，用同末点但绕行走廊不同、多层同XY和地图换版反例，证明局部不会穿越已禁止区域。

建图、里程计、全局定位、地图服务、规划分别适配。目标至少用两类真实建图后端、两类完整估计定位后端、两全局及两局部/控制组合证明配置替换；缺候选来源/许可/接口/运行证据就保持待接入，不用GT建图或仅换NDT/GICP匹配核补数量。已有faster-lio/hdl对照与切源实验保留，但v8_ndt_odom的monitor和重定位实验不自动成为连续导航后端。

SCAN的高度补偿、抽稀和单调剖面限制作为已知适配边界保留，原生local是已有主线实物；后端选择按合同与可运行证据，不强制回到旧探针阶段，也不通过独立检查器不断拒绝来声称任务成功。

## 7. 扩展合同

M20须先核型号、系统/架构、ROS、协议、遥测、包络/参考点、模式隔离、停止和现场许可，再独立适配。训练须固定机器人/场景、观测/动作与缩放/单位/频率/限幅、奖励/优化器、种子/依赖、checkpoint和导出哈希，并由独立评测消费。通用在线状态迁移、运行期重接及完整四足上阶另按[23号](23_v8.1任务队列.md)扩展前置执行。
