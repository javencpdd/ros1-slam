## Y11 提交与推送纪律（真人 2026-10-22 明文）

- **施工侧每批（或多批）只做 commit，不做 push；最终 push 由真人进行。**
- ★施工侧不得自行 push，也不得因「怕堆积」而 push***；**例外只有一条**＝真人当批明文要求 push。
- **分权理由**＝commit 可逆；push 是把本地动作变成**对外事实**（远端共享面既成事实；本仓虽为单人仓但有 x86 侧／Lite3 侧／其他工具多实例读它）⇒ ★「做完」与「发布」分开：施工侧管做完，真人管发布***。
- ★该格此前从无仓内在册条文***——历批沿用 `~/.workbuddy/MEMORY.md` 的本机通道（跨项目本机事实），本稿把它落成在册。
- **每批须报一个数**＝未推送提交数＝`git rev-list --count origin/main..HEAD`（★须先 `git fetch origin/main`，否则读过期远端引用＝假零***）；≥5 批时施工侧在汇报里额外提示一次，★只提示不代推***。

## Y12 commit 内容可读性规范（真人 2026-10-22 明文）

| 条 | 内容 |
|---|---|
| 首句纪律 | 第一个「＝」之前必须是**一句平实的话**（≤60 字、不含内部黑话），读完即知本批完成了什么；★禁止把批号／窗态／侧别／星号堆砌放首句*** |
| 固定七段 | 做了什么 ‖ 为什么做 ‖ 改了哪几面（逐面 numstat、数须带口径）‖ 读数（各件 rc；rc=0 须同句写「不覆盖 C1」）‖ 遗留与待真人 ‖ 未动面 ‖ 号位 |
| 全文指针 | 每条提交必须给「本批全文＝进度/<阶段>/批次记录/Rxxx.md（＋04 R号段）」 |
| 数字纪律 | 凡写进提交内容的数必须带口径（现取／沿用、哪条命令、哪一面）；★不写裸数、不写「我记得是」的数*** |
| 黑话纪律 | 内部术语不要求在标题里解释（解释了更长更不可读），★但必须在指针件里可查***；该批无指针件时首次出现须给最短解释 |
| 可读性优先 | ★写不下的一律不写，交给指针件***；判据＝**一个不熟本仓的人读完首句＋指针，能否知道这批改了什么** |

★可读性靠「首句说人话＋指针给全文」两件凑，不靠把正文塞进标题***——正文的合法位置是条目全文件（`批次记录/Rxxx.md`）与 04 段。

## Y13 允许多批合并成一个 commit（真人 2026-10-22 明文：不必强制每批即 commit）

| 提示线 | ≥3 批未提交时施工侧提示一次，★只提示不代提交*** |
| 建议而非强制 | ★改了在册件或门禁相关面的批，建议当批单独提交以便回溯*** |
