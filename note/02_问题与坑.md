## 坑16 · `kill -0` 判进程存活在 root 属主进程上返回 EPERM → 误判「进程已死」；`ss -lntp` 不含 UDP → 假报「未监听」（登记日 2026-10-08 · 源于主理人实测踩坑，小王登记 · 验收/核验类作业单通用规范）
- 症状：红线核验（确认 root 侧 foxy 生产栈未被触碰）时用 `kill -0 <pid>` 探活，对 root 属主进程 **115792 / 115795 / 115797 / 115799** 全部失败 → 被读成「进程不存在」，一度误报为「**生产栈被杀**」重大事故；另一次用 `ss -lntp` 查 UDP 43897（qnx2ros，02 坑5 同族）返回空 → 误报「端口未监听」。
- 根因：两条都是**工具语义误用**，非现场状态异常。① `kill -0` 只做信号发送权限检查：进程存在但属主不同且无 CAP_KILL → 返回 **EPERM（Operation not permitted）** 而非 ESRCH（No such process）；沙箱身份 ros1-slam 对 root 进程恒得 EPERM，`$?≠0` 被当作「死」。② `ss -lntp` 的 `-t` 限定 TCP，UDP socket 天然不列（`-n` 数字化、`-p` 需 root 才显示进程名）→ 空输出 ≠ 未监听。
- 处置（固化为**验收/核验类作业单通用规范**，建议后续 Gate 模板补这行）：
  - **进程存活/属主核验一律用** `ps -o pid,user,lstart,etime,args -p <pid1>,<pid2>,...`（能看到属主与启动时刻，兼作「生产栈未被重启」的承重证据）或 `pgrep -a <name>`；**禁止用 `kill -0` 作存活判据**（尤其跨属主场景）。
  - **端口归属核验**：TCP 用 `ss -lntp`，**UDP 必须用 `ss -ulnp`**（qnx2ros/43897、Livox 56300/56301/56400/56401 皆 UDP）；需进程名时加 sudo 或以 `lsof -nP -iUDP <port>` 复核，零权限则只报端口在位、不臆断属主。
  - 本次实际后果：**零生产栈损伤**，纯误报；已按「先 ps/pgrep 复核再下结论」补进核验动作口径。**小王 2026-10-08 只读复核（零节点、零改动）**：`ps -o pid,user,lstart,etime -p 115792,115795,115797,115799` → 四件 `user=root`、STARTED `Mon Oct 5 01:27:51/53 2026`、ELAPSED `2-23:30+`（**在位且未重启**）；对同四 PID `kill -0` 逐条返回 `kill: (PID) - Operation not permitted` = **EPERM 实证**（非 ESRCH），与本坑根因判定一致。
- 计划书是否需要更新：不需要改正文；建议 P0.5 双查/Gate 作业单模板增补一行「探活禁 `kill -0`，用 `ps -o pid,user,lstart` 或 `pgrep -a`；UDP 归属查 `ss -ulnp`」（由主理人决定是否入 v4.x 补丁）。

## 坑17 · Edit/写入工具走 temp+rename 会冲掉已补的 ACL；ysc 落盘致属主漂移（登记日 2026-10-08 · 源于 G7-① 补验收与 SCAN 拷包 · 主理人登记）

  - 核验类命令一律 `stat -c '%U:%G'` + `getfacl -p`，**不要用 `kill -0` 那类依赖属主的探测**（见坑16）。
