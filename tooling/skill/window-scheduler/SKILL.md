# window-scheduler · 队列与实验窗调度

> 最新更新时间：2026-11-05 13:20:56 CST

工程规则统一引用 [`note/架构/工程标准.md`](../../../note/架构/工程标准.md)，任务状态操作见 `note/09_跨工具协作契约.md`。中心计划书、执行队列与调度作业单从 `note/00_README.md` 的现行指针读取；本技能不维护阶段号、负载阈值或队列路径的副本。字段与选取要求见 [references/queue-format.md](references/queue-format.md)。

## 调度循环

1. 核当前用户指令、任务卡、队列状态、源码和证据，只选当前明确授权且依赖满足的任务。取消、废弃、被替代或缺状态的项不自动恢复；历史“下一步”不替代授权。
2. 切成一个阶段或最小纵向切片，写清产物与验证出口；上一项仍授权且缺验收时先补，不以此恢复取消任务。
3. 普通离线工作按权限与依赖推进。需窗任务单次报实际负载和占用，执行现行作业单规定的预检，rc=0 才开窗；不启动后台看守、不轮询等旗、不使用 FORCE。预检不通过只阻塞该需窗任务，若另有独立已授权离线工作可按依赖继续。
4. 实现后运行定向测试和相称检查，登记实现状态、自动化验收、目标环境验收和证据路径，更新文档最新更新时间。
5. 核工作区与暂存差异，显式暂存本任务路径后必须本地 `git commit`，记录 SHA；由用户决定 push，再维护任务状态和交接。无下一授权工作时可正常收口，不为队列非空擅自扩范围。

## 平台与运行边界

Lite3/M20 是真机目标，不编译仿真、不训练；x86 承担仿真、算法测试与运动学/策略训练。真机任务不由通用调度自动启动，必须满足当前明确授权及现场条件。仿真预检通过不提供真机许可，也不证明 M20 或训练器已实现。

L1 判据交独立实例复核，L2 按协作契约呈报；普通已授权工作不重复请示。运行窗登记按回执册的现行约定，只有登记不等于已开窗或验收通过。

包内 `scripts/window_watch.sh` 作为通用来源模板保留；本项目不调用它或 `scripts/ops/window_watch.sh` 作为默认调度入口，不沿用其旗文件或缺省阈值代替预检。
