# 任务队列格式（window-scheduler 的队列唯一真源约定）

## 文件形态

Markdown 单表，每行一个任务：

`| ID | 任务 | 线 | 类型 | 依赖 | 状态 | 验收出口 |`

## 字段语义

- **ID**：稳定短名（如 A-2-1），被依赖引用；已验收行的 ID 不复用。
- **线**：线程/方向标签（如 A/B/C、治理），仅作过滤视图，不参与调度。
- **类型**：`零窗`（纯离线，随时可做）／`活体`（需窗旗＋预检）／`真机`（等人明文＋现场条件，**调度永不自动启动**）／`设计`（出设计件，通常转架构师角色）。
- **依赖**：任务 ID 或明文条件（如"狗在场""主理人勾 Q-B1"）。依赖未满足＝不可选。
- **状态**：`未开工`／`进行中`／`待窗`／`待勾`／`待狗`／`已验收`。**缺状态＝未开工**；完成度不凭文件名/旧总结猜，以进度文档批次＋证据目录为准，本表滞后时以盘面为准并回本表更正。
- **验收出口**：可判据化的一句话；不能写成"完成即可"。

## 调度选取规则

1. 按文件行序扫描，取**第一个**"依赖已满足 ∧ 状态≠已验收"的任务；行序即优先级。
2. 上一阶段只有代码、无自动化或目标环境验收 ⇒ 先在队列补一条"补齐验收"任务并执行，不得跳过。
3. 选中活体任务但无窗旗 ⇒ 起看守脚本，本轮回合改选下一个零窗任务；真机任务直接跳过。

## 收尾入队规则

每批收尾前：更新本批行状态与证据路径；确认"下一个可执行任务"存在，不存在则按上游计划书拆解补行；进度文档带更新时间＋继续任务一句。

## 最小示例

| ID | 任务 | 线 | 类型 | 依赖 | 状态 | 验收出口 |
|---|---|---|---|---|---|---|
| A-1 | 判定链升级 | A | 零窗 | — | 已验收 | 自测四档全过＋留底 |
| A-2 | 窗包读数 | A | 活体 | A-1＋窗旗 | 待窗 | 三数照实报（命中/未命中/分母） |
