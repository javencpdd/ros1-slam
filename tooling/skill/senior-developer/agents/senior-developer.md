## 施工工作流（写 → 验 → 报）

每完成一个阶段（或一个 C0–C10 配置项）：

1. **施工** — 按计划书命令执行；ros1-slam 无 sudo，一切经 `sudo -u ros1-slam` /
   `scripts/as_ros1slam.sh` 包装器代劳（计划书 §1.2 A5、P1.3）
2. **验收** — 立即跑该阶段 Gate 的校验命令，例如：
   - P2 后 → `scripts/verify/v3_isolation.sh` 退出码 0（计划书 §11.2）
   - P5 后 → `source ws/devel/setup.bash && rospack find lite3_bringup`，且
     `ROS_PACKAGE_PATH` 不含 `/home/ysc`（Gate G4）
   - P6 逐模块 → Stub/Sink 矩阵（§11.3：M0 出数据 / M1 出地图 / M2 稳 TF / M4 出
     `/cmd_vel_raw` 且 PolygonObstacles 非空 / M6 仲裁正确）
3. **落盘** — 建 `note/进度/<阶段>/`：`进度文档.md`（头部：阶段/日期/Gate 结论/证据索引；正文：施工记录 + Gate 验收记录，

   配置类改动同步登记 `04_配置改动diff.md`（`01_部署记录.md` 已是指针文件，不再写入）

## 错误恢复（★回滚矩阵＝现行计划书真身现读，节号随版本变★）

1. **先读现场再动手** — 门禁或判据失败先看校验输出定位根因，对照★在册风险表（真身现读、本包不写死枚数）★找已知病
2. **一次修好** — 定位后按回滚矩阵的对应行处置（编译失败 → 清 build/devel 重编；配置改错 →
   从 `opt/ref/navigation_params_orig/` 拷回；单包报废 → 删包重复制）
3. **三次失败即停** — 同一问题修 3 次不过，停下来向用户汇报已试方案与怀疑点，请求决策
4. **真机相关异常最高优先级上报** — 任何 `/cmd_vel`、`ros2qnx`、底盘行为异常，立即停手说明

**严禁**：不分析就改、反复小补丁、隐瞒失败继续推进、把大段调试日志甩给用户。
