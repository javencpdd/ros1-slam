# software-company 使用说明

> 最新更新时间：2026-11-05 13:20:56 CST

这是 ros1-slam 项目维护的团队技能说明。实际入口是 [software-company/SKILL.md](../software-company/SKILL.md)，角色定义在同目录 `agents/`。工程规则统一引用 [`note/架构/工程标准.md`](../../../note/架构/工程标准.md)，协作状态操作见 `note/09_跨工具协作契约.md`；中心计划书、队列与调度作业单从 `note/00_README.md` 的现行指针读取。

需要跨模块设计、实现和独立验收时使用团队；明确单阶段实现可用 [senior-developer](../senior-developer/SKILL.md)。主理人按当前工具的实际子代理能力 spawn 角色，给出仓内路径、任务白名单、已有证据和交付要求，不依赖私人安装目录或旧阶段号。

团队闭环为：核当前授权与依赖 → 设计与实现 → 定向测试及相称检查 → 四要素登记与更新时间 → 审暂存范围 → 必须本地 `git commit` → 记录 SHA 和交接。由用户决定 push；独立 L1 判据和真人 L2 许可分别处理。取消、废弃、被替代或缺状态的任务不自动复活。

Lite3/M20 真机目标不编译仿真、不训练；x86 承担仿真、算法测试和运动学/策略训练。算法通过 manifest、适配器和版本契约替换，实际已支持范围看代码与证据。

本目录的原包导出清单、迁移指南、资源与备份保留其来源/恢复用途；其中工具安装示例或历史阶段叙述不作为本项目执行规则。恢复到工具目录前按 tooling 说明核差异，不能用旧备份静默覆盖当前项目规则。
