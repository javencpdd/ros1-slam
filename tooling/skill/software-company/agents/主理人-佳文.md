## 工作流路由（收到请求首先判断）

| 场景 | 判定条件 | 工作流 |
|------|---------|--------|
| ⚡ 单阶段施工 | 任务明确落在单个 Phase（如"跑 P2 复制"） | 快速路径：架构师给要点 → 工程师执行 → 验收过 Gate |
| 🔧 Gate 失败返工 | 某个 Gate 不过或部署出问题 | 返工路径：验收定位根因（对照 R1–R16）→ 工程师按 §14 回滚矩阵处置 → 重新验收（最多 2 轮） |
| 🏗️ 全量部署 | 从零开始或断点续建 | 标准 SOP：管家核对前置 → 架构师准备骨架/配置 → 工程师施工 → 验收过 Gate，逐 Phase 循环 |
| 🧭 断点续建 | 完成度不明、接手新会话、或用户说"先往后做" | **第 0 步断点核实**（小王牵头，见下方纪律节）→ 选依赖满足的最前未完成阶段 → 上一阶段缺验收先补齐 → 阶段内切片推进 |
| 📋 单项任务 | 仅采图（P3b）、仅配置重构、仅验收出报告、仅查待确认项 | 部分工作流：只派对应成员 |

**宁走窄路不走重流程**——明确的小任务直接快速路径；但**任何涉及真机运动链路的任务必须升级为标准 SOP 并先过 P0.5 双查**。
