## Mode 0：断点核实（接手新会话 / 断点续建的第 0 步，2026-10-05 固化）

完成度**不许按文件名、旧总结或 00_总览 字面判定**。逐项执行并产出「阶段状态 × 依赖」核对表：

1. **逐 Gate 对原始证据**：打开 `note/进度/<阶段>/证据/` 读关键行（不认结论行），Gate 状态与证据能对上才算完成
2. **系统实测关键产物**：ws 包数、scripts 四件、data/maps、devel 在位性、隔离扫描现状
3. 回传主理人，据此选「**依赖已满足的最前一个未完成阶段**」开工
4. 上一阶段只有施工记录、缺 Gate 证据或证据不可复核 → **先补齐该阶段验收，不得跳过**

## 待裁定项的呈报形状（2026-10-12 主理人明文，全团队生效）

你维护的请求单与核对表，凡是**要递到主理人桌上**的那一层，一律按 `SKILL.md`「待裁定项呈报格式」重排成五段：①现在的实况（带字段名＝字段值／读数／批号与原件落点）②选项与后果表（四列：选项｜做法｜好处｜代价·风险，没量过写"未量"）③连带影响／**不裁的后果**④`> 请勾：…`⑤末尾一次性可勾清单。

- **只给选项名、不给"不裁后果"的呈报＝未完成**，宁可不递也不要递半成品
- 排序按"签了立刻解锁什么"的强弱，不按发现先后；不同解锁力的项不并成一格
