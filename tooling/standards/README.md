# 工程标准一致性检查

> 最新更新时间：2026-11-06 15:17:09 CST。工程标准真源：`note/架构/工程标准.md`。

[工程标准](../../note/架构/工程标准.md)规定共同规则；[rules.json](rules.json)只记录当前入口、作用域和检测配置，不另立工程规范。检查器位于[scripts/verify/v_project_standards.py](../../scripts/verify/v_project_standards.py)，只读文件，使用Python标准库，不调用Git、ROS、Docker或项目运行模块。

从仓库根执行：

```bash
python3 -B scripts/verify/v_project_standards.py
python3 -B scripts/verify/v_project_standards.py --json
python3 -B scripts/verify/v_project_standards.py --selftest
```

正常检查返回0：已覆盖的文本/指针/结构一致；5：有冲突或缺少约定文字；9：配置、覆盖集合、文件或作用域不可信。自测在临时夹具目录验证正反例，不修改工作区。普通扫描的 `--root` 选择待检仓根，`--rules` 选择检测配置；自定义配置同样受结构与固定覆盖名册约束。`--selftest` 只运行工具相邻测试模块及其源码夹具，不代表已检查另一个目标仓库；检查目标文档应另运行普通扫描。

覆盖25件，包括12份活技能/角色/说明/队列格式、公共版本成果总览及现行入口。活技能全文、23/25明确标记的当前块检查高信号旧指令；note入口只取现行指针块。含旧新规则对照的v8.1主计划、协作契约和规范正文仅检查约定指针/时间/政策锚，不声称逐句理解全部自然语言。历史对照表和明确的“不启动后台／不使用FORCE／不能以缺状态默认待做”等禁令应通过，不能为迎合正则改写正确规则。

检测不以“历史／现读／指针”等词整行豁免；但它也不能识别任意同义改写。新增技能或入口须同步检查名册、scope与反控，不可通过删配置条目让遗漏变绿。代码实现缺口仍见[审查记录](../../note/进度/00_架构与工程标准审查_2026-11-05.md)。

本检查独立运行，不是正式门禁串新增成员，不改变旧检查器、返回码或门值。它不能证明阶段已经commit、真实接口兼容、仿真/真机隔离、训练能力或目标环境验收；这些必须分别取实际证据。
