## 1. 一句话结构

系统已收敛为**单一主仓 + 三个子项目 + 一个运行域**：

1. **P1 平台仓**（主仓根）持有契约、组件注册、图装配、执行、BT、局部规划、安全仲裁、集成验证与账本；**BT 是图内一等组件**，树决定 WHEN，算法组件决定 WHAT。
2. **P2 仿真子项目** `subprojects/simulation` 持有独立 catkin 工作区、运动学载体/真值/支撑格、17 个 Gazebo 世界与独立发布物；通过 app 声明与组件 manifest 在装配期被 P1 调用。
3. **P3 可视化子项目** `subprojects/console` 持有 host-only 任务台 agent/UI、12 栈白名单、世界/地图/体素数据与独立发布物；对 ROS 域只读。
4. **运行域**由 Docker ROS1 Noetic 承载：`roscore`、`sim-viz`、`sim`（headless）、`rosbridge`、官网与控制台 agent；真机 Lite3/M20 仍在 L2 边界外。

自 11-14 第二切片后，P2/P3 以 `git subtree` 并入主仓（`a74d9b2d`/`5220227f`、合并 `e36562b0`，落位 `2d4e6231`），保留各自工作区与发布物；主仓 `origin` 是唯一远端同步面。

## 6. BT 编排设计解析

### 6.1 树与职责分离

`navigate_with_planner.xml` 的根是 `Fallback(mission, cancel, recovery)`：

- **mission**：`WaitForGoal → CheckLocalization → RequestPath → WaitForPath → FollowPath → WaitArrival → Dwell → Stop`。
- **cancel**：`IsCancelled → CancelStop`，只在收到取消请求时进入。
- **recovery**：`skip / retry / replan / abort`，由节点配置；每目标可被 policy 覆盖 retry 预算。

这是“**树决定 WHEN、组件决定 WHAT**”的直接实现：BT 不计算路径/速度，只决定顺序、超时、取消与恢复；全局/局部规划器仍是独立组件，可替换。

### 6.2 取消是显式协议，不是零速

- 输入 `/v8/bt/cancel` 的 wire 是 `<seq>:<scope>:<reason>`，`scope=current|all`。
- `CancelStop` 向 `/v8/local/cancel` 发命令，并等 `/v8/local/cancel_ack`；超时/拒绝显式上报。
- 终态：`cancelled`（有 ack）、`cancel_ack_fail`（执行端拒绝）、`cancel_unacked`（超时）。
- 旧 `Stop` 的零速**不**被当成取消；避免“看起来停了但执行层仍在跑”的静默成功。

### 6.3 恢复与多目标

- `GoalQueue` FIFO；`Recovery` 的 retry/replan 用 `push_front` 重排当前目标，保留 attempts。
- 每目标 policy 可带 `dwell/arrival/path/retry/index/total/label`；`retry_exhausted` 后跳过并进入下一目标，`recovered_skip` 记录定位门失败。
- 多目标任务由 task 的 `goals` 列表 + `/v8/bt/goal_mission` 注入；单目标仍走 `/v8/bt/goal` 兼容路径。

### 6.4 运行读数

`ABC-upstairs-r3`（subprojects 合并后复跑）：六项 checks 全 true（assembly/map/global_path/local_arrived/carrier_at_local_goal/markers），57 poses，末点 `(-5.9,1.1,1.6)`，carrier `(-5.7476,1.1218,1.6)`，markers 40。取消正控 `cancelled`、负控 `cancel_unacked`；两目标任务在 path=1s、retry=1 下四次超时后 `retry_exhausted` 进入第 2 目标。

### 6.5 设计评价

**强项**：取消/恢复是显式状态机而非隐式行为；每目标预算可配置；失败有终态与可观测字段；BT 与算法解耦，换算法不必改树。  
**边界**：formal 只覆盖 `upstairs` 单场景/declared 几何；carrier 是运动学方盒，不是四足接触物理；取消 ack 只到局部规划器，未覆盖真机执行器全链；M20/真机仍 L2。

## 11. 设计评价与待办

### 强项

1. **平台优先、BT 一等**：编排、算法、执行、安全在图上分层，BT 不越权写速度。
2. **显式契约**：manifest v3 + graph + port truth 把“声明/装配/实测”分开，失败 fail-closed。
3. **子项目自治**：P2/P3 独立工作区/发布物，主仓单一远端；解耦守卫有正反控。
4. **取消/恢复可验收**：终态、ack、retry 预算、多目标都有仿真读数，不是设计口号。
5. **安全单写者**：`/cmd_vel` 由 mux 独占；supervisor 只 hold；真机边界明确。

### 风险与技术债

| 风险 | 影响 | 建议 |
| --- | --- | --- |
| GTC 07 表在搬迁后 14 vs 15 | 代际门禁失真 | 由判据载体权属人裁定补行/迁移口径，不施工侧自改 |
| VAR 默认 v7 证据 glob | 门禁 INVALID | 更新 v8 证据面或明确 v7 历史面独立口径 |
| VCC 旧 `95_simulation` 路径 | 2 条 RED 噪声 | 更新已知项路径或按搬迁登记 |
| P3 voxel_stream 挂载缺失 | 一个 demo 栈不可用 | 补 `subprojects/console` 兼容挂载或改容器路径 |
| 容器无 `.git`/`subprojects` 挂载 | 全链无法单次复跑 | compose 补只读挂载并重建；不改 rc 语义 |
| BT formal 单场景/kinematic | 不能外推全场景/物理 | 多目标完整窗、真机/M20 另立 L2 作业 |
| P3 信任 LAN/无鉴权 | 局域网内可启停 demo 栈 | 保持 host-only；公网发布另裁 |
